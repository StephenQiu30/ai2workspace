## 执行与接收

1. 读取根 AGENTS、PROJECT、DESIGN，以及本文件和适用角色 Skill。
2. 显式选择 roleIds，声明工程和每个精确输出文件。角色路径以精确文件或以斜杠结尾的目录前缀表示，不是任意 glob。迁移旧目录的责任仅用于删除旧来源；一致性检查拒绝重新创建旧目录。
   前端和体验角色还必须声明 roles.json 的 checkIds，包括 lint、格式、构建、浏览器和构建追踪检查。

3. 本机 CLI 创建并 prepare 实际任务，导出并实际读取上下文；源资料不能直接执行命令。
4. 按固定定义执行必需检查，保留原始候选和结果；角色不符、遗漏必需检查及策略不可读会被阻止。
5. verify 比较 TaskOrigin 以来的实际文件变化、精确输出和角色范围。策略所属工程必须纳入任务；首次准备后工程集合固定，不能通过移除工程逃避检查。新工程须另建任务，不补造历史现场。
6. 策略或角色定义变化会使原任务依据过期，须有理由地修订或重建快照；已固定的策略不能借重建快照丢弃。角色与策略正文随快照导出，不能静默读取新版本替代旧依据。完成条件不由 AI 自报满足。
7. 使用真实 runId 交接，保留未知外部动作；新会话先核对现场与有效证据，再接续。

角色校验属于任务准入和产物接收控制，不是 OS 沙箱。当前 CLI 能执行声明检查，不能自动调度或限制整个 Codex 会话。人工验收写入、例外写入、语言检查器适配和真实新会话验收需要实际实现与证据；完整计划不得因此被自动标为通过。

## 当前项目检查

- pnpm check:workspace：目录、角色、Skill、规范入口、计划、文档身份、链接和必需检查一致。
- pnpm types:check 与 pnpm test：当前 TypeScript 模块的适用工程检查。
- pnpm lint、pnpm format:check、pnpm build、pnpm test:e2e：交付时执行适用的格式、构建和交互回归。

完整计划按当前绑定工程选择规范；当前模块没有的语言或其他项目的业务流程不成为通用平台建设任务。CLI 不授权提交、推送、发布、付费调用或业务数据变更。
