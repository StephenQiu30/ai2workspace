# 项目执行计划

先读仓库根 [AGENTS.md](../../../AGENTS.md)、[项目规范](../../../workspace/content/standards/project-design.md)和[计划模板](../../../workspace/content/templates/plan.md)，再读实际需求、PRD、设计及既有计划与交接。

核对当前范围、工程与已有修改，识别前置条件和已经发生的工作。拆分可交付任务，关联设计、产品验收、实际产物和依赖；没有依据的排期与责任人不代填。

验证方法来自实际工程和相关风险，不填写不存在的命令或报告。关键产品验收有对应验证任务，检查缺口在计划中说明；不通过删验收或放宽条件获得完成。

用户只要求计划时交付计划文档。获得实际执行授权后，才运行对应任务，并依据真实观察更新结果、状态和证据；未知外部动作先核实，不自动重试。

接续时比较已有记录与当前现场，过期证据说明适用限制。任务定义改变时同步受影响的需求、PRD 或设计引用，保留已经发生的记录，不将预计结果写成通过。

重算输出文件的相对链接。交付计划路径、已完成与剩余任务、阻塞和具体下一步；提交、推送、验收和发布分别记录实际状态，权限仍以当前用户授权为准。
