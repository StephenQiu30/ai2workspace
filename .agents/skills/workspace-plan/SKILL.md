# 项目执行计划

先读仓库根 [AGENTS.md](../../../AGENTS.md)、[项目规范](../../../workspace/content/standards/project-design.md)，再读实际需求、PRD、设计及既有计划与交接。

创建或重新拆分多步实施计划时，在宿主当前可用技能中查找并实际读取 `superpowers:writing-plans`，说明本轮正在采用它，再按其当前说明编写和自检。不可用时说明缺少该能力，只整理已知依据和缺口，不声称已完成上游方法要求的计划。仅更新已有任务的实际进度时无需重新拆分整份计划。

核对实际工程、已有修改和规格约束，采用上游的文件职责、任务接口与可检查步骤组织计划；以独立可验证的交付划分任务，不按技术层或空泛的阶段名称拆分。命令、测试名、接口和规格规定的数值以实际工程为据，不复制上游示例代码冒充本项目实现。

读取[计划项目模板](../../../workspace/content/templates/plan.md)，在上游规定的计划头、约束、Review Focus 和任务结构上补充 PLAN-ID、R / FR / AC 关联、状态、证据与交接。本模板不替换上游要求的计划结构和自检。

计划默认保存为 `workspace/content/projects/项目标识/专题/plan.md`；用户指定位置时遵从用户，既有计划原位更新。该目录明确替代上游的 `docs/superpowers/plans/` 默认位置，不建立重复计划。重算输出位置的相对链接。

保存并完成上游自检后交付计划供审阅，按其交接要求处理后续执行及执行方式；保留用户已指定的方式，不擅自启动子代理或实施流程。计划中的 Commit、部署或外部操作步骤不是执行授权，实际动作仍遵守根入口与用户当前指令。

更新执行记录时比较现场与原计划，仅引用真实操作和证据，注明过期、失败、阻塞与未知外部动作。交付路径、采用的上游 Skill、验收覆盖、剩余事项和下一步，分别记录提交、推送、验收与发布的实际状态。
