# 项目产品 PRD

先读仓库根 [AGENTS.md](../../../AGENTS.md)、[项目规范](../../../workspace/content/01-项目文档与设计规范.md)，以及实际需求与确认记录、已有设计与调研。

在宿主当前可用技能中查找并实际读取 `pm-execution:create-prd`，按其当前说明开展 PRD 创建或评审；项目入口不复制上游方法。找不到或无法读取时，说明缺少该能力，只整理已有依据与缺口，不宣称已使用插件完成 PRD。

采用上游默认的精简 PRD；用户要求详细版时再展开。问题、目标用户或成功判据仍有关键缺口时，遵循上游澄清要求，不用项目模板的占位内容绕过澄清。只有用户明确允许带假设继续时，才将相应缺口标为假设后成稿。

读取[PRD 项目模板](../../../workspace/content/templates/003-PRD模板.md)补充项目字段：稳定文档 ID、需求来源、FR / AC 关联、定义状态，以及设计与计划的真实链接。产品验收融入方案部分；实现细节引用设计，避免再生成一份重复规格。

产物默认保存为 `workspace/content/prd/NNN-中文文档名称.md`（NNN 为该分类最大已用编号加一，标题同步为 `NNN · 文档标题`）；用户指定位置时遵从用户，已有 PRD 原位更新。这个位置是本项目对上游默认文件名的明确适配，不在仓库根另建一份 PRD。替换 frontmatter、移除模板说明并重算相对链接。

按上游要求检查精简程度、产品逻辑与未定假设，再核对项目引用。交付实际路径、采用的上游 Skill、范围与验收变化及未定问题；简要说明有意省略的内容，不把文档确认记作实现或验收完成。
