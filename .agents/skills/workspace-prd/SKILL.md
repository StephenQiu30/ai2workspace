# 项目产品 PRD

先读仓库根 [AGENTS.md](../../../AGENTS.md)、[项目规范](../../../workspace/content/standards/project-design.md)和[PRD 模板](../../../workspace/content/templates/prd.md)，再读实际需求和确认记录。

区分已确认交付与待确认范围。需求不足时先编写已知部分并列出缺口，不将模板示例、截图业务或 AI 建议提升为确认事实。

围绕使用者、场景与目标定义行为，说明适用的输入、业务规则、权限、例外和恢复。需要用户故事时直接写入 PRD，不额外生成无必要的文档层级。

每个关键行为关联需求来源，每项验收写明前置条件、操作与可观察结果，并覆盖实际风险。没有依据的性能指标、人员和排期保持待确认。实现细节引用设计，避免重复维护技术方案。

更新既有 PRD 时保留文档与条目 ID，记录范围或规则变更及其依据，指出对设计、计划和验收的影响。复制模板后移除模板说明并重算本地相对链接。

交付 PRD 路径、范围与验收变化、待决定的问题。PRD 评审或确认不等于实现、验收或发布完成。
