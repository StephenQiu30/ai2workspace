# 项目实现设计

先读仓库根 [AGENTS.md](../../../AGENTS.md)、[项目规范](../../../workspace/content/01-项目文档与设计规范.md)和[设计模板](../../../workspace/content/templates/002-设计文档模板.md)，再读本次需求、调研与适用的工程说明；PRD 已存在时一起核对，不为尚未创建的 PRD 虚构条目。

在用户提供或已知授权的工程范围内核实现状、可复用能力和真实依赖。没有工程依据时将内容写成建议或待验证假设，不声称已实现、已接入或已通过验证。

PRD 未形成时以已确认 R-ID 约束方案，后续再补齐 FR / AC 映射。用实际需求或产品条目约束设计范围，说明关键流程、模块职责，以及适用的状态、接口、数据、权限和恢复。复用现有框架及组件；新增抽象说明具体收益，简单修改不虚构复杂机制或备选方案。

记录影响决策的方案与取舍，建立产品验收到设计章节或设计决定的关联。技术限制影响产品行为时列出影响和待决定项，不自行扩大范围或修改确认结论。

系统拓扑、跨域职责、共享技术选型和架构图统一更新到 [workspace/ARCHITECTURE.md](../../../workspace/ARCHITECTURE.md)。专题设计保存到 `workspace/content/design/NNN-中文文档名称.md`（NNN 为该分类最大已用编号加一，标题同步为 `NNN · 文档标题`）。更新已有文档时保留稳定 ID 和已发生的决定，并按实际位置核对相对链接、范围、依赖、风险、验证方法和待确认项。

交付设计路径、关键决定、受影响文档及未验证的假设。用户只要求设计时交付设计，不据此启动代码实施、提交或发布。
