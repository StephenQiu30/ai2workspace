# 项目实现设计

先读仓库根 [AGENTS.md](../../../AGENTS.md)、[项目规范](../../../workspace/content/standards/project-design.md)和[设计模板](../../../workspace/content/templates/design.md)，再读本次需求、PRD 与适用的工程说明。

在用户提供或已知授权的工程范围内核实现状、可复用能力和真实依赖。没有工程依据时将内容写成建议或待验证假设，不声称已实现、已接入或已通过验证。

用产品条目约束设计范围，说明关键流程、模块职责，以及适用的状态、接口、数据、权限和恢复。复用现有框架及组件；新增抽象说明具体收益，简单修改不虚构复杂机制或备选方案。

记录影响决策的方案与取舍，建立产品验收到设计章节或设计决定的关联。技术限制影响产品行为时列出影响和待决定项，不自行扩大范围或修改确认结论。

更新同一专题的设计文档，保留稳定 ID 和已发生的决定；重算实际文件的相对链接。核对范围、依赖、风险、验证方法和待确认项是否相互一致。

交付设计路径、关键决定、受影响文档及未验证的假设。用户只要求设计时交付设计，不据此启动代码实施、提交或发布。
