# 职责与文档归属

本约定依据用户于 2026-11-15 对职责、文档归属和目录混杂的反馈，以及随后明确的重构授权。它修订旧设计的组织方式；既有产品范围、文档身份和封存证据继续保留。只调整本工作区，不提交或推送。

## 产品与领域

ai2workspace 是本机项目工作区工具。Workspace 定义空间和本机绑定；知识治理保存可追溯资料；上下文组织提供明确用途的材料选择；Harness 为研发任务采集检查证据并交接。它们在同一产品内分域实现，无需拆成多个部署服务。

| 领域      | 所有权与输入                                           | 输出与边界                                                               |
| --------- | ------------------------------------------------------ | ------------------------------------------------------------------------ |
| Workspace | 空间声明、来源/工程绑定、内建配置校验                  | 解析后的空间；不替资料确认事实或判定任务完成                             |
| Knowledge | 原文引用、稳定文档身份、治理注记、来源修订、导航元数据 | 阅读、检索和可追溯版本；不依赖研发任务，不执行正文命令                   |
| Context   | 显式资料选择、用途、依赖及适用规则                     | 所选资料、确认约束、规则分组和缺口；不执行检查，不修改任务状态           |
| Harness   | 任务合同、工程候选、Context 选择结果、检查定义         | 任务快照、原始现场、检查证据、验证、交接和恢复；不把文字主张当成检查通过 |

依赖方向为 Harness → Context → Knowledge → 基础配置/存储；Workspace 和共享基础设施不加载领域执行策略。文件存储适配器可实现各领域的窄接口，知识域不调用任务或进程接口。类型按领域归属，对外保留原公共入口以兼容现有调用者和文件格式。

Context 的材料选择可脱离任务合同使用；Harness 将合同输入和适用规则转换为选择请求。已有 prepare/export 命令仍由 Harness 适配，保留原字段和快照语义，不重写历史 manifest。通用空间无需工程、检查或研发文档链。

## 文档与文件归属

| 内容                                   | 唯一位置                           | 使用方式                                                     |
| -------------------------------------- | ---------------------------------- | ------------------------------------------------------------ |
| 本服务原始需求、规格                   | docs/product                       | 保留用户原话、确认与验收；原需求和产品规格职责不同           |
| 本服务架构、技术设计和研究             | docs/architecture                  | 描述领域和技术决策；本文件为本轮职责约定                     |
| 使用、配置、运维、编写、Codex 协作说明 | docs/guides                        | 面向使用者的操作说明；profile 在此说明其语义                 |
| 本服务开发计划与验证事实               | docs/development                   | 只记录本工程开发；CLI TaskState 仍是已登记任务的当前状态权威 |
| 初始化等历史资料                       | docs/archive                       | 保留历史原文与旧 ID，明确历史身份，不混入当前入门入口        |
| 可复制知识模板                         | templates/knowledge                | 实际模板唯一来源，旧模板文档 ID 指向其使用说明               |
| 空间配置样例                           | templates/workspace                | 共享声明与本机绑定样例                                       |
| 任务和交接样例                         | templates/harness                  | Harness 输入样例；不包含真实运行证据                         |
| 真正供 Codex 加载的 Skill              | .agents/skills                     | 本项目操作入口；文档说明不冒充已安装能力                     |
| 自用空间声明/侧载身份/共享任务合同     | spaces/self                        | 将 docs 和模板作为普通来源接入；不存第二份正文               |
| 本机绑定和运行事实                     | workspace.local.yaml、私有 dataDir | 保留旧合同、TaskOrigin、快照、运行和检查点；不进入构建或 Git |
| 用户其他知识原文                       | 用户选择的来源目录                 | 保留所有权和原目录；不要求搬进本服务 docs                    |

根 AGENTS.md、PROJECT.md、DESIGN.md 保持原位置与唯一来源。知识通过显式 instruction 来源引用根规则，网页将适用规范单列。profiles 原有说明迁入指南，不再以可安装策略目录的形式出现。

## 导航合同

文件目录表达内容归属；网页导航读取同一知识修订中的目录标题、顺序和默认展开设置。普通目录没有 meta.json 时根据实际目录生成导航，不强制编号或配置。

保留稳定 ID 驱动的旧阅读 URL；路径移动不改变 `(workspaceId, sourceId, documentId)`。来源边界用于隔离和解析，单一知识正文来源直接呈现内容分类，多来源时使用来源展示名；instruction 来源作为适用规范单列。搜索、正文、导航、来源展示描述和附件固定在同一来源修订，历史修订不能借用当前磁盘上的新导航。旧索引没有采集导航或来源描述时保留兼容读取，按现有声明与旧正文来源推断显示；无法补造过去未采集的分类，不承诺这类旧索引的历史展示完全一致。

## 迁移与证据约束

1. 迁移前保存现有 29 个阅读 ID 与原路径清单，记录旧合同、TaskOrigin、快照、运行和检查点摘要；本机目录大小写调整仅修复确认属于同一目录的 owner 路径。
2. 按上述归属移动文件并更新相对链接、导航和 ID 映射；不覆盖已封存对象。可复制模板与使用说明各有一个职责。
3. 改绑 self 的知识根到 docs，明确迁移映射；旧索引、快照和交接保留旧内容。移动后当前候选与依据产生变化应如实过期，不能冒称旧检查仍有效。
4. 现有 self-operations-guide 任务不由本轮重新完成，也不自动 rebaseline；保留其状态和交接原始字节，供后续使用者核对。
5. 新增回归覆盖无任务上下文选择、依赖方向、导航元数据的版本固定、旧 ID 的移动与历史读取。完整质量检查和真实浏览器结果另行记录。
6. 本轮不增加模型调用、网页执行、远端同步或发布。真实跨 Codex 会话验收仍须实际新会话，独立进程测试不替代。

详细的旧 ID → 新路径映射见随文迁移清单。当前旧设计中的 knowledge/profiles/扁平 Core 路径由本约定及实际代码位置替代；历史命令、运行记录和封存说明保留当时信息，不按新路径改写已封存数据。
