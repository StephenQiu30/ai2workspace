# 知识维护

1. 按资料用途选择分类，普通资料不强制研发模板；根规范保留原位置和唯一来源。
2. 编号可选，本服务已有编号、来源与稳定 ID 保留；正文 H1 不重复展示编号。
3. 新建或移动服务自用文档时同步既有 document-ids.json、导航、meta.json 与有效链接；Core 身份关联必须显式处理，不能靠路径改号。
4. 明确区分用户确认、观察事实、建议和待定；正文变更后重新核验确认摘要，不以整理之名删除原始需求或有效验收。
5. 如有 CLI 维护任务，先准备上下文并声明文档产出，再执行适用检查、verify 和 handoff；真实运行数据保留在私有 dataDir。
6. 执行适用格式、构建与浏览器检查，记录结果和限制；历史由 Git 追溯，状态以 TaskState 为准。
