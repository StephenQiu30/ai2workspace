# 需求到交付

1. 读取根规范、空间 profile 与当前授权，核对 Git 状态和已有修改。
2. 保留原始诉求、来源、ID、明确确认与待定事项；普通资料不必转成 PRD。
3. 产品要求进入产品范围与验收，设计、故事和测试关联相应产品要求；Plan 与任务引用必要依据，不强制单向文档链。
4. 为需要交接的工作建立 CLI 任务合同，显式声明范围、依据、检查和交付；准备并实际读取导出的上下文后实施。已有任务先 resume，TaskState 为状态权威。
5. 运行与风险匹配的声明检查并验证候选证据，记录失败、阻塞和过期；Plan 可链接必要证据，BACKLOG 只保留未登记迁移及人工缺口。
6. 生成匹配合同和快照的交接；实际新 Codex 会话复核现场后接续。说明关键文件、结果与限制，Git 和发布按用户实际授权处理。
