# ai2workspace 本机使用与交接

本指南面向当前本机版本：用户在 Codex 发起任务，Web 阅读和配置知识，CLI 执行声明检查、形成上下文与交接。任务定义、版本和结果语义以 [主设计](../architecture/02-知识治理与Harness设计.md)和项目实际 CLI 为准。

## 1. 初始化与启动

需要 Node.js 24 和 pnpm 12.4.2，在 ai2workspace 仓库根目录执行：

```bash
pnpm install --frozen-lockfile
pnpm setup:local
pnpm dev
```

`setup:local` 只在不存在时创建自用空间的私有本机绑定，并构建 Core/CLI；不会覆盖已有自定义配置。阅读入口为 http://127.0.0.1:1140/，`/spaces` 选择空间。正式预览使用 `pnpm build` 后 `pnpm start`，同一端口的开发和正式服务择一运行。

应用为 apps/web，CLI 为 apps/cli，共享 Core 为 packages/core；本服务自身文档在 docs。资料实际位置由空间绑定决定，其他项目不必使用相同目录结构。

## 2. 选择知识源

自用描述在 spaces/self/workspace.yaml；实际绝对路径在不入 Git 的 workspace.local.yaml。知识目录绑定 knowledge-root，工程根绑定 service-root。移动仓库时核对私有绑定及运行存储归属，不修改公共配置来保存个人路径。

其他空间参考 templates/workspace 的空间和本机绑定样例，以及 templates/harness 的任务样例，放到自行选择的可写 workspaceDir。Web registry 默认读取仓库 spaces 下的空间目录，可在运行环境指定 AI2WORKSPACE_SPACES_DIR。原始资料可以独立存放，接入不自动改正文。网页创建的是声明，随后在本机填写私有 bindings。

```bash
pnpm cli --workspace spaces/self space validate --json
pnpm cli --workspace spaces/self source scan --json
```

阅读 envelope 的 data 和 issues。普通 Markdown 无编号、无 PRD 仍可接入；资料中的命令不会因扫描而执行。确认注记必须绑定实际正文和来源决定，不能把检索结果自动标为 confirmed。

## 3. 准备与读取任务上下文

按真实目标填写 templates/harness/task.example.json，明确空间、工程、精确输出、资料身份、验收和检查 ID。先准备再编辑，避免把本任务修改误记成初始现场。

```bash
pnpm cli --workspace spaces/self task create --contract /path/to/task.json --json
pnpm cli --workspace spaces/self task prepare --task example-task --json
pnpm cli --workspace spaces/self context export --task example-task --json
```

实际读取导出的规则、依据、候选资料、正文及缺口；导出不等于已注入 Codex。快照包含选中正文的真实副本，根规范由显式 instruction 来源纳入。源码链接不是自动发布许可，未支持的附件会提示；需要时由 Codex 从已绑定工程读取实际代码。

来源改变时区分无关资料、任务产出和真正的依据漂移。需要调整合同或依据时，使用 task revise 或明确带理由的 task prepare --rebaseline；保留原始 TaskOrigin，不能通过重建抹掉先前现场或降低验收。

## 4. 执行与核对检查

```bash
pnpm cli --workspace spaces/self check run --task example-task --check service-types --json
pnpm cli --workspace spaces/self check run --task example-task --check service-tests --json
pnpm cli --workspace spaces/self task verify --task example-task --json
```

命令在声明的目标工程运行，不默认在 CLI 自身目录执行。实际 argv、目录、工具/公开环境、前后候选指纹、退出结果和产物构成证据。当前候选的通过结果可以取代历史失败，但旧候选或旧规则的结果不能证明新输入。

退出码 0/1/2/3/4/5 分别为操作成功、检查失败、输入错误、阻塞、过期和冲突。查询操作成功不代表任务已验证；尤其 task status/list/handoff/resume 的成功必须结合状态阅读。

必需产物只能来自本次新建运行目录，检查程序通过 AI2WORKSPACE_RUN_DIR 获取根目录，产物写到 artifacts 子目录。旧工程报告、日志文字或模型自报不替代本次证据。私有环境依赖、人工验收、报告导入和例外写入在当前闭环明确阻塞，不以模拟结果补齐。

## 5. 交接与真实新会话恢复

按 notes.example.json 填入真实 taskId、合同修订、snapshotId、当前运行 ID、未决问题和下一步；无证据的完成主张会单独标记。

```bash
pnpm cli --workspace spaces/self task handoff --task example-task --notes /path/to/notes.json --json
pnpm cli --workspace spaces/self task resume --task example-task --json
pnpm cli --workspace spaces/self task status --task example-task --json
```

在实际新的 Codex 会话中，先读取项目 Skill，再运行 resume、查看差异与交接，需要时重新导出上下文。匹配证据可以复用，过期项需要重查；未知外部动作先确认真实结果，不自动重试。只有交付和验收满足时才运行 task complete，不自动提交、推送或发布。

当前真实自用任务 ID 是 `self-operations-guide`。其初始验证曾因指南与检查证据缺失而拒绝通过；后续按真实产出和实际检查形成交接。它的 TaskOrigin 对应这项指南任务开始时的现场，不冒充整个 bootstrap 实施开始时的原始基线。

AC-AW-012 只有使用者在真实新 Codex 会话继续任务并核对后才成立；同会话命令、独立 CLI 进程及子代理均不替代。task resume 是核验与建议，不自动执行交接下一步。

## 6. 数据、故障与保留

workspace.local.yaml、私有 dataDir、运行日志与证据不入 Git，也不随 Web 构建打包。身份登记、合同、快照、证据和检查点需要保留；索引可以重建，不能用清缓存的名义删除任务资产。

来源失联时 Web 明确展示旧修订；正文、搜索、Markdown 与图片按同一修订读取。配置并发写入或检查持有锁时返回冲突，不覆盖别人的修改。CLI 崩溃后需要先确认所属进程组已退出，space recover-lock 不会仅凭锁较旧就放开竞争；它也不自动杀死无法证明归属的进程。

网页 registry 创建锁的异常恢复见 apps/web/README.md，应在本机确认持有者状态后处理；没有网页工程执行或随意清锁入口。

## 7. 项目检查

```bash
pnpm test
pnpm types:check
pnpm lint
pnpm format:check
pnpm build
pnpm test:e2e
pnpm --filter @ai2workspace/web test:bundle
```

Core、CLI、网页单测、隔离浏览器、构建清单隐私和真实用户会话分别记录。命令和源码实现不能代替产品验收；当前支持范围以实际环境与检查记录为准。
