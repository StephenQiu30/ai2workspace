# ai2workspace 最小闭环实施计划

> 当前职责、目录和模块依赖以 [职责与文档归属](../architecture/03-职责与文档归属.md) 为准。本页保留原方案和验证历史；其中旧路径不作为新的组织约定。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.
>
> 本文是用户要求的正式工作区计划，不是运行日志。以上为未来执行指导，不自动授权启动实施、委派实现、Git 操作或发布；实际执行方式按当时用户指令决定。

**Goal:** 在保留当前阅读站点的前提下，完成自选知识源、固定上下文、CLI 检查及一次真实跨 Codex 会话接续。

**Architecture:** Web 与 CLI 使用无 Next.js 依赖的共享 Core，知识、配置和运行数据分离；先完成本机文件合同与真实证据，再完善网页和目录。Codex 执行编码，CLI 仅执行显式声明的检查。

**Tech Stack:** 延用 Node.js 24、pnpm 12.4.2、TypeScript strict；保留 Next.js 16/Fumadocs 当前版本的阅读站点。新增解析/校验依赖在实施时核验实际版本，不在设计文档中捏造安装结果。

**Spec:** 主要产品依据为 [第一版 PRD](../product/specifications/02-第一版PRD.md)。技术依赖为 [主设计](../architecture/02-知识治理与Harness设计.md)，包括配置、快照、结果、状态与 MIG 清单。

## 全局约束

- 本计划最初在仅文档授权下编写；后续用户已授权完整方案实施、知识库重构与重命名，第一版代码与目录迁移已落地，实际结果与限制见本页当前实施证据。已登记任务状态以 CLI TaskState 为准，迁移与人工验收缺口见根 BACKLOG.md；下方复选项是计划步骤，不作为独立实时状态库。
- 本机单用户、多空间；知识来源仅本地目录和已检出 Git 工作目录，不同步远端。
- 用户从 Codex 发起任务，不实现网页编码执行、Agent 调度或模型调用。
- 接入不改原文，任务修改沿用授权；无自动提交、推送、发布、回滚或清理。
- shell=false，检查 argv/cwd/required 来自合同，超时默认 120000ms、允许 1—3600000ms。
- CLI 退出码 0/1/2/3/4/5 分别为操作成功、检查失败、格式错误、阻塞、过期、冲突。
- 任务合同修订和快照不可覆盖；source、contract、check、candidate 变化使相关证据重新匹配。
- 先使用文件持久化与空间排他锁；不引入数据库、向量服务或多机共享运行目录。
- 首个真实验收在当前 macOS 环境执行；未验证的平台不得声称支持完成。

## Review Focus

1. 代码与知识同仓：任务正常改代码不废弃原始依据，但旧候选检查必须失效；由任务 3/4 的漂移测试覆盖。
2. 原文/根规范/附件更新：引用闭包改变不能复用旧结果，无关资料变化不误伤；由任务 2/3 覆盖。
3. CLI 中断和并发：未完整证据不能变成 passed，锁冲突不能覆盖状态；由任务 1/4/5 覆盖。
4. 同名空间对象和本机路径：身份/结果不串用，路径和私有输出不进共享配置或公共页面；由任务 1/2/6 覆盖。
5. 接续时已有用户修改：不能用恢复便利为由 reset、覆盖或误算任务成果；由任务 3/5/6 覆盖。

Core 公共调用在实施时保持以下签名，类型字段遵循主设计，不引入第二套同名模型。`SpaceStore` 在 storage.ts 定义，所有写入包含空间边界和预期 revision。

```typescript
resolveWorkspace(workspaceDir: string): Promise<ResolvedWorkspace>
openSpaceStore(workspace: ResolvedWorkspace): Promise<SpaceStore>
scanSources(workspace: ResolvedWorkspace, store: SpaceStore): Promise<ScanResult>
annotateCatalog(workspace: ResolvedWorkspace, store: SpaceStore, input: CatalogAnnotationInput): Promise<Catalog>
createTask(workspace: ResolvedWorkspace, store: SpaceStore, input: TaskInput): Promise<TaskState>
reviseTask(workspace: ResolvedWorkspace, store: SpaceStore, taskId: string, input: TaskRevisionInput): Promise<TaskState>
prepareTask(workspace: ResolvedWorkspace, store: SpaceStore, taskId: string, options?: PrepareOptions): Promise<PrepareResult>
exportContext(workspace: ResolvedWorkspace, store: SpaceStore, taskId: string): Promise<ContextBundle>
runCheck(workspace: ResolvedWorkspace, store: SpaceStore, taskId: string, checkId: string): Promise<RunRecord>
verifyTask(workspace: ResolvedWorkspace, store: SpaceStore, taskId: string): Promise<VerificationResult>
createHandoff(workspace: ResolvedWorkspace, store: SpaceStore, taskId: string, notes: HandoffNotes): Promise<Checkpoint>
resumeTask(workspace: ResolvedWorkspace, store: SpaceStore, taskId: string): Promise<ResumeResult>
completeTask(workspace: ResolvedWorkspace, store: SpaceStore, taskId: string): Promise<TaskState>
```

TaskInput 为未分配 revision 的合同输入；TaskRevisionInput 含 contract、expectedRevision、reason、可选 decisionRef；PrepareOptions 含 rebaseline 和 reason，重建时 reason 必填。CatalogAnnotationInput 与 HandoffNotes 遵循主设计的注记/交接输入，不从检查输出猜测完成动作或确认结论。

PrepareResult 含 snapshotId、ready 和 issues；ContextBundle 含 manifest、正文索引、分组与缺口；VerificationResult 含 phase、condition、当前验收覆盖和过期证据；ResumeResult 含 checkpointId、现场差异、可复用证据及下一步。实际类型定义集中在 contracts.ts，不能让各步骤各造一套。
