## 用户、问题与价值

第一版服务于使用 Codex 的本机使用者：资料位于自选目录或仓库，多个项目具有不同规则；换会话后容易丢失依据和现场，测试结论可能缺少版本与证据。

提供统一治理入口，并保留各项目知识所有权。让“依据什么做、检查了什么、下一步是什么”成为可追踪项目资产，避免重复解释、遗漏验收和恢复时覆盖已有修改。

## 产品边界

| 维度     | 第一版合同                                                         |
| -------- | ------------------------------------------------------------------ |
| 定位     | 通用 ai2workspace，项目空间独立，自用空间也遵循相同合同            |
| 使用环境 | 本机单用户，可管理多个空间；不做团队身份及跨机协同                 |
| 知识源   | 普通 Markdown 目录、已检出的 Git 工作目录及允许本地附件            |
| 治理     | generic / development 分开；接入不改原文，元数据可选，问题显式报告 |
| 发起入口 | 用户在 Codex 发起；项目 Skill 和 CLI 连接治理能力                  |
| 网页     | 阅读、配置与治理/结果展示，不发起编码执行                          |
| 操作授权 | 不自动提交、推送、发布、回滚、清理或调用收费服务                   |

## 完整第一版与首个闭环

完整第一版按主设计包括知识接入、治理、动态阅读、上下文、CLI 检查、任务/交接、必要的例外和汇总呈现。先实施的首个闭环只交付其中能够证明一次真实任务接续的核心。

| 能力       | 首个闭环                                     | 后续第一版完善                           |
| ---------- | -------------------------------------------- | ---------------------------------------- |
| 空间配置   | 共享描述、本机绑定、多空间隔离               | 配置编辑与诊断体验                       |
| 来源治理   | 显式扫描、身份、链接、必需依据校验           | 文件监听及更丰富治理视图                 |
| 上下文     | 显式资料、依赖、根规则、不可变副本及漂移检查 | 资料选择与影响展示体验                   |
| 检查       | 声明命令、真实结果、失败/阻塞、指纹匹配      | 导入报告、人工说明与例外合同入口         |
| 交接       | 合同、任务事实、检查点、现场比较与恢复       | BACKLOG 派生汇总、网页结果展示           |
| 阅读       | 当前站点保持可用，CLI 查询使用空间来源       | 多空间动态目录、正文、搜索与文本路由一致 |
| 名称与目录 | 文档使用目标名，运行路径保持当前状态         | 独立命名任务与 apps/web、knowledge 迁移  |

## 首个闭环的真实验收旅程

1. 使用者在一个可写配置目录描述服务自用空间，绑定自用 `knowledge` 与项目根目录；其他空间正文无需移动。
2. Codex 根据一个真实、边界清楚的维护任务准备合同和验收，读取包括根规范在内的上下文。
3. Codex 在当前授权内实施，在指定工程调用 CLI 检查。至少展示一次失败或阻塞，再在实际修复后得到匹配当前输入的通过结果。
4. CLI 保存真实证据并生成交接；工作区可以保留合法未提交修改。
5. 使用者在新 Codex 会话继续同一任务。该会话通过交接定位依据、现场、已验证项和下一步；不依赖原聊天补充才能继续。
6. 核对改动没有覆盖初始用户修改，旧证据没有在新候选上被误用。只有交付及检查合同满足后任务才完成。

测试用的小型工程可以验证 CLI 行为，但不能独自替代第 5 步的真实会话验收。自用任务选择不预先授权任意业务、收费或远端操作。

## 风险与限制

- 外部 Coding Agent 可以绕过 CLI 修改文件；系统通过准备、检查和恢复发现变化，不能保证其所有操作均受系统拦截。
- 本机采集证据帮助追溯，不是对抗本机所有者伪造的远程证明。
- 格式/链接/构建通过只支持文档站事实，不代表新服务能力、产品接受或生产发布。
- 只备份共享配置不包含正文、身份和运行数据；迁移/清理需要分别保护。
- 未来依赖和 API 的组合仍需验证，不能根据接口存在性宣称动态源已可用。
