# 工作区运行

> 初始化阶段的历史运行记录。当前目录、来源绑定与命令以 [本机使用与交接](../../guides/02-本机使用与交接.md) 为准。

## 本机入口

在仓库根目录执行 `pnpm install --frozen-lockfile` 后执行 `pnpm dev`。默认 http://127.0.0.1:1140/，使用 Node.js 24 和 pnpm 12.4.2。正式预览先 `pnpm build` 再 `pnpm start`；dev 与 start 择一占用端口，不终止其他项目进程。

## CLI 与空间

构建 `pnpm build:cli` 后执行 `pnpm cli --workspace spaces/self space validate --json`。自用空间绑定 `knowledge` 和项目根，真实绝对路径仅在私有 workspace.local.yaml；运行数据位于配置的私有 dataDir。新空间与完整步骤见仓库 `PROJECT.md`和 `.agents/skills/ai2workspace/SKILL.md`。

## 检查与边界

从根目录执行 `pnpm lint`、`pnpm types:check`、`pnpm format:check`、`pnpm test`、`pnpm build` 和 `pnpm test:e2e`。浏览器测试默认启动已构建站点；已有预览可设置 WORKSPACE_TEST_URL。命令说明不代表本轮检查已通过，最终结果见根 BACKLOG 与实施计划。

无需数据库、付费模型或外部搜索服务。CLI 仅执行配置检查；不自动启动 Codex、不执行正文命令、不提交或发布。独立进程恢复不能代替真实跨 Codex 会话验收。

## 部署与恢复

采用标准 Next.js build/start，根 workspace 安装与构建，Web 包在 `apps/web`。生产托管、访问范围和远端资源仍按实际授权处理。本机预览不代表发布。恢复先核对合同、快照、现场和证据，不自动应用补丁或重置用户修改。
