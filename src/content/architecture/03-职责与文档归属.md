# Workspace 模块职责与文档归属

本文件按用户最新确认的项目内 Workspace 模块定位与参考目录修订。它是当前目录职责约定；完整机制见 [交付设计](./05-Workspace交付设计.md)，范围见 [模块需求](../product/requirements/03-Workspace模块范围.md)。旧原文和封存证据保留其历史身份。

目录按内容归属，角色以 harness/roles.json 承担维护责任。一个需求只有一份权威定义，设计、实现、测试、运维和交接以 ID 与版本引用。根规范不复制，模板正文不再存第二份。

## 模块依赖

Workspace 只负责项目声明、本机绑定和基础校验；Knowledge 管理资料身份和修订；Context 组织显式材料；Harness 固定任务、解释当前项目策略、执行检查并验证产物和交接。

依赖方向仍为 Harness → Context → Knowledge → 基础配置与存储。Workspace 可以声明 Harness 策略的位置，但不执行 Harness 策略；网页调用领域 API，不复制判定。它们是同一项目内的模块，不拆成通用部署服务。

## 身份与历史

src/content/document-ids.json 保留既有阅读 ID，路径迁移不改变文档身份。旧索引、TaskOrigin、快照、运行和检查点不按新目录覆盖。源绑定变化如实使旧依据过期；当前任务经显式修订重建，保留最初 origin。

私有迁移只改仍指向旧默认 docs 和 templates 的绑定，保留自定义路径、运行目录、注释及历史资产。新初始化使用 src/content 和 harness/templates。

普通资料和旧 generic profile 的兼容读取仍可使用，但不是首期产品定位，也不继续建设通用空间平台。原迁移清单仅作为历史记录，不承担当前目录权威。
