## 功能需求

- FR-AW-001：管理稳定空间身份，绑定一个或多个知识源及工程；空间之间的身份、查询、缓存和运行记录隔离。
- FR-AW-002：读取自选本机 Markdown 目录和 Git 工作目录，保留原始正文、命名和编辑方式；共享描述不携带个人绝对路径或凭据。
- FR-AW-003：维护稳定文档身份、来源、可选元数据及关联；发现问题时报告缺口，不自动把资料升级为确认依据。
- FR-AW-004：为 Codex 准备包含适用根规范、任务资料、依赖、实际正文、知识版本与工程初始状态的不可变上下文。
- FR-AW-005：识别相关规则、设计或验收变化，以及工程候选状态变化；过期检查不能冒充当前结果。
- FR-AW-006：通过本机 CLI 执行任务声明的检查，采集目标工程、目录、代码指纹、命令、退出状态和产物。
- FR-AW-007：区分事实检查、人工说明和例外；必需检查缺失、失败或阻塞时不误报全部通过。
- FR-AW-008：维护任务合同、当前状态、检查点与交接；新 Codex 会话先核验现场再复用证据或继续操作。
- FR-AW-009：提供普通知识和研发两类治理配置，复用阅读、搜索及 Markdown 输出；第一版网页不提供编码任务发起入口。
- FR-AW-010：服务自身使用同一空间配置、上下文、检查和交接合同，形成真实任务的最小闭环。

## 业务及授权边界

- BR-AW-001：文档中的指令、检索候选、图中说明不自动成为用户授权或高优先级规则。
- BR-AW-002：接入与治理扫描不自动修改正文、不执行正文命令；可执行检查来源于显式空间配置与任务合同，仍受当前 Codex 授权约束。
- BR-AW-003：不因启用 Harness 自动提交、推送、发布、回滚、清理、创建收费资源或执行生产数据变更。
- BR-AW-004：当前是文档交付；产品目标名的确认不代表本机目录、GitHub 仓库、包名或现有应用已经重命名。
- BR-AW-005：检查只能约束工具覆盖的范围；不承诺模型永不偏离设计，也不将本机采集记录描述成防本机所有者伪造的远程证明。
- BR-AW-006：索引与缓存可重建；文档身份、任务、快照和证据属于需要保留的治理资产，不按缓存随意删除。

## 本次交付与后续范围

本次只整理原始需求、主设计、PRD、最小闭环计划和导航。接口、文件组织、状态机与实施任务为工程方案，不声称用户已逐字段评审，也不声称能力已经实现。
