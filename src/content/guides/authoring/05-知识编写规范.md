# 知识库编写规范

## 资料与产品知识

通用空间接入普通 Markdown，保留原目录、文件名和编辑方式，不要求 PRD、编号或研发模板。服务自用正文位于 `src/content`；本服务按 product、architecture、guides、development、archive 归属组织文档，但不把本仓库分类强加给其他空间。

产品要求由原始需求与明确确认进入产品范围和验收；设计、用户故事及测试关联对应产品要求，Plan/任务引用实际需要的依据。关联采用稳定 ID 与链接，不强制 requirement → design → PRD → plan 的单向链。每份文档明确主要依据与跨领域依赖，不重复维护正文。初始化历史原有“唯一来源设计/PRD”关系是当时记录，保留可追踪性；小修复不机械创建全套文档。

## 来源与确认

保留用户原意、来源、稳定 ID、明确确认与实际证据。公开事实、观察、推断、建议和待定分别标注，不补造人员、排期、容量或能力。评审通过不等于实现或验收完成。侧载治理状态由 catalog 维护，确认绑定正文摘要与 decisionRef；正文变更不能自动继承旧确认。用户原文和截图来源不因名称迁移而改写。

## 文档与链接

编号为可选组织方式，不承担身份。本服务现有 `NN-名称.md`、00 导航和 meta.json 可保留；增加同类编号时保持唯一，不重排旧文。`src/content/document-ids.json` 保留既有阅读 URL 映射，Core catalog 登记空间/来源/文档身份；移动时显式关联，稳定 ID 不随路径改变。

相对链接显式使用 ./ 或 ../；移动正文同步有效相对链接、导航与既有映射。历史命令和路径若为当时证据则标为历史，不能伪装成当前运行方法。普通资料缺少编号或研发元数据只作适用问题提示，不自动阻断阅读。

## 模板与任务

产品设计使用 [八节模板](./01-设计模板使用.md)，用户故事和测试分别参考 [故事模板](./02-用户故事模板使用.md)、[场景模板](./03-测试场景模板使用.md)，关联产品要求和验收 ID。空间样例在仓库 `harness/templates/workspace`；TaskInput、HandoffNotes 样例在 `harness/templates/tasks`；字段以 Core 合同和实际 schema 为准。

CLI 已登记任务以 TaskState 为当前状态权威，合同修订为定义权威；Plan 记录步骤和必要证据，不能另造实时状态。BACKLOG 当前只维护尚未纳入 CLI 的迁移、历史事实和人工验收缺口；自动派生汇总待实现后切换，不能同时手填同一任务的两份状态。

## 证据与发布

证据写清日期、版本或工作区、环境、命令、结果与限制。未执行、失败、跳过、阻塞和过期分开记录；模拟、真实子进程、真实 Codex 新会话、浏览器与生产发布分开判断。CLI 成功导出不代表宿主已读取；交接说明不自动变成检查通过。

正文只收长期知识；运行日志、工具过程计划、临时截图、凭据与构建产物不进入发布正文。根规范保留原位置和唯一来源。知识维护不自动授权收费调用、业务数据变更、Git 操作或生产发布。
