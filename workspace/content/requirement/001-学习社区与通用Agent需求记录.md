## 1. 背景与问题

ai2workspace 面向公众建设课程学习、交流和通用 Agent 服务。这是一组相互协作的需求，七个领域分别定义和验收。客服与课程助手是通用 Agent 实例，不是两套独立产品。

工程观察沿用 2026-11-17 的已核对记录：前端仅服务连接页、Go 仅健康检查及接口生成基线；身份、课程、交易、社区和 Agent 均未实现。已有文档网站不等于业务知识库，初始化通过不代表业务验收。

| 观察依据 | 仓库内路径 |
| --- | --- |
| 项目定位 | `PROJECT.md` |
| 前端入口 | `frontend/src/app/page.tsx` |
| 后端入口 | `backend/services/ai2workspace/internal/server/server.go` |

用户接受“完整闭环与权限正确”为首期验收；尚无市场访谈、销售、留存或成本实测基线。本文保存原话、来源及确认历史；具体需求条目正文由下列领域需求维护，产品规则由领域 PRD 维护。

S-01 原文：

> 1. 将我们的平台打造成一个学习交流的社区，主要的一些功能需要至少包括基本的CRUD
> 2. 我们的平台需要知识课程的播放上传以及学习，因此一些基本的社交，评论，点赞，点踩服务都是需要的，包括如何设计课程相关，视频播放相关等服务。
> 3. 我们需要基于 RAG 做智能的客服以及对应的学习的agent服务，比如我们可以做很多的课程的agent，基于我们的课程上下文回答学生提出的问题等等

> 1. 遵循MVP原则，不要过度设计，先规划我们的需求和文档不要开始编写我们的代码
> 2. 设计需要符合软件工程的规范

## 3. 目标、范围与领域入口

### 共同目标与边界

首版面向公众开放邮箱密码注册；管理员／受邀讲师供课；保留免费／试看及人民币单课购买。形成“供课 → 购买与授权 → 播放和继续学习 → 交流 → 有来源的 Agent 帮助”闭环。Agent 基于授权 RAG 并每答实际联网，至少覆盖四家指定模型提供商；不执行业务写入。

本轮只整理文档，不创建业务服务、数据库、凭据、真实订单或付费调用；不提交、推送或发布。已确认 MVP 不因拆分扩大；后续关注／私信、会员套餐分账、私人知识库与 Agent 市场仍留在各领域后续范围。直播、考试证书、工作流、多 Agent 等不预建系统。

| 课程与交易 | 课程给出可售／可交付事实；交易拥有价格、支付及按购买授予的权益 | 不以浏览器成功开通；普通停售保留已购，退款成功只撤对应授予 |
| 课程与社区／知识 | 课程组合内容状态及当前权益，供讨论和资料访问判断 | 内容撤回、退款与普通停售分别处理；索引和通知不能成为旁路 |
| 知识与 Agent | 知识提供有效授权证据和引用；Agent 配置、搜索并组织回答 | 维护者权限不能传给学员；每次新回答真实搜索，历史会话读取也复核 |
| 模型费用与知识／Agent | 模型费用领域提供允许模型、预算预占、用量与未知费用核对 | 任何付费索引、搜索或生成先准入；失败不抹除成本，AI 不可用不阻塞学习 |
| 交易／内容与通知 | 原领域拥有业务事实，社区接收去重事件 | 通知失败不回滚支付／退款，摘要不泄漏受保护正文 |

CRUD 仍按业务对象解释：内容删除、停售、撤回、账号停用、订单／退款状态不能混为物理删除。详细语义由各领域 PRD 定义或保留待决，不能通过“通用 CRUD”抹除支付及审计事实。
