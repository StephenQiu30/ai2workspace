## 1. 背景与问题

用户要在学习社区中配置不同用途的智能服务，使学习者能基于有权使用的知识资料和当前网页信息提出问题、核对答案来源。课程助手和平台客服是通用 Agent 的配置实例，不是两套固定产品。

当前依据总需求 S-04 只有工程基线，没有真实问答、可用模型或引用质量的验收证据。已有用户范围为公众学习者；尚无问答满意度、响应时间或节省人工成本的实测基线，不将预期价值记为已验证效果。

## 3. 目标与范围

首版目标是：维护者能发布不同用途的 Agent；学习者每次新提问都获得真实搜索与授权知识处理结果；完成、证据不足、失败和取消有可区分的状态，答案来源可核对。

包含管理员维护角色说明、多个知识库绑定、允许模型选择、草稿／发布／停用，以及学员在全局 Logo 浮层中提问、查看知识及网页引用、读取本人会话、取消与明确重试。用户端不建独立 Agent 页面；关闭面板与取消运行分别设计。每答联网、外发边界和失败行为遵循[本域 PRD](../prd/007-通用Agent与联网问答产品需求.md#联网搜索失败策略)。

不包含业务写入、任意工具运行器、自主循环、可视化工作流、多 Agent 协作。个人 Agent／知识库市场放到后续；视频理解和转写不随 Agent 名称自动加入。模型和费用参数由[模型费用需求](./008-模型接入与AI费用治理需求记录.md)及其 PRD 管理，不在此维护第二份预算。
