# 知识库编写规范

## 目录与职责

主链为 requirement → design → prd → plan。requirement 保存原始需求与确认；design 维护技术方案；prd 维护用户价值和验收；plan 维护执行步骤与必要证据。每份 PRD 指定唯一来源设计，每份 Plan 指定唯一来源 PRD，跨领域依赖用链接表达。

research 维护有日期与一手来源的调研，operations 维护部署运维，templates 提供模板，skills 描述项目能力，workflows 描述协作步骤。实施进度、优先级、阻塞、承诺与下一步只在根 BACKLOG 维护。

## 来源与确认

保留用户原意、稳定 ID、明确确认和实际证据。观察、推断、建议和待定分别标注，不补造人员、排期、容量或产品能力。评审通过不等于实现或验收完成。

## 文档与链接

每类以 00 导航开头，正文采用 NN-名称.md，类内序号唯一。日期放序号后，已有空缺不重排；正文 H1 不手写重复编号，展示编号由文件名派生。

content/document-ids.json 维护唯一稳定 ID 与文件路径，ID 不随移动改变。meta.json 定义侧栏顺序。相对链接显式以 ./ 或 ../ 开头，重命名同步导航、映射和锚点；原始需求和有效验收不能通过整理静默删除。

## 模板

设计使用 [八节模板](./01-设计模板.md)，用户故事使用 [故事模板](./02-用户故事模板.md)，验收使用 [场景模板](./03-测试场景模板.md)。按实际需要引用，不为临时修复机械创建全套文档。

## 证据与发布

证据写清日期、版本或工作区、环境、命令、结果与限制。未执行、失败、跳过和阻塞分开记录；模拟、真实服务、浏览器和生产发布分开判断。

正文只收长期知识；日志、截图、工具过程计划、凭据与构建产物不进入 content。根规范保留原位置，不复制成第二套权威。文档维护不自动授权收费调用、业务数据变更、提交、推送或生产发布。
