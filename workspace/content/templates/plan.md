title: 执行计划模板
description: 使用 Superpowers 拆解可实施计划，补充项目验收关联、执行证据与交接。
---

实施计划采用 `superpowers:writing-plans` 的当前方法。先实际读取上游 Skill，再依据已知规格生成计划头、任务结构与自检；本页只提供项目适配字段，不能用空白骨架代替完成的计划。

目录和引用规则见[项目规范](../standards/project-design.md)。默认保存到 `workspace/content/projects/项目标识/专题/plan.md`，用户指定位置时遵从用户；不另建 `docs/superpowers/plans/` 副本。

## 项目记录

| 项目字段 | 填写要求 |
| --- | --- |
| 文档 ID / 所属项目 | 稳定的 `PLAN-项目-主题` 与实际专题 |
| 定义与执行状态 | 计划的确认状态，以及任务的真实执行状态分别记录 |
| 实施依据 | 真实需求、PRD、设计链接与适用版本 |
| 执行范围与方式 | 用户已经授权的工作与明确选择的执行方式；未知时不代选或启动 |

## 计划头

成稿时移除模板说明，正文开头按上游当前要求生成计划头及执行者说明，包含以下决策信息：

- **Goal**：一个明确的交付目标。
- **Architecture**：实际方案与职责边界。
- **Tech Stack**：真实工程使用的技术。
- **Spec**：本计划实现的规格或设计路径，执行者同时读取。

## Global Constraints

汇总规格中适用于全局的真实约束及准确数值，任务通过引用继承；不将猜测或上游示例语言、文件名当成本项目要求。

## Review Focus

按上游要求检查规格隐含的输入类别与失败模式，指出最重要的未覆盖风险，并将相应验证落实到负责该代码的任务。此处是实际审查结果，不是固定复制的通用风险清单。

## 文件职责与任务依赖

先核对实际工程与已有修改，再列出将创建或修改的准确路径、各文件职责和任务依赖。按独立可验证的交付划分任务；准备、配置与说明归入需要它们的交付，不单独制造阶段。

## 任务拆解

由 `superpowers:writing-plans` 生成完整任务块；每个任务除上游要求的 Files、Interfaces 和可检查步骤外，补充本项目的依据、状态与验收关联。

### Task T-01：实际交付名称

| 字段 | 填写要求 |
| --- | --- |
| 依据与依赖 | 实际设计章节、需求 / FR / AC-ID 和前置任务 |
| Files | 准确列出 Create、Modify、Test 的实际路径，适用时注明位置 |
| Interfaces | 前置任务提供的接口，以及本任务产出的准确名称、参数和返回类型 |
| 验证方法 | 具体测试名和断言，或风险适用的真实检查及操作 |
| 状态 | 未开始、进行中、阻塞或有真实证据的已完成 |

在此生成 `- [ ]` 形式的具体步骤。每步有可检查的结果；测试步骤写清名称和断言，代码步骤写清文件与接口，验证步骤写清实际命令和预期结果。成稿不得保留“实现功能”“加一些测试”等含糊动作，也不大段复制已能由接口与测试确定的实现代码。

任务中的检查、Commit 或发布步骤只是计划，不构成执行授权。低影响文档修改和工程代码变更按实际风险采用适用验证，不复制上游样例命令。

## 自检与验收覆盖

先完成上游的计划自检，再核对本项目的验收覆盖：

| 产品验收 / 技术风险 | 负责的任务与具体步骤 | 实际验证方式 | 当前结果 |
| --- | --- | --- | --- |
| 实际文档引用及 AC-ID，或明确风险 | T-ID 与步骤 | 实际命令、测试或操作 | 初始为未执行 |

缺项补入负责的任务，接口和类型在任务间保持一致。计划只记录执行者不能自行决定的信息，细节深度与本次规格匹配。

## 执行证据与变更

| 记录 | 任务 / 验收 | 实际版本、环境与操作 | 结果、限制与证据引用 |
| --- | --- | --- | --- |
| 实际执行后新增 | 实际关联 | 实际观察 | 如实标注通过、失败、跳过、模拟、阻塞或未执行 |

任务定义或依据变化时，记录决定来源、影响及需要重新验证的范围。日志与私有数据不进入正文，命令入口见[知识库使用说明](../index.md)。

## 交付与交接

计划编写完成后先保存和自检，再按 `writing-plans` 的交接流程供用户审阅并处理后续执行方式；已给出的选择继续沿用。编写计划不自动触发实施、子代理、提交或发布。

实际执行后的交接分别记录已完成、未完成与阻塞、对应证据、验收结果、Git / 发布事实和具体下一步。不把计划已保存或评审通过写成代码已完成。
