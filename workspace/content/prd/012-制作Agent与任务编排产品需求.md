## 1. 摘要

让制作团队通过编剧、分镜和校验 Agent 取得可编辑候选，并在同一项目看清数据来源、运行状态和成本。

## 3. 背景

用户要通过学屿掌握 Agent 平台和多 Agent 编排。真实制作需要控制版本、费用和人工确认，先用有限的制作步骤验证价值。

## 4. 目标与成功标准

跑通「剧本候选 → 人工确认 → 分镜候选 → 校验意见」链路。操作者能采纳、拒绝和重试，看见失败步骤、输入版本及用量。用代表性案例查看校验是否能指出样本中的设定冲突。

## 5. 目标用户

- 编剧和分镜人员需要可编辑的草案与分镜建议。
- 审片人和制作运营需要检查依据，处理生成失败和费用异常。

## 6. 价值主张

| Who／Why | What before／Alternatives | How／What after |
| --- | --- | --- |
| 创作者要把同一个故事从分场写到分镜 | 可以在通用对话工具和文档之间复制草稿和参考资料 | 在作品中按版本运行任务，候选可修改、可选用且来源可查 |
| 审片人与运营需要说明结果为什么失败或超费 | 可在不同模型后台手查，制作版本与模型记录可能分开 | 运行详情对应输入、节点、引用和费用，能定位问题并从适当步骤恢复 |

## 7. 产品方案

**页面**为剧本、分镜及审片内的 Agent 操作和任务抽屉。制作任务保存步骤和候选结果，由操作者在权限范围内采纳。项目检索见[制作知识库与RAG](../prd/011-制作知识库与RAG产品需求.md)。

| 行为 | 来源 | 规则 | 验收 |
| --- | --- | --- | --- |
| FR-01 制作 Agent | R-01 | 编剧出场景和对白，分镜出镜头草案，校验出冲突与证据。候选由人采纳 | AC-01：依次执行三个步骤，候选能编辑或拒绝；拒绝后未改正式作品。用已知设定冲突与缺证据样本运行校验，能分别定位冲突和标出依据不足 |
| FR-02 任务记录及恢复 | R-02 | 记录输入、配置、引用和步骤状态，支持查看、取消和明确重试 | AC-02：重复点击得到同一运行；分镜失败后保留已完成结果，可重试失败步骤。输入换版后，迟到结果不能覆盖新稿 |
| FR-03 预算与用量 | R-03 | 调用前检查预算，状态详情显示已知用量或待核对 | AC-03：不足额时任务显示受限且允许继续手工编辑，已发生的费用可定位。原调用结果未知时显示待核对，重复提交不引起第二次扣费请求 |

## 7.3 非功能验收

| 验收 | 需求 | 可观察结果 |
| --- | --- | --- |
| AC-11 | NFR-01 | 对包含要求修改发布状态的候选做运行，候选不会改变正式版本、公开状态或交易状态 |
| AC-12 | NFR-02 | 在已知、未知和取消三种结果下检查预算记录；重复提交保持同一运行，核对完成前不多发请求 |
| AC-13 | NFR-03 | 从一例失败的分镜任务定位到失败步骤、输入版本和用量状态；普通账号及日志输出无法取得密钥或不该访问的源文 |

## 7.4 待决定问题

模型、生成工具、预算、超时和评测样本见需求 Q-01、Q-02。若使用真实计费服务，需单独确认试点范围。

## 8. 版本范围与发布

首版采用一条固定任务流程和明确的人工确认点。通用可视化编排、开放工具市场和自动对外发布留待另外验证。
