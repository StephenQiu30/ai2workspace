## 1. 摘要

ai2workspace 面向公众提供课程学习、交流和有来源的通用 Agent 帮助，由管理员与受邀讲师供课，支持邮箱注册与人民币单课购买。产品由七个相互关联的领域组成，各有需求、设计、PRD 和计划；平台客服和课程助手共用 Agent 配置机制，每次新回答实际联网。

本页保留整体目标、跨领域行为与验收及旧引用入口。领域产品规则已迁往对应 PRD，本页不再保存第二份政策表；迁移不扩大 MVP，也不意味着业务已交付。

## 3. 背景

需求来自用户规划，尚无市场调研、课程销售或学习留存数据。工程目前只有技术基线，因此本版是业务产品定义，不能把已有知识库网站或健康检查当作业务功能。知识库网站继续保存项目文档，产品课程、用户内容与业务知识库由业务系统管理。

## 4. 目标与成功标准

| 目标 | 首版可观察的成功条件 | 测量方式 |
| --- | --- | --- |
| 供课与学习闭环 | 一门真实课程从创建、上传、处理、发布到购买、播放、进度恢复均可完成 | 使用讲师、普通学员与管理员角色走通 AC-01–AC-05；上线前验证所选真实媒体和支付环境 |
| 社区与智能帮助 | 学员能发布讨论、回复和反馈，并通过 Agent 获得可核对的知识库／网页引用 | 以代表性课程问题与平台问题执行 AC-06–AC-10 |
| 权限与异常正确 | 无权益不能获取付费内容；重复支付通知不重复授予；撤回资料不可继续用于新回答；故障有明确状态 | 执行 AC-03、AC-04、AC-08–AC-12 的异常与越权场景 |

这是用户接受的首期产品验收口径，不等于商业成功。转化率、完课率、留存、问答满意度以及响应时间质量目标在取得实测基线后确定；成本准入参数采用[模型费用 PRD](./008-模型接入与AI费用治理产品需求.md#ai-费用控制)，不在本阶段编造目标值。

## 5. 目标用户与细分

面向公众，不限定职业或课程主题；具体账号资格规则另行确定，按用户要完成的工作区分角色：

- **学习者**：寻找适合自己的课程，完成学习，向社区和 Agent 求助；可以购买课程并参与讨论。
- **内容供给者**：管理员或受邀讲师，组织课程、上传素材、维护获授权知识，处理课程相关问题；讲师提交课程后由管理员审核发布。
- **平台运营者**：管理员维护账号和讲师资格、发布审核、订单退款、内容处置、Agent 配置与服务质量；Agent 配置仅限管理员，依据[需求 009](../requirement/009-学屿品牌与界面需求记录.md) UI-S-08。后台管理是运营入口，不另造一套业务数据。

一个账号可以同时具备多个角色；“受邀讲师”不意味着可以管理其他讲师的课程或查看所有学员数据。

## 6. 价值主张

| 维度 | 学习者 | 内容供给者／运营者 |
| --- | --- | --- |
| Who | 需要课程和交流帮助的公众用户 | 提供课程并持续维护学习体验的人 |
| Why | 找到、获取并理解学习内容，在疑问出现时得到可核对的帮助 | 发布内容、管理可见范围与销售，减少重复答疑并处理异常 |
| What before | 尚未取得现状访谈；课程、讨论与检索可能分散只是待验证假设 | 尚未取得运营基线，不宣称已有人工成本改善数据 |
| How | 浏览试看、购买播放、恢复进度、社区交流、RAG＋联网 Agent | 课程和素材管理、发布与权益流程、知识库／Agent 配置、必要运营管理 |
| What after | 在同一平台完成学习与求助，能看清答案依据及内容访问范围 | 内容、交易、知识与反馈可追溯地维护，失败操作有恢复路径 |
| Alternatives | 其他课程平台、独立社区、通用搜索或问答工具；是否选择本平台需真实试用验证 | 分别使用内容管理、收款和答疑工具；集成价值与成本优势尚待验证 |

产品价值假设是：把课程获取、学习交流和可溯源的智能帮助连在一起，使学员可以持续学习，使供给者可以持续维护课程。首版通过完整闭环验证这一假设，不以功能数量代替用户价值。

## 7. 产品方案

### 7.1 跨领域主流程

供给者验证身份并维护课程 → 媒体处理和显式发布 → 学员验证邮箱、下单 → 服务端确认支付并授予权益 → 授权播放、图文学习与进度恢复 → 课程讨论和反馈 → 通用 Agent 使用有权知识并实际联网后回答。

退款、内容撤回、账号停用和 Agent 停用走相应领域的明确状态；通知、索引和缓存只消费事实，不成为授权权威。AI 故障或预算不足不阻塞已独立可用的学习、交易和社区。各流程的界面、业务规则与异常由领域 PRD 定义，技术接口由设计维护。
