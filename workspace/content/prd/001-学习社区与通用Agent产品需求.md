## 1. 摘要

ai2workspace 面向公众提供学习交流社区，由管理员与受邀讲师供给课程，用户通过邮箱密码注册，免费学习或购买单门课程，并围绕学习内容交流。通用 Agent 组合有权访问的 RAG 知识库，并在每次回答时联网搜索；模型接入至少覆盖 DeepSeek、OpenRouter、火山、OpenAI；平台客服和课程助手是不同配置实例。

完整设计覆盖内容、交易、学习、社交、智能服务与运营；首版以一条真实可用且权限正确的学习闭环验证产品。Agent 不承担退款、发帖或修改课程等业务写入。

## 3. 背景

需求来自用户规划，尚无市场调研、课程销售或学习留存数据。工程目前只有技术基线，因此本版是业务产品定义，不能把已有知识库网站或健康检查当作业务功能。知识库网站继续保存项目文档，产品课程、用户内容与业务知识库由业务系统管理。

## 4. 目标与成功标准

| 目标 | 首版可观察的成功条件 | 测量方式 |
| --- | --- | --- |
| 供课与学习闭环 | 一门真实课程从创建、上传、处理、发布到购买、播放、进度恢复均可完成 | 使用讲师、普通学员与管理员角色走通 AC-01–AC-05；上线前验证所选真实媒体和支付环境 |
| 社区与智能帮助 | 学员能发布讨论、回复和反馈，并通过 Agent 获得可核对的知识库／网页引用 | 以代表性课程问题与平台问题执行 AC-06–AC-10 |
| 权限与异常正确 | 无权益不能获取付费内容；重复支付通知不重复授予；撤回资料不可继续用于新回答；故障有明确状态 | 执行 AC-03、AC-04、AC-08–AC-12 的异常与越权场景 |

这是用户接受的首期产品验收口径，不等于商业成功。转化率、完课率、留存、问答满意度以及响应时间／成本阈值在取得基线和预算后确定，不在本阶段编造目标值。

## 5. 目标用户与细分

面向公众，不限定职业或课程主题；具体账号资格规则另行确定，按用户要完成的工作区分角色：

- **学习者**：寻找适合自己的课程，完成学习，向社区和 Agent 求助；可以购买课程并参与讨论。
- **内容供给者**：管理员或受邀讲师，组织课程、上传素材、维护知识与 Agent，处理课程相关问题。
- **平台运营者**：维护账号和讲师资格、发布审核、订单退款、内容处置与服务质量。后台管理是运营入口，不另造一套业务数据。

一个账号可以同时具备多个角色；“受邀讲师”不意味着可以管理其他讲师的课程或查看所有学员数据。

## 6. 价值主张

| 维度 | 学习者 | 内容供给者／运营者 |
| --- | --- | --- |
| Who | 需要课程和交流帮助的公众用户 | 提供课程并持续维护学习体验的人 |
| Why | 找到、获取并理解学习内容，在疑问出现时得到可核对的帮助 | 发布内容、管理可见范围与销售，减少重复答疑并处理异常 |
| What before | 尚未取得现状访谈；课程、讨论与检索可能分散只是待验证假设 | 尚未取得运营基线，不宣称已有人工成本改善数据 |
| How | 浏览试看、购买播放、恢复进度、社区交流、RAG＋联网 Agent | 课程和素材管理、发布与权益流程、知识库／Agent 配置、必要运营管理 |
| What after | 在同一平台完成学习与求助，能看清答案依据及内容访问范围 | 内容、交易、知识与反馈可追溯地维护，失败操作有恢复路径 |
| Alternatives | 其他课程平台、独立社区、通用搜索或问答工具；是否选择本平台需真实试用验证 | 分别使用内容管理、收款和答疑工具；集成价值与成本优势尚待验证 |

产品价值假设是：把课程获取、学习交流和可溯源的智能帮助连在一起，使学员可以持续学习，使供给者可以持续维护课程。首版通过完整闭环验证这一假设，不以功能数量代替用户价值。

## 7. 产品方案

### 7.1 主要流程与交互

1. **发现与账号**：用户浏览课程目录、详情和可公开讨论；需要购买、完整学习或互动时登录。邮箱注册、验证、登录、找回密码的流程完整，邮件未送达可重试。邮箱验证后才可购买和互动已确认；具体公开展示范围仍待评审。
2. **课程供给**：供给者维护课程简介和内容，上传素材并看到进度、处理中、失败／重试或可用状态；审核发布后进入目录。首版录播、课程／章节／课时和图文资料已由 Q14 确认。
3. **购买学习**：用户查看价格与试看范围、创建订单并支付；支付结果未确认时显示处理中，可查询，不要求重复支付。权益生效后开始播放，离开后能继续学习。平台持续提供课程期间保留已购访问，普通下架只停止新售；退款人工审核，成功后撤销相应权益。
4. **交流反馈**：用户发布独立帖子或课程讨论，评论／回复、赞踩和收藏；能找到自己的内容并编辑／删除，收到必要通知，可举报不当内容；管理员可处置并记录原因。
5. **智能帮助**：用户选用已发布 Agent，每次回答前均发起联网搜索，提问后可看到回答和来源；知识库与网页引用可区分，来源冲突、信息不足和联网失败均明确提示。页面提供联网状态，不能假装完成未执行的搜索。
6. **运营恢复**：管理端处理发布审核、举报、退款、素材或知识处理失败；用户能看到业务状态。管理台不直接修改数据库，也不依赖 Agent 代操作。

所有主要页面覆盖加载、无内容、无权限、失败及恢复状态；未购买、已购买、处理中、下架分别呈现对应行为。尚无设计稿，本轮不虚构视觉验收；业务界面沿用工程既定 shadcn/ui Radix 基线。

### 7.2 首版功能、规则与验收

下表确认的是需求方向与验收建议；新增业务规则在整体评审前保持草稿。每个 AC 都是未来应验证的结果，本轮没有执行业务验收。

| 行为 | 关联需求 | 产品行为与规则建议 | 验收与可观察结果 |
| --- | --- | --- | --- |
| FR-01 账号与角色 | R-01 | 邮箱密码注册登录；邮箱验证、找回、退出；讲师邀请和账号停用；资源归属独立于角色校验 | AC-01：普通用户可完成注册登录；重复邮箱、错误密码和失效找回链接得到明确结果；普通用户不能进入供课操作，讲师不能修改他人课程 |
| FR-02 课程管理与发现 | R-02 | 课程与学习内容 CRUD、草稿／发布／下架、目录；分类／标签与标题搜索为未确认候选；建议管理员审核发布，已售课程不直接物理删除 | AC-02：草稿不公开；发布后可浏览，搜索纳入范围后验证可检索；修改未发布内容不泄露；普通下架停止新售且已购仍可学习；特殊撤回按另行确认的政策处理 |
| FR-03 素材与播放 | R-03、R-15 | 上传、处理状态、失败恢复；仅可用素材参与发布；鉴权后播放，试看与付费内容明确分开 | AC-03：上传失败可恢复或重传；处理中不可当作已可播放；未购买者不能用媒体地址、文稿接口或引用绕过保护；有权益者能播放；新增 AC-14 验证第 7.5 节推荐上传规格 |
| FR-04 交易与权益 | R-04、R-14 | 人民币单课购买，免费课／试看；订单、支付状态查询、购买记录、退款申请与运营处理；服务端确认结果 | AC-04：重复、乱序通知不重复收款操作或授予权益；前端伪造成功不能开通；支付超时未知可查询恢复；人工审核退款成功后撤销对应权益，处理中和失败状态不得冒充完成；新增 AC-15 验证第 7.5 节推荐退款细则 |
| FR-05 学习记录 | R-03 | 我的课程、最近学习位置和进度；暂停／离开后可继续；学习进度不授予购买权益；完课判定为未确认候选 | AC-05：同一用户再次进入可恢复位置；用户间进度隔离；课程内容变更时说明进度兼容结果；完课判定纳入范围后再按评审标准验证 |
| FR-06 社区互动 | R-05、R-06 | 独立帖子、课程讨论、评论／单层回复；赞／踩／未表态互斥并可取消；收藏；作者管理自己的内容 | AC-06：重复点赞不重复计数，切换赞踩保持唯一态；他人不能编辑；删除或隐藏内容后列表与详情状态一致；收藏可取消 |
| FR-07 通知与内容管理 | R-06 | 首版站内通知：购买结果、回复、审核／举报处置等必要事件；举报提交、管理员处置和原因记录 | AC-07：接收人只能查看自己的通知；重复投递不产生重复业务事项；举报后可处理，隐藏内容不能继续通过详情或搜索公开访问 |
| FR-08 业务知识库 | R-08 | 管理资料导入、来源、版本、可见范围、处理状态和撤回；课程资料需显式授权接入，用户讨论不自动成为可信知识 | AC-08：导入失败可重试；未发布版本不参与回答；删除、撤回或权益失效后，新检索及历史会话重新读取不泄露受保护内容 |
| FR-09 通用 Agent | R-09、R-13 | 管理角色说明、多个知识库绑定、提供商／模型选择、草稿／发布／停用；每次回答联网，不提供绕过联网的正常回答开关；客服和课程助手复用同一配置机制 | AC-09：两个不同用途的 Agent 可复用机制且内容范围不同；讲师不能绑定无权使用的知识；停用后不能发起新问答 |
| FR-10 RAG＋联网回答 | R-10、R-16 | 对允许的资料检索；每次回答均发起联网搜索；回答附知识来源或网页链接；证据不足不编造引用；不执行平台写入 | AC-10：可溯源回答覆盖课程问题、时效问题、来源冲突和证据不足场景；即使知识库已足够，每次新回答仍有实际搜索记录；推荐搜索失败即停止正常作答，新增 AC-16 覆盖第 7.5 节超时／重试／零结果；提示注入不能泄露受限资料或触发业务操作 |
| FR-11 付费内容保护 | R-03、R-04、R-08–R-10 | 课程、文稿、播放授权、检索、会话、引用均检查当前权限；Agent 配置者有权访问不等于使用者有权访问 | AC-11：未购／退款撤权／被停用用户均不能通过新请求、其他 Agent 或会话链接读取付费内容；已签发播放凭证的残留有效期必须按评审目标验证 |
| FR-12 可恢复运行与运营可见性 | R-04、R-08–R-11 | 展示失败状态、保留可追踪记录；查询支付未知结果；重试媒体和索引任务；AI 失败不阻塞课程学习 | AC-12：模拟渠道、媒体或模型故障后状态明确，可恢复且不重复授权或重复发布；后台可定位失败原因，用户界面不暴露内部凭据 |
| FR-13 多模型提供商 | R-13 | 至少接入 DeepSeek、OpenRouter、火山和 OpenAI；Agent 使用所配置模型，供应商不可用时明确失败，不擅自换供应商外发数据 | AC-13：四家各使用一个实际可用模型分别完成问答、流式或已声明的完整返回、错误展示及可取得的用量记录；每家均验证 RAG 与实际联网链路，不把兼容接口或模拟响应当作接入完成 |
| FR-14 AI 用量与费用控制 | R-17 | 账号配额、调用上限、平台预算、预占与实际费用核对；不做钱包、积分或自动超额扣款 | AC-17：并发不透支预算，失败释放成功次数但保留真实费用，未知用量不记零，入库任务不能绕过总额；详见第 7.5 节 |

赞踩对象建议为帖子、评论和回复；课程评价与星级评分另行决定。首版社区排序建议按时间，不因赞踩自动生成复杂推荐。课程讨论已确认需要有课程访问权才参与，详情页可公开内容的边界待评审。

### 7.3 技术约束

沿用根 `PROJECT.md` 的 Next.js、Go 微服务、HTTP API、独立数据所有权和接口生成链路；课程不是静态文档页面，业务知识库不是 `workspace/content/` 的默认镜像。服务划分、媒体链路、支付幂等、RAG 权限和联网边界见[顶层设计](../design/001-学习社区与通用Agent顶层设计.md)。本轮不新增框架、脚本或业务工程。

### 7.5 MVP 推荐细则

本节为 **2026-11-17 的待确认推荐方案**，依据 S-07 细化。数值是试运营与验收起点，不是实测性能、法律结论、已生效的售后承诺或支出授权。产品默认值以本节为唯一来源，需求和设计通过引用关联；既有每答联网、退款成功撤权和四家模型要求继续有效。

#### 退款规则

| 项目 | 推荐默认规则 |
| --- | --- |
| 普通窗口 | 课程学习权益首次实际可用起 **7×24 小时内**，可申请整单全额原路退款。起点是服务端确认已支付且课程可访问的时刻，不是首次点击播放；按申请提交时间判断，截止时刻提交也受理 |
| 人工核验 | 核验本人订单、实付与已退款事实；窗口内不因已观看、完成课时或使用 AI 拒绝，不扣观看费或 AI 费。以宽松规则换取首版简单流程，承认已消费后退款的经营成本 |
| 金额与时限 | 只退实际支付金额，不做部分退款、手续费或平台余额替代。建议 **2 个工作日内**给出审核结论，通过后 **1 个工作日内**提交渠道；这是待确认的运营目标。到账按渠道状态展示，不承诺固定到账日 |
| 窗口外及特殊情况 | 质量不符、无法交付、重复扣款及依法应退情形保留人工入口，不因超窗自动拒绝。因内容问题永久停止交付或平台无法继续供课，建议主动通知并整单全退，不按观看量折算；临时故障走修复和人工支持，不自动触发全部退款 |
| 权益与取消 | 待审核可撤回；批准进入提交阶段后不承诺可取消。申请、处理中、失败及结果未知均不因退款流程提前撤权；仅渠道确认成功后撤对应购买权益。内容必须撤回时可独立停止交付并处理退款，不能假称退款完成 |
| 重复与回购 | 有效权益存在时阻止再购。重复扣款退多余支付，保留合法购买；退款后回购是新订单，旧退款迟到通知不得撤销新购买权益 |
| 异常恢复 | 受理不等于成功；超时先查询原退款单，不另起一笔。明确失败／关闭后才允许人工重试，累计退款不得超过实付；异常持续 **1 个工作日**进入人工跟进并更新用户状态 |

保留购买时的政策版本；后续收紧不追溯影响旧订单。七天是拟提供的商业政策，不将在线课程一律判定为法定七天退或不退；质量与未交付责任不能被普通窗口排除。法定责任和支付渠道依据见关联设计的“退款实现与依据”。

#### 视频上传规格

| 项目 | 推荐默认规则 |
| --- | --- |
| 允许输入 | MP4 容器、H.264 视频、8-bit SDR；音轨可缺省，有音轨时为 AAC。首版不接受 HEVC、HDR、4K、ZIP 批量包或其他容器；不合格时明确提示重新导出 |
| 单文件边界 | 大小大于 0 且 **≤2 GiB（2,147,483,648 字节）**；时长大于 0 且 **≤120 分钟**；旋转后画面长边 ≤1920、短边 ≤1080；帧率 ≤30 fps，各项均需满足。横竖屏均可，建议按 10～30 分钟拆课时 |
| 上传恢复 | 每位讲师最多 **2 个并行上传会话**；采用存储官方分片／续传能力直传。会话自创建起保留 **24 小时**，续传须重新鉴权；过期重传，失效分片最终清理，不永久占空间 |
| 服务端校验 | 前置核验声明大小；完成后核验实际大小、容器、编码、时长、分辨率、帧率和可解码性。伪装扩展名、损坏或超限文件不得发布；错误区分网络可重试和文件需重新导出 |
| 播放产物 | 受保护 HLS，H.264／AAC，最多 **720p、1080p 两档**，保持比例且不增加帧率；不足对应档位不升采样，低于 720p 保留源分辨率单档。首版不提供学员原片下载入口 |
| 版本替换 | 新文件是新版本，处理成功后显式发布切换；处理失败不覆盖仍在使用的旧版。因违规撤回旧版独立处理，不通过回退重新公开违规内容 |

这些是产品候选门槛，不是云厂商通用上限；首版不建设通用视频编辑或格式转换平台。图文附件、字幕与转写不因本次规格自动纳入实施。

#### 联网搜索失败策略

| 场景 | 推荐行为 |
| --- | --- |
| 新回答与重复请求 | 每个新回答实际发起搜索；同一请求重复提交／查询读取原任务，不重复调用。用户主动重试或重新生成是新尝试，重新搜索；不能用旧答案缓存替代 |
| 超时与重试 | 单次搜索 **8 秒**，最多 **2 次尝试**，证据检索阶段合计 **18 秒**（含并行 RAG、搜索等待与网页读取）；仅网络故障、429、临时 5xx 重试一次。Retry-After 超出剩余时间就失败；不自动切换搜索供应商 |
| 失败停止 | 参数错误、认证／余额问题、安全阻断不重试。两次仍失败或无法形成安全外发查询时，保留问题、提示原因和重试入口，**不调用回答生成模型，不输出正常的纯 RAG 答案**；错误提示不是一次回答 |
| 成功零结果 | 有效搜索返回零相关结果是成功调用。可用授权 RAG 回答并标明“未找到相关网页来源”；两侧均无证据时说明不足，不编造引用。无法解析的响应属于失败，不冒充零结果 |
| 网页读取失败 | 仅引用实际取得的文本／摘要并说明范围；不能凭标题声称读过全文，需要全文才能成立的结论应说明依据不足 |
| 模型失败／取消 | 生成模型自动重试为 **0**，生成总时限 **60 秒**，流式响应空闲时限 **15 秒**；不静默跨提供商切换。超时／断流显示未完成，释放本地运行槽位，保留未知费用预占，用户可主动重试。取消尝试停止上游，不承诺已经发生的调用免费 |
| 次数与成本 | 未完成回答不扣成功问答次数，仍受发起速率和实际费用约束；已发生搜索、embedding、模型费用照实记录。完整的“证据不足”回答计入成功次数 |

建议搜索只外发处理后的问题／关键词，不发送付费资料原文、身份信息或会话全文；安全处理失败即停止，不以强制联网为由外发。RAG 检索异常也不得静默冒充课程问答，应提示知识服务暂不可用；搜索成功不等于课程依据完整。

#### AI 费用控制

首版推荐由平台承担有额度的 AI 成本，不从课程款扣除问答费用，不做钱包、充值、积分兑换、自动超额扣款或用户自带 Key。四家接入是支持经过验证的允许模型，不等于任意模型、无限推理与上下文均可用。

| 参数 | 试运营推荐默认值 |
| --- | --- |
| 账号额度 | 已验证账号每天最多 **20 次成功问答**，跨课程、Agent、模型合计；失败归还成功次数占位。购买课程不叠加次数，无权益仍不能检索付费知识 |
| 发起与并发 | 每账号每分钟最多 **3 个新问答**、同时 **1 个运行问答**；平台同时最多 **10 个运行问答**。超出立即提示稍后重试，不建无限队列 |
| 请求上限 | 总输入最多 **8,000 tokens**，含系统、历史、问题、RAG 和网页；生成最多 **2,000 个可计费输出 tokens**，包含上游计费推理部分。不支持可靠限额的模型不进入允许列表；裁减内容保留来源和权限，不制造误导引用 |
| 成本上限 | 单次最终预占（包含下述 20% 缓冲）最多 **¥0.50**、单账号 **¥2／日**、平台 AI／搜索合计 **¥100／日、¥2,000／月**；任一不足就拒绝新付费调用。20 次不是保证可用次数，昂贵模型可能先触及成本上限 |
| 入库任务 | 解析、转写、embedding、索引重建纳入平台同一预算；后台任务额外建议 **¥20／日**，是 ¥100 内的子上限，不另加总额。不扣学员次数，缺预算暂停可恢复；尚未纳入首版的转写不因此获实施授权 |
| 周期与提醒 | Asia/Shanghai 自然日／月；平台预算到 **80%**提醒管理员，到 100% 或余额不足预占时阻止新增。已有预占任务可收尾；管理员可暂停新 AI 任务，课程、交易和社区继续可用 |

上述金额未获支出授权。启用前验证四家具体模型和搜索服务能否在限额内完成代表性请求；不合格则调整允许模型或提交预算变更，不悄悄提高限额。

成本机制：调用前按完整输入、最大输出、最多两次搜索和查询 embedding 估算并加 **20% 缓冲**，原子预占次数、账号与平台预算；获得实际用量后结算并释放多占。已消费＋未结算预占均占额度，后台任务遵循同样机制。失联、断流或缺失 usage 保留成本预占，**24 小时**仍未知转人工核对，不能记零或因跨日／跨月直接释放；未决成本在新周期继续扣减可用预算，核对后归属原调用周期并消除重复占用。

用户次数和平台实际成本分开；取消／失败不能抹除费用。价目、币种、有效期及汇率采用版本化配置，缺价、过期或无法保守估算时暂停对应模型／服务。估算和供应商账单分别展示；实际超预占照实记账并阻止继续超额调用，不截断数字，也不把内部准入控制承诺成供应商账单绝不超出的保证。
