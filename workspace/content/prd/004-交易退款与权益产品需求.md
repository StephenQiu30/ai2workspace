## 1. 摘要

让中国大陆用户使用人民币购买单门课程，由平台统一收款；让本人能够查询订单和申请退款，运营人员按简单、可解释的规则处理。首版把真实支付、内容可用与购买权益关联，重复或未知结果不能造成重复授予或错误撤权。

## 3. 背景

用户明确第一版需要付费课，采用人民币单课购买、平台收款，保留免费课程与试看；普通下架不取消已购学习，人工退款成功后撤销相应权益。后续接受普通窗口、全额原路退款、异常恢复和运营时限推荐作为 MVP 基线。来源见[交易需求](../requirement/004-交易退款与权益需求记录.md#2-原始材料与来源)。

当前没有选定支付渠道和商户，没有业务实现、真实收款退款或支付故障数据。本次仅迁移既有产品规则，不把商业退款政策表述为统一法定结论。

## 4. 目标与成功标准

一名已验证学员能购买一门课程并在服务端确认支付后获得权益，异常可查询恢复；退款成功只撤销对应购买，回购和其他合法购买不受旧通知影响。按 AC-04／AC-15 和总 PRD 的 AC-11／AC-12 验证。退款处理目标按下文已采纳时限执行，不虚构收入、转化率、拒付率或固定到账日期。

## 5. 目标用户与细分

| 用户 | 工作与问题 | 首版边界 |
| --- | --- | --- |
| 已验证学员／购买者 | 确认价格、完成购买、查看结果、提出退款 | 只访问本人订单与申请；使用人民币购买单课 |
| 退款运营管理员 | 核验实付、审批、提交与跟进异常 | 人工判断与渠道事实区分；审核通过不等于退款成功 |
| 课程运营管理员 | 协调在售、可交付和永久停止供课 | 内容状态由课程域维护；停止交付须联动权益与退款 |

## 7. 产品方案

### 7.1 主要流程与交互

| 路径 | 交互与状态 |
| --- | --- |
| 购买 | 已验证用户查看课程与服务端价格 → 确认订单及政策 → 支付 → 查询服务端结果；前端返回页不能直接开通权益 |
| 支付确认 | 校验渠道支付事实 → 记录实付 → 授予对应课程权益；重复和乱序通知幂等，超时未知查询恢复 |
| 访问交付 | 课程可交付且购买权益生效后形成首次实际可用时刻；未交付不因已支付或未点击播放提前计算退款窗口 |
| 普通退款 | 本人提交申请 → 人工审核 → 通过后提交原渠道 → 显示处理结果；待审核可撤回，提交后不能承诺取消 |
| 异常退款 | 未知先查原单，失败／关闭后按规则人工重试；持续异常进入人工跟进，不新起退款掩盖未知结果 |
| 退款与回购 | 渠道确认成功后撤对应购买；新订单回购与旧退款隔离，多扣款退款保留合法购买 |

首次实际可用取自有效购买与课程交付历史的交集，不以首次播放、退款申请时的当前状态或单纯支付时间替代；后续故障不重置已形成的起点。缺少可验证交付事实时转入核验，不以查询失败断言从未交付。

### 退款规则

| 项目 | MVP 基线规则 |
| --- | --- |
| 普通窗口 | 课程学习权益首次实际可用起 **7×24 小时内**，可申请整单全额原路退款。起点是服务端确认已支付且课程可访问的时刻，不是首次点击播放；按申请提交时间判断，截止时刻提交也受理 |
| 人工核验 | 核验本人订单、实付与已退款事实；窗口内不因已观看、完成课时或使用 AI 拒绝，不扣观看费或 AI 费。以宽松规则换取首版简单流程，承认已消费后退款的经营成本 |
| 金额与时限 | 只退实际支付金额，不做部分退款、手续费或平台余额替代。**2 个工作日内**给出审核结论，通过后 **1 个工作日内**提交渠道；这是已采纳的运营处理目标。到账按渠道状态展示，不承诺固定到账日 |
| 窗口外及特殊情况 | 质量不符、无法交付、重复扣款及依法应退情形保留人工入口，不因超窗自动拒绝。因内容问题永久停止交付或平台无法继续供课，主动通知并整单全退，不按观看量折算；临时故障走修复和人工支持，不自动触发全部退款 |
| 权益与取消 | 待审核可撤回；批准进入提交阶段后不承诺可取消。申请、处理中、失败及结果未知均不因退款流程提前撤权；仅渠道确认成功后撤对应购买权益。内容必须撤回时可独立停止交付并处理退款，不能假称退款完成 |
| 重复与回购 | 有效权益存在时阻止再购。重复扣款退多余支付，保留合法购买；退款后回购是新订单，旧退款迟到通知不得撤销新购买权益 |
| 异常恢复 | 受理不等于成功；超时先查询原退款单，不另起一笔。明确失败／关闭后才允许人工重试，累计退款不得超过实付；异常持续 **1 个工作日**进入人工跟进并更新用户状态 |

保留购买时的政策版本；后续收紧不追溯影响旧订单。七天是已采纳的产品商业政策，不将在线课程一律判定为法定七天退或不退；质量与未交付责任不能被普通窗口排除。法定责任和支付渠道依据见[交易退款与权益设计](../design/004-交易退款与权益设计.md)。

### 7.3 技术约束、失败与跨领域关联

交易域保有价格、订单、实付、退款与权益事实；课程域保有可售和可交付事实。订单固定金额与政策快照，不接受前端价格作为收款依据；接口、状态机和幂等方案见[交易设计](../design/004-交易退款与权益设计.md)。首版先完成一个正式支付渠道的闭环，不因设计抽象承诺多渠道上线。

| 边界／依赖 | 对方责任与本域责任 | 联合验收贡献 |
| --- | --- | --- |
| [账号](./002-账号与访问控制产品需求.md) | 提供当前已验证主体；本域校验本人订单和退款运营权限 | 不能读他人订单、代他人退款或前端伪造购买者 |
| [课程](./003-课程与媒体学习产品需求.md) | 提供可售、可交付及历史；本域提供当前购买权益 | 下架停止新售但保留已购；延迟交付不缩短普通退款窗口 |
| [社区通知](./005-社区互动与内容治理产品需求.md) | 消费交易结果生成站内通知；订单状态仍由本域维护 | 通知失败可补发，不能回滚已支付或已退款事实 |
| [知识](./006-知识库与检索产品需求.md)、[Agent](./007-通用Agent与联网问答产品需求.md) | 消费当前权益，执行资料／会话访问保护 | 退款撤权后新的检索、引用和播放不能沿用旧权限 |
| [AI 费用治理](./008-模型接入与AI费用治理产品需求.md) | 独立控制 AI 使用与成本；不改变课程实付和退款金额 | 买课不代表 AI 无限使用，普通退款不扣 AI 消费费 |
| 支付及退款未知 | 查询原渠道记录；显示处理中或异常待跟进，不假称成功 | 重复渠道事件不重复开通；不同真实支付多扣款单独处理 |
| 访问校验异常 | 无可靠权益事实时不能默认放行；查询失败也不删除支付事实 | 内容和权益恢复后按真实状态继续，不靠重下单修复 |

FR-11／FR-12、AC-11／AC-12 共同正文仍在[总 PRD](./001-学习社区与通用Agent产品需求.md)。本域贡献是订单归属、实时权益、幂等确认与未知结果恢复，不另立共享规则。

## 8. 版本范围与发布

首版包含单课一次性购买、订单查询、免费／试看衔接、人工全额退款与权益撤销。会员订阅、课程套餐、优惠促销、讲师自动分账、平台钱包及部分退款未纳入已确认 MVP；不按观看量或 AI 消费拆退款金额。

[交易实施计划](../plan/005-交易退款与权益实施计划.md)拆分前端订单／结果／售后与后端支付确认／退款／权益任务；依赖账号、课程交付历史及商户渠道，联动社区通知与知识访问。发布前须通过 AC-04／AC-15、涉及本域的 AC-11／AC-12、真实支付退款与重复／乱序／未知恢复、回购隔离及运营时限演练。当前全部业务和真实渠道验收未开始；文档及计划不构成业务实施或发布授权。
