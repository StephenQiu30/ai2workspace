## 1. 系统范围

首个可验证的纵向流程使用一个自有 IP、一集建议 30–60 秒的动态漫、一次关联二创和一个自营商品。制作团队从设定和剧本开始，得到有版本可核对的成片。观众从正式作品进入观看、制作学习、讨论或二创。买家从同一作品确认权益并获得约定内容。各专题的具体功能和质量要求分别维护。

仓库当前具备 Next.js 业务前端、五个 Go 服务和独立知识库。账号、媒体、讨论、知识／Agent、订单权益各有可复用机制，需按具体接口和实际证据核对。作品生产、版本交接及相关商品属于新规格。此阶段记录设计和验收方法。

## 3. 跨域契约与状态

| 交接 | 传递与校验 | 失败处理 |
| --- | --- | --- |
| 设定与素材 → 检索／制作 | 来源或素材 ID、版本、工作区和用途；在消费和读取时核对权威状态 | 撤回先改变源状态，旧索引及历史访问按当前授权处理 |
| 制作 → Agent／媒体任务 → 制作 | 作品与镜头 ID、输入版本、运行／步骤标识及候选产物引用；人确认采纳后才更新制作版本 | 重复返回同一运行；失败和迟到结果保留供处理，正式版本按授权确认 |
| 审片成片 → 正式发布 | 交接冻结的审片版本、可用媒体与用途记录，形成正式快照 | 条件不足时保留现行完整快照；依据权利处理撤回 |
| 正式发布 → 商品 → 付费访问 | 商品锁定版本、金额和权益；核验渠道付款后建立本单权益；访问时核对当前可交付状态 | 支付成功但未可用时保留原订单，补偿开权或进入售后。已退款只处理该笔购买 |
| 作品 → 讨论／二创 | 讨论绑定作品 ID，投稿绑定原作和素材版本；发布再校验开放范围 | 原作或素材撤回时暂停新增使用，并保留授权可读的审阅记录 |

各业务域通过服务接口交换版本和权限结果。对外契约沿用 Go DTO 与 Swaggo 生成流程。异常采用可诊断的状态和关联标识，告知用户可以重试、继续编辑还是联系处理。字段、错误、幂等与一致性细节由详细设计维护。

## 4. 工程兼容、发布与恢复

- **D-01 制作域边界与技术重设计。** 技术选型已确认将后端整体收拢为 **Go 模块化单体（按域分 Schema）+ Node/TS 独立 Worker（Remotion / Vercel AI SDK / Yjs CRDT）**，并引入 Temporal、Milvus、腾讯云 COS（短链验证）、Redis/SSE、独立 AI 网关与 K8s 可观测栈，制作域以独立模块与 Schema 纳入单体，详见[技术选型与架构重设计](./019-原创IP技术选型与架构重设计.md)。实施前保留既有 5 服务现状记录，按计划分阶段迁移。
- **D-02 现行入口兼容。** 实施前列出涉及的路由、API 与数据消费者。新作品入口以可独立验证的方式引入，变更公开首页前先验证原有社区、课程和账户入口仍可达。迁移与回退行为写入后续计划。
- **D-03 发布与恢复。** 首版发布前确认素材授权、试点账号、外部服务、额度与商户条件。准备数据库及素材恢复、正式版本回退，以及暂停新任务、新支付和受影响内容的处理方式。恢复时保留已产生的订单和费用事实。

方案依赖的生成和渲染服务、素材保留期限、预期负载、性能指标与恢复时限待评审。按代表性样片和试点请求记录处理、排队、发布至可用、付款至交付等时间，获得基线后确定目标与监控阈值。
