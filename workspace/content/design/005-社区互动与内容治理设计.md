## 1. 目标、范围与非目标

本域解决学员发起讨论、获得回复、表达反馈和举报内容的闭环。首版包含独立帖子、课程讨论、评论及单层回复、赞踩、收藏、站内通知和管理员处置。关注、私信、群聊、推荐算法与星级评价不进入本轮实施范围。

独立帖子和课程讨论复用内容能力，以 `scope` 区分，不为点赞、通知或举报单独建微服务。课程讨论的访问必须通过课程域检查，不能只判断是否登录或是否曾经付款。具体公开展示、收藏目标和保留期限仍是 PRD Q16 的待决项，下文给出可评审方案。

## 3. 交互、流程与状态

| 流程 | 正常行为 | 失败、空态与恢复 |
| --- | --- | --- |
| 发布／编辑 | 已验证用户选择讨论范围并提交；服务端生成作者身份；更新携带预期版本 | 校验失败保留输入；版本冲突提示重新载入；无课程权时拒绝提交 |
| 评论／回复 | 评论关联帖子；回复只指向一级评论，保留被回复者展示信息 | 已删除／隐藏的父内容不接受新回复；不形成任意深度回复树 |
| 赞踩／收藏 | `like`、`dislike`、`none` 单一状态；重复提交相同状态不累计 | 乐观界面失败时回退并提示；失效目标不允许新增反馈 |
| 删除／隐藏 | 作者删除与管理员隐藏分别记录；列表、详情、引用入口同步按权威状态过滤 | 建议以占位保留已有回复的上下文；不回显已隐藏正文，恢复须由授权管理操作完成 |
| 举报／处置 | 用户提交目标与理由，管理员核对后记录处理结论 | 重复提交可返回已有处理中事项；处置失败不得显示已完成 |
| 通知 | 回复、购买结果及处置等事件进入本人收件箱，点击时重新检查目标权限 | 目标已隐藏／无权显示不可访问；通知失败不回滚支付或内容操作 |

帖子建议采用 `published → author_deleted / hidden`，编辑增加版本；首版不建设社区内容发布工作流。举报为 `open → resolved / dismissed`。删除、隐藏、账号停用分别处理，不能依靠异步计数刷新来阻断内容读取。是否允许作者撤销删除及保留期限在实施前确定。

界面沿用 shadcn/ui Radix；[需求 009](../requirement/009-学屿品牌与界面需求记录.md) UI-S-05–07 已确认独立公开摘要／登录后正文与评论、Tiptap 正文及精简评论、按时间排序与分页。具体分页大小及输入限制仍需落实，不增加热度算法。页面与组件方案见[设计 009](./009-学屿首版页面与交互设计.md)和[设计 010](./010-学屿品牌与界面设计规范.md)；加载、空、提交中、无权、失败和键盘状态仍需实际验收。

## 4. 接口与数据契约

以下是计划实现的操作契约，不是可调用接口或手工 Swagger。公共前缀为 `/api/community/v1`，作者和操作者只从可信会话取得。

| HTTP / operationId | 关键输入 → 输出 | 权限、错误与一致性 |
| --- | --- | --- |
| `POST /posts` / `createPost` | `{scope, courseId?, title, publicSummary, body, requestId}` → `{postId, version, state}` | 邮箱已验证；公开摘要独立维护，不从受保护正文自动截取；课程讨论必须 `scope=course` 且课程可访问；相同作者与 requestId 幂等 |
| `PATCH /posts/{postId}` / `updatePost` | `{expectedVersion, title, publicSummary, body}` → 更新版本 | 作者或有明确处置权限者；摘要与正文分开校验，冲突 `409 VERSION_CONFLICT`，跨作者拒绝 |
| `DELETE /posts/{postId}` / `deletePost` | `{expectedVersion}` → `{state, version}` | 逻辑删除业务内容，保留审计；重复删除返回一致结果 |
| `GET /posts`、`GET /posts/{postId}` / `listPosts`、`getPost` | 范围、游标或 ID → 当前可访问视图、下一游标 | 游客仅标题、作者昵称、分类、时间与独立公开摘要，响应不含正文、评论、正文图片或富文本原始数据；登录后才读正文／评论，课程范围另核权限；隐藏内容不得由直接 ID 绕过 |
| `POST /posts/{postId}/comments` / `createComment` | `{body, parentCommentId?, requestId}` → `{commentId, version}` | 父评论必须属于同帖且为一级；更新／删除评论使用 `updateComment`、`deleteComment`，规则同作者内容 |
| `PUT /reactions` / `setReaction` | `{targetType, targetId, value}` → `{value, likes, dislikes}` | 目标限定帖子与回复，互斥赞踩且可取消；唯一键 `(userId, targetType, targetId)`，事务更新状态与汇总 |
| `PUT /favorites` / `setFavorite` | `{targetType, targetId, saved}` → `{saved}` | 仅帖子可收藏与取消，其他目标拒绝；不扩展课程或回复收藏 |
| `POST /reports` / `reportContent` | `{targetType, targetId, reason, requestId}` → `{reportId, state}` | 仅对可见目标；同一用户同目标处理中举报去重 |
| `POST /management/reports/{reportId}/decision` / `moderateContent` | `{expectedVersion, action, reason}` → `{state, version}` | 管理员；处置与审计同事务，不允许通过通用 action 操作其他域数据 |
| `GET /notifications`、`PUT /notifications/{id}/read` / `listNotifications`、`markNotificationRead` | 游标／已读状态 → 本人通知及状态 | 用户不能提供他人收件人身份；无权目标只保留通用状态提示 |
| `POST /internal/community/v1/notifications` / `appendNotification` | `{eventId, recipientId, type, target}` → `{notificationId, accepted}` | 仅可信服务；`(eventId, recipientId)` 持久去重；事件类型和最小摘要白名单 |

公共错误至少区分未登录、未验证、禁止访问、目标不可访问、版本冲突及暂不可用。不存在与无权对象的响应需避免泄露受保护内容；不能把权限校验失败当作空列表继续写入。

数据由 community 独占：Post、Comment、Reaction、Favorite、Report、ModerationAction、Notification 及投递去重记录。Post 的 `publicSummary` 与受保护 `body` 分开维护；公开搜索、SEO／GEO 和游客页面只使用公开字段，爬虫身份不额外获得正文。目标类型采用已确认白名单；Tiptap 正文及精简评论在服务端检查允许结构，不接受任意脚本或 HTML。正文长度、图片输入限制、评论精简集合、附件及保留期限实施前落实；已确认图片不等于允许任意文件上传。

### 跨域权限与事件

课程讨论调用 `learningCheckCourseAccess`：`POST /internal/learning/v1/course-access/check`，携带可信用户和 `{userId, courseId, purpose:"discussion"}`，得到 `{allowed, reason, accessVersion, contentVersion}`。learning 负责综合内容状态与 commerce 权益；调用失败拒绝受保护读写。普通下架保留已购访问，特殊撤回另行处理。

生产者在自己的业务事务中保存待投递事件，之后有限重试 `appendNotification`；接收成功才标记已投递。community 故障时事件留存重试，不撤销已成功的购买。通知只存最小状态摘要，不复制付费文稿或完整回复正文；点击目标重新鉴权。内容隐藏立即影响读接口，计数和通知摘要允许异步修正但不得再次暴露正文。

## 5. 设计决定与取舍

本页 D-ID 归属 `DES-ai2workspace-community`，不与总设计的同号决定混用。

| ID | 选择及依据 | 影响 |
| --- | --- | --- |
| D-01 | 一套讨论内容能力区分独立与课程范围，保留课程访问检查 | 避免两套编辑／互动逻辑；独立社区可以先交付，课程讨论等待权益契约 |
| D-02 | 用户目标唯一态，而非追加点赞事件直接累加 | 重复请求、切换和取消均有确定结果；计数可核对重建 |
| D-03 | 站内通知归社区，跨域用持久投递与去重 | 不建设消息平台；通知故障不影响付款事实 |
| D-04 | 逻辑删除与管理员隐藏分别留痕，读取检查权威状态 | 方便申诉与恢复；保存期限仍需产品和运营评审 |

## 6. 实施与恢复边界

先交付独立帖子和互动，再接课程讨论权限，随后通知与治理闭环。账号鉴权是全部写入的前置；课程讨论依赖学习／权益服务。跨域端到端验收使用隔离账号和内容，避免根测试的并行执行互相污染。

业务状态和待投递事件由数据库备份恢复；计数可从唯一态重算，通知按 eventId 重放去重。恢复隐藏内容必须显式授权，不能因重放旧事件复活已删除正文。当前没有业务数据迁移，也没有上线或提交授权。
