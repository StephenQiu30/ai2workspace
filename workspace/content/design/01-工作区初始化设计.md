# 工作区初始化设计

依据：[FR-WS-001](../requirement/01-工作区初始化需求.md)。以下技术取舍为本次初始化方案，业务范围等待后续确认。

## 1. 摘要

提供可本机运行的 Ai2sd 知识库与一致的配置、协作和文档规范，支持后续从需求进入设计和实施。

## 2. 参与者

项目使用者与维护者；具体成员、职责分配与排期待确认。

## 3. 背景

初始化前 Ai2sd 是空目录，无 Git 仓库或业务文件。参考本机 Glowloom/glowloom-server/workspace 当前代码、README、根规范与模板；部分历史部署正文已不对应当前实现，不直接复制。

## 4. 目标

形成可阅读、搜索、编写和检查的最小知识工作区。复用参考项目已使用的工具与主题配置。

## 5. 使用场景

维护者启动工作区后，从知识库索引阅读分类内容，检索中英文关键字，查看原始 Markdown；接到业务需求后按来源链编写文档。

## 6. 价值

让后续研发有固定的知识入口、配置依据、视觉基线和验收方法，减少规范重复与来源丢失。

## 7. 方案

工作区独立位于 workspace，使用 Next.js App Router、Fumadocs MDX 和官方 Base UI；shadcn Base Nova / Neutral 与参考项目保持一致。源码与正文分离，Markdown 通过官方内容源加载。

文档路径映射为稳定 ID，目录侧栏由 meta.json 组织；相对链接通过官方 createRelativeLink 解析。原始 Markdown 和 LLM 路由复用官方能力。搜索使用同源 /api/search 的内置多语言实现。Mermaid 只在页面需要时加载。

根规范负责协作、配置、视觉和任务状态；知识正文按九类组织。默认入口 127.0.0.1:1140，免登录本机阅读。当前没有远端仓库，不生成虚假的 GitHub 编辑链接或品牌资源。

```mermaid
flowchart LR
  requirement[原始需求] --> design[技术设计]
  design --> prd[产品验收]
  prd --> plan[实施与证据]
```

## 8. 实施与验收

覆盖导航、稳定 ID、相对链接、中文与英文搜索、Markdown/LLM 路由、未知页、主题及移动端阅读。检查使用 lint、类型、格式、正式构建和 Playwright；执行记录见 [Plan](../plan/01-工作区初始化计划.md)，状态见根 BACKLOG.md。
