## 1. 当前实现与首版目标

Agent 是 Go 单体的业务模块，已确认包含 Evals、RAG、多 Agent 编排及父子 Agent。客服问答、课程助教和制作任务复用模型接入、授权检索与用量治理。首版以制作任务验证父子编排。工作台发起任务，父 Agent 执行固定流程，按需等待人工确认，再把指定版本交给下一个子 Agent。

当前代码已有管理员配置与发布、会话、多轮问答、联网搜索、授权检索、取消和预算治理。问答从 `/api/assistant` 的 HTTP 处理器进入，回答计算跟随请求上下文。它按内存索引检查幂等，之后才预占预算并写入运行。数据库的问答幂等索引当前是普通索引，部分运行或结果写入错误会被忽略。因此制作任务需要以数据库确认的运行状态作为执行依据，并在费用调用之前完成唯一性检查与预占。当前代码的持久化能力和制作任务的恢复设计分别验收。[问答执行](https://github.com/StephenQiu30/ai2workspace/blob/349260dea4f1f4784147cd96cb46aa91af5bd7f6/backend/internal/agent/application/agent/agent.go#L532) · [数据库结构](https://github.com/StephenQiu30/ai2workspace/blob/349260dea4f1f4784147cd96cb46aa91af5bd7f6/backend/schema.sql#L606)

## 2. 代码组织

[项目总体设计中的 Agent 架构图](../../01-项目总体设计.md#6-agentrag-与-evals)说明父子 Agent、RAG 和 Evals 的协作关系。

| 位置 | 当前职责 | 首版增量 |
| --- | --- | --- |
| `agent/module.go` | 装配问答、知识、费用、模型及路由 | 注入制作权限、版本读取、结果交接能力。接入由应用生命周期管理的模块内任务执行 |
| `agent/domain/agent/` | Agent 配置、会话、运行、消息 | 定义 Agent 版本、父子运行关系、输入引用、状态和步骤结果 |
| `agent/application/agent/` | 配置管理、会话和问答用例 | 制作父 Agent 在 `production_run.go` 选择子 Agent、处理状态与汇总结果。编剧、分镜、校验实现定义各自的输入、提示、工具和结构化输出 |
| `agent/application/knowledge/` | 索引、检索和引用复核 | 作为 Agent 共用的 RAG 能力，接入制作工作区、IP、来源版本与用途。由制作域提供当前源状态和授权 |
| `agent/application/evals/` | 现有问答、知识和费用回归测试分布在 `backend/tests/agent/` | 按需新增评测用例与结果汇总。首批固定数据集放在 `backend/tests/agent/testdata/` |
| `agent/application/usage/` | 预算预占、结算及人工核对 | 制作使用明确的费用用途，关联 run、step、attempt，复用账本和平台限额 |
| `agent/application/provider/`、`agent/adapter/provider/` | 模型与搜索接口及供应商调用 | 在已有模型接口中满足制作调用所需的超时、结果和用量信息。供应商凭据、协议与错误归适配层 |
| `agent/adapter/postgres/`、`agent/adapter/http/` | 本模块持久化与 HTTP 请求适配 | 按对应任务增量落位，新增 API 通过现有 Swagger 生成链路覆盖 |

三类制作任务由 Go 用例选择工具、模型和输出校验。问答每次联网的规则保留在问答用例，制作步骤按其用途读取授权项目资料。在出现独立用例或明确复用时继续拆包。

## 3. 父子 Agent、RAG 与任务恢复

父 Agent 是一个可版本化的编排入口。它接收创作者目标、作品和初始输入版本，选定本流程允许的子 Agent，负责顺序、等待条件、执行上限、汇总及取消。首版由 Go 执行固定步骤。子 Agent 是独立的可运行能力，各自具备版本、模型配置、工具权限、输入和输出契约。

下图展示剧本、校验、人工采纳和分镜的执行顺序。RAG 按步骤提供授权资料。Evals 的隔离回放使用同一编排路径，并用样本轨迹核对调度、引用、候选和费用。

![学屿 Agent 执行流程图，展示父 Agent 调度、人工采纳和评测回放](/design/agent/execution.svg)

[全屏查看执行流程图](/design/agent/execution.html) · [执行流程图源文件](/design/agent/execution.json)

制作运行使用一层父子关系。根运行保存流程版本、创作者、工作区和执行上限。子运行保存 `parent_run_id`、流程步骤键、子 Agent 版本、实际输入版本及结果引用。父运行与步骤键约束同一步骤只创建一个子运行，明确重试在该子运行追加尝试。父 Agent 只下发任务所需的资料和权限范围，子 Agent 依范围检索和调用工具，将结构化结果及引用返回给父 Agent。人工确认由制作域完成，父 Agent 依据确认结果读取冻结的版本再调度分镜。拒绝采纳时结束该流程并保留候选及运行记录。

RAG 的输入包含当前用户、工作区、IP 或作品、用途和可读来源范围。检索服务按版本和有效授权过滤，再对发送给模型的片段复核权限。引用记录来源 ID、版本和定位，候选查看或采纳时重新检查该来源。子 Agent 收到的证据需覆盖任务所需范围，资料不足时输出依据不足。检索范围、撤回和索引策略沿用[制作 RAG 设计](./013-制作知识库与RAG设计.md)。

| 阶段 | 应用行为 |
| --- | --- |
| 登记 | 接收流程类型、作品、目标、初始输入版本和幂等键。先验证当前工作区权限，再按 `workspace_id + actor_id + request_id` 在 PostgreSQL 原子登记父运行。请求指纹包含流程类型、作品、目标与输入版本。同键同内容返回原运行，同键不同内容返回冲突 |
| 准入 | 固定实际执行的父子 Agent 配置与模型价格版本。执行前复核权限和目标版本。同一事务内记录尝试、核验父运行费用上限并完成实际调用的预算预占。父运行按尝试汇总费用，实际调用按尝试入账 |
| 执行 | 编剧使用创作简报和获准设定。分镜读取人工确认的剧本版本。校验返回冲突位置、证据或依据不足。步骤构建自己的结构化输入输出，检索片段和模型生成内容只作为业务数据 |
| 交接 | Agent 保存经过校验的不可变结果和证据引用。由制作域的 `RecordCandidate` 登记结果引用，重复交接返回原候选。制作人员调用 `ApplyCandidate` 时，制作域再次检查当前授权、工作区、目标和预期版本，再生成对应草稿版本 |
| 恢复 | HTTP 返回父运行标识，页面读取父子状态、人工等待点与结果。重启后恢复排队任务及可安全续跑的步骤，读取已完成子运行的结果并复核引用权限。取消父运行时停止派发并向在途子运行传递取消，保留各尝试的结算与核对记录 |

子运行中的步骤记录检索、生成和结果交接等阶段，尝试记录一次可独立核对的供应商调用。制作运行记录以工作区和作品为作用域，问答会话沿用现有问答记录。

任务由 Agent 模块在单体进程中执行，PostgreSQL 保存状态与结果。认领、取消和完成使用数据库上的条件更新，避免多个执行路径同时推进同一任务。HTTP 断开后可凭运行 ID 继续查看。状态查询是刷新和重连的依据，SSE 按工作台的实时进度需求补接。需要跨进程协调、持久定时或长时间等待时，再按[架构设计](../../01-项目总体设计.md#4-数据与任务执行)评估编排设施。

## 4. 数据、权限与费用边界

- `agent` 是运行、执行结果、来源版本和费用关联的权威。模型输出只保存一份，制作域候选记录引用该结果。 `creation` 持有工作区成员角色、作品、素材授权、人工采纳记录和正式版本。
- `identity` 提供当前账号与会话。 `creation` 提供工作区、作品和版本判断。调用经各自的根包或注入的 Go 接口协作，由 `app` 装配。结果查看和采纳根据当前身份、来源用途与撤回状态重新判断。授权失效时只提供允许读取的运行摘要。
- 源资料和历史上下文按当前任务用途读取。模型获得经过选择的上下文和该任务需要的能力。写入候选由应用校验，采纳、发布和交易由对应业务域的用户操作控制。
- 运行结果和费用状态分别记录。结果迟到且输入已换版时，保留旧运行记录与已知费用，候选标为过期。供应商可能已收到请求但结果或用量未知时，冻结对应核对额度并交由费用模块确认。只有确认原尝试可重试时，才允许新尝试重新准入。
- 恢复时依据持久状态区分尚未取得发送权、已经取得发送权但缺少供应商结果、结果已保存但尚未交接。第一种可继续，第二种先核对供应商结果和用量，第三种使用同一结果标识重新交接候选引用。取消后仍核对已发生的用量。日志与进度只记安全的摘要、阶段、耗时、关联标识和错误类别。

数据库结构在 `backend/schema.sql` 单点维护。制作接口、列表及事件名称由实施时的 Go DTO、路由及注解定义。

## 5. Evals 与首版验收

Evals 使用固定样本重跑用例，并用同一套规则比较编排、提示、模型或 RAG 配置变更前后的结果。首批由代码断言和人工抽样组成。日常回归使用模拟模型与隔离数据，真实模型质量在单独授权的样本和预算下验证。线上候选结构校验仍由子 Agent 用例执行。

| 评测项 | 固定样本与判断 |
| --- | --- |
| 编排 | 检查父子运行关系、步骤顺序、人工确认点、取消传播、重复提交和重试。覆盖校验失败后保留编剧结果，以及恢复时复用已完成的子运行 |
| RAG | 以标注的来源与版本验证前 K 条召回和引用定位。覆盖无证据、旧版本、跨工作区和撤回后读取。越权片段进入检索上下文或结果视图均判失败 |
| 候选质量 | 检查输出结构、冲突定位和证据一致性，制作人员用同一评分说明抽样复核。校验结果能区分已发现的冲突与依据不足 |
| 费用与稳定性 | 用模拟场景检查仅一次外部尝试、预算拒绝、取消和未知费用核对。记录各节点耗时和用量 |

评测记录关联样本版本、评分规则版本、父子 Agent 与模型配置版本、RAG 来源和索引版本，保留逐样本结果供对比。指标阈值根据试点样本评审。运行结果与评测结果分别归档，指标可以追到原始用例。

| 决定 | 首版选择 |
| --- | --- |
| D-01 用例边界 | 通用问答与制作任务分别组织，复用现有知识、模型和费用能力 |
| D-02 任务模型 | 每次制作操作登记父运行。采用一层父子 Agent 和固定流程，步骤明确输入版本与人工确认点 |
| D-03 恢复 | PostgreSQL 持久状态，单体内执行。外部调用的未知结果进入账务核对 |
| D-04 结果与版本 | Agent 输出为不可变结果，制作候选引用它，制作域确认后生成可编辑版本 |
| D-05 Evals | 将可重复的回归用例、RAG 检查和人工质量样本纳入首版验收 |

建议首个验证切片采用「父 Agent → 编剧子 Agent → 校验子 Agent → 人工采纳」。让两个子 Agent 使用同一套授权 RAG，并用固定样本复验整条轨迹。跑通后，将确认过的剧本版本接给分镜。代表性素材、供应商、额度、超时和允许传给模型的数据范围继续按制作 PRD 评审。实施与结果记录沿用[制作 Agent 实施计划](../plan/013-制作Agent与任务编排实施计划.md)。

| 产品验收 | 验证方法 |
| --- | --- |
| 制作 AC-01、AC-11 | 运行三类固定任务。校验无证据样本能给出依据不足。用包含越权指令的候选验证只有有效人工采纳可写入制作草稿 |
| 制作 AC-02、AC-12 | 并发提交相同请求，确认一个运行及一次外部尝试。模拟调用前、调用结果未知、结果已保存但交接失败的重启场景 |
| 制作 AC-03、AC-13 | 用可控样本模拟不足额、已用、取消与未知费用。通过运行定位输入、步骤、引用与账务关联，验证日志和结果视图权限 |
| 问答 AC-09、AC-10、AC-16 | 回归角色与配置、每答搜索、来源复核、失败与取消。真实联网和计费分别在获授权环境验收 |

## 6. Archify 调研与采用范围

Archify 是开源的 Agent Skill。它将人工或 Agent 编写的结构化图源生成可独立打开的交互式 HTML，支持架构图、流程图、时序图和树图。其交付流程包含图源校验、渲染与产物检查。Code Analysis 从代码快照提取依赖和分层问题。官方 MCO 案例将组件与连线指向固定提交中的源码，并明确区分所有权关系和函数调用。 [Archify 官网](https://archify.si/) · [官方 Skill](https://github.com/tt-a1i/archify/blob/main/archify/SKILL.md) · [MCO 案例](https://archify.si/cases/mco-runtime)

学屿可借用其展示与校验方法。先用一张结构图解释父子分工，再用一次固定评测样本的时序展示调度、RAG 引用和费用关联。架构图的已实现节点对应 Git 版本和源码，运行耗时、引用及用量由实际运行或评测记录提供。Archify 作为设计评审和演示工具，运行、权限、检索和评测结果继续由学屿后端负责。 两张图使用 Archify v3.3.2 生成，源文件随知识库维护。[Archify 运行时许可](/design/agent/archify-license.txt)
