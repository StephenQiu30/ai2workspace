## 1. 目标、范围与非目标

本域负责把明确授权的业务资料变成可追溯、可撤回、受访问控制的知识来源。知识库不是 `workspace/content/` 项目文档的默认镜像，也不把用户帖子自动当作可信课程资料。

首版交付知识库管理、来源登记、解析与切片、检索数据生成、版本发布、引用定位与撤回。管理员和受邀讲师只可管理自己获授权的资源；学员使用已发布内容，不能自建知识库或发布 Agent。视频转写、OCR、网页爬取、个人知识库和知识市场均不因 RAG 入库而自动纳入。

支持的独立资料格式仍需决定。MVP 建议先选 UTF-8 文本／Markdown 和课程域已授权图文来源，拒绝未知格式；PDF、附件解析与字幕应在有明确需求及预算后单独增加。格式、大小、正文长度和原始资料保留期限是入库任务开始前的局部门禁，不伪称已获产品确认。

## 2. 职责与目录

| 模块 | 数据和职责 | 计划路径 |
| --- | --- | --- |
| `knowledge` 来源管理 | KnowledgeBase、Source、SourceVersion；维护者和可见范围引用 | `backend/services/assistant/internal/knowledge/source.go` |
| `knowledge` 检索 | Chunk、IndexVersion、来源定位；带当前权限的检索 | `backend/services/assistant/internal/knowledge/retrieval.go` |
| 域内入库任务 | 状态、租约、幂等、失败恢复；调用费用模块后才可使用付费解析或 embedding | `backend/services/assistant/internal/knowledge/index_job.go` |
| 前端管理 | 知识库列表／详情、来源导入、版本与失败重试、发布／撤回 | `frontend/src/app/manage/knowledge/page.tsx`、`frontend/src/app/manage/knowledge/[knowledge_base_id]/page.tsx`、`frontend/src/features/knowledge/` |
| 独立测试 | 来源权限、版本、重复任务、撤回与引用 | `backend/services/assistant/tests/knowledge_test.go`、`frontend/tests/knowledge.test.ts`、`tests/e2e/knowledge.spec.ts` |

所有业务路径均为计划创建。与 Agent、提供商和费用模块共用 assistant 的 Go module、数据库和部署边界；跨域课程内容只通过 learning API 获取。Go DTO／Swaggo 注释在所属业务包维护，`internal/apidocs/` 和前端 `services/generated/` 由官方链路生成。

课程原文的权威仍是 learning。assistant 只拥有授权来源引用、处理版本及派生切片，不提供编辑课程原文的第二个入口。独立上传的知识资料由 assistant 管理对象存储引用。向量和全文索引是可重建数据，不能作为购买权限的权威。

## 3. 入库、检索与交互状态

| 阶段 | 行为与状态 | 失败和恢复 |
| --- | --- | --- |
| 登记来源 | 验证维护权、课程来源权限及输入格式，生成 `registered` 版本 | 不支持格式、来源越权直接拒绝；不预先将文件当作可检索资料 |
| 处理 | `registered → processing → ready / failed`；记录解析、切片和索引阶段 | 暂时故障有限重试；文件错误需修改源；缺预算为 `paused_budget`，不能先调用后补记费用 |
| 发布 | 有权限者显式选择 ready 版本，事务切换 `publishedVersion` | 新版失败保留上一有效版本；旧任务只能写自己的源版本 |
| 检索 | 从 Agent 允许集合中取用户可访问的已发布有效资料，再召回和核对命中 | 资料不足返回无证据；权限服务或必需索引不可用是失败，不冒充零结果 |
| 撤回 | 先改权威状态为 `withdrawn`，阻断新检索与引用，再清理派生索引 | 清理失败留任务重试，不因旧索引仍存在而重新放行 |

管理页区分“上传／登记成功”“处理完成”和“已发布可用”；显示来源版本、处理阶段、可恢复失败和预算暂停。没有来源时说明支持范围，不能暗示上传视频就能检索视频内容。页面不能让讲师扩大自己没有的课程授权。

同一 `(sourceId, sourceVersion, parserVersion, embeddingModelVersion)` 只有一个有效处理结果；重复提交返回原任务。切换 embedding 模型使用新 IndexVersion 并重建，不能将不同维度或语义空间的向量混合查询。新索引质量验证通过后切换，旧索引只在仍有权且源版本仍有效时允许恢复使用。

## 4. 接口与数据契约

公共前缀 `/api/assistant/v1`。以下为设计契约，真实 Go DTO 是未来生成代码的唯一来源。

| HTTP / operationId | 关键输入 → 输出 | 权限、错误与一致性 |
| --- | --- | --- |
| `POST /knowledge-bases` / `createKnowledgeBase` | `{name, description, visibility}` → `{knowledgeBaseId, version}` | 管理员／受邀讲师；可见范围不能超过本人可授权范围 |
| `GET /knowledge-bases`、`GET /knowledge-bases/{id}` / `listKnowledgeBases`、`getKnowledgeBase` | 游标或 ID → 授权资源与来源状态 | 管理视图不向学员开放原始资料；无权对象不泄漏存在性或正文 |
| `PATCH /knowledge-bases/{id}` / `updateKnowledgeBase` | `{expectedVersion, name, description, visibility}` → 新版本 | 修改权限后立即影响后续读取；扩大范围重新校验所有来源 |
| `POST /knowledge-bases/{id}/sources` / `registerKnowledgeSource` | `{kind, sourceRef, sourceVersion, requestId}` → `{sourceId, version, state}` | `kind` 只接受已支持类型；课程引用由 learning 确认，不能接受用户随意提供的内网 URL |
| `POST /knowledge-sources/{id}/index-jobs` / `startIndexJob` | `{sourceVersion, requestId}` → `{jobId, state}` | 维护者；去重处理、后台预算准入；缺预算返回暂停状态 |
| `GET /index-jobs/{id}` / `getIndexJob` | jobId → `{stage, state, retryable, errorCode}` | 本资源维护者；不暴露上游凭据、原始堆栈或其他人的内容 |
| `POST /knowledge-sources/{id}/publish` / `publishKnowledgeSource` | `{expectedVersion, readyVersion}` → `{publishedVersion}` | ready 且源仍有效；版本冲突拒绝，切换在本地事务完成 |
| `POST /knowledge-sources/{id}/withdraw` / `withdrawKnowledgeSource` | `{expectedVersion, reason}` → `{state, version}` | 同步撤回授权状态；派生清理异步，重复请求幂等 |
| `GET /citations/{citationId}` / `getCitation` | citationId → `{sourceTitle, sourceVersion, locator, excerpt}` | 当前用户有权且来源有效；旧链接不绕过退款、源撤回或账号停用 |

后端内部入口 `knowledge.Retrieve(ctx, RetrievalInput) (RetrievalResult, error)` 由 Agent 调用，不公开任意学员指定的检索知识库列表。`RetrievalInput` 包含可信 `userId`、已发布 `agentVersion`、允许的 `knowledgeBaseIds`、问题与截止时间；输出 `evidence[]`、`accessChecks[]` 和检索状态。每条 evidence 包含 `sourceId / sourceVersion / contentVersion / chunkId / locator / text`，引用标识由服务端生成。

Source 至少保存 `knowledgeBaseId`、来源种类、权威资源 ID、维护者、访问规则引用、源版本、状态及内容哈希；Chunk 保存来源位置及处理版本；Citation 保存实际使用的版本和范围。日志只保留必要 ID、状态与摘要，受保护原文不进入普通日志。保留期限需结合实际提供商外发政策决定。

### 课程授权与检索边界

| 调用场景与接口 | 授权、输入与输出 |
| --- | --- |
| 维护者登记课程来源：`learningGetKnowledgeSource`；`GET /internal/learning/v1/courses/{courseId}/knowledge-sources?version=...` | 使用可信服务身份和授权 actor，得到 `sourceId / sourceVersion / contentVersion`、访问引用和已授权图文内容。该维护权不授予所有 Agent 学员使用权。 |
| 学员使用课程来源：`learningCheckCourseAccess`；`POST /internal/learning/v1/course-access/check` | `{userId, courseId, purpose:"knowledge"}` → `{allowed, reason, accessVersion, contentVersion}`。learning 综合课程状态和 commerce 权益；assistant 不绕过它直接以购买记录授权。 |
3. 实际检索范围为 **已发布 Agent 绑定集合 ∩ 用户当前可访问范围 ∩ 已发布有效来源**。召回前过滤、命中后核对，生成前以及向用户交付前再检查；权限服务失败拒绝受保护回答。
4. 撤回／退款后先阻断新的检索、引用和历史答案读取；异步索引清理只节省存储。普通下架保持合法已购权益和相应知识访问，不与内容违规撤回混用。

不共享付费问答结果缓存；索引缓存绑定源版本并受当前权限约束。已发送到用户或上游的文本不能远程收回，设计保障后续访问和调用不继续扩大暴露，不能宣称物理删除已经收到的字节。

## 5. 方案取舍与依据

本页 D-ID 归属 `DES-ai2workspace-knowledge`。

| ID | 选择及理由 | 影响 |
| --- | --- | --- |
| D-01 | assistant 内部知识模块与域内持久任务，不另建向量微服务 | 先验证 PostgreSQL 生态检索能力，达到实测瓶颈再引入独立引擎 |
| D-02 | 显式来源和发布版本，避免课程自动全量镜像 | 有明确授权、可回溯引用；首次内容整理需要维护者操作 |
| D-03 | 权威状态先撤回，索引后台清理 | 避免异步索引延迟成为权限漏洞；增加实时权限依赖 |
| D-04 | 所有可能付费入库操作先调用统一预算准入 | 后台不会绕过平台上限；预算不足可暂停恢复 |

沿用前轮 2026-11-17 已核验的 [Azure AI Search 安全筛选说明](https://learn.microsoft.com/en-us/azure/search/search-security-trimming-for-azure-search)，支持“检索结果需按可信身份过滤”的设计依据；不表示本项目选用 Azure，本轮未重新核验或接入供应商。模型处理数据的范围与保留条件仍需实际提供商评审。

## 6. 实施与恢复

先完成来源及权限契约、统一费用准入，再运行付费 embedding／解析；然后交付版本入库、检索、引用与撤回。可以先使用受控文本样本验证纯本地流程，但不能把固定样本检索通过声称为真实模型或生产质量验收。

数据库恢复后以源状态为准重建索引；任务租约过期可恢复，但不能重复发布或重复调用结果未知的付费任务。若上游调用已发生而结果丢失，按费用未知处理，先查询／核对而非无条件重新支付执行。源撤回优先于恢复旧任务。
