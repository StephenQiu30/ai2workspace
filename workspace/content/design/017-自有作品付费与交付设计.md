## 页面与业务责任

作品详情展示售价、购买内容、访问方式、交付状态和适用退款约定。用户在 **确认购买** 检查商品，付费后到 **订单详情** 查看渠道结果、访问作品或提交退款。运营在 **商品与订单** 管理在售状态、价格、支付异常、交付和退款。

commerce 域保有订单、支付、权益、退款与对账记录。制作域发布功能提供登记的作品版本、可交付状态和实际媒体访问。方案参考已存在的交易服务结构，首版拟增加自有作品商品与按作品开权，真实支付仍需商户条件和渠道核验。[交易与权益设计](./004-交易退款与权益设计.md) · [作品发布与制作学习](../design/015-作品发布与制作学习设计.md)

## 付款与交付

| 步骤 | 数据来源与恢复 |
| --- | --- |
| 下单 | 商品关联明确的作品发布版本及售卖权益。订单锁定价格、币种、内容、退款政策版本和预期交付 |
| 支付 | 服务端校验真实渠道事件或查询结果，匹配订单、金额和币种。回跳只显示查询结果。重复事件和延迟失败记录不能覆盖已确认的支付或重复开权 |
| 开权 | 已确认实付后幂等地建立该订单的作品权益。授权同步暂时失败则保留支付成功与待开权状态，可按原订单恢复 |
| 交付 | 内容已发布、可交付且权益生效后记录首次实际可用。购买者可通过受控链接播放约定的具体内容。故障保留原订单、通知运营并可恢复 |
| 退款与对账 | 人工审核或查询按适用政策办理。渠道确认退款后只撤该笔购买产生的权益，独立的其他合法权益仍按各自事实生效。支付、授权、交付和退款进入人工核对视图 |

## 版本与售后

D-01 订单与权益指向购买时承诺的已发布内容。价格调整形成新快照。仅停售且可继续交付时，已购者保有访问。作品因素材权限或内容撤回而无法继续交付时，关闭不允许的访问、停止新售，并让运营从订单进入交付异常与售后处理。

D-02 支付、交付与退款分别记录。付款未知时查原单；渠道和站内记录不一致时登记异常。退款待确认显示处理中，只有渠道确认才能登记退款完成。现有单课售后规则可作参考，作品商品的政策需单独确认。

首个自有数字商品建议为一集作品加制作拆解。委托结算、外部 IP 团队订阅与二创分账分别待验证。真实收款条件由商户、支付渠道、权益承诺和退款约定确认后落实。

## 非功能设计与验证

| 需求 | 设计措施与验证方法 | PRD 验收 |
| --- | --- | --- |
| NFR-01 | 对支付确认核对签名和渠道状态；启用最小权限及敏感字段掩蔽，前端只消费订单状态 | AC-11 |
| NFR-02 | 支付、开权、交付和退款记录各自幂等标识；一致性检查报告不匹配项，异常按原单恢复 | AC-12 |
| NFR-03 | 保存关联键、状态时间和渠道差异；运维视图展示待核对、待开权和待交付。对有权限的操作员记录复核动作 | AC-13 |

## 验证映射

| 需求／验收 | 验证方法 |
| --- | --- |
| R-01／AC-01 | 核对商品展示、订单快照及本人查询，价格变化不改历史订单 |
| R-02／AC-02、AC-03 | 模拟重复及乱序通知、未知结果、未付款与交付失败，验证恢复同一订单与实际受控播放 |
| R-03／AC-04 | 模拟退款成功、重复通知、回购、停售和撤回，核对权益和人工对账记录 |
| 商业试点／AC-05 | 在获得相应授权的环境记录一笔实际小额付款、首次交付、渠道与站内对账，以及适用退款证据 |

渠道、售价、币种、退款规则与真实验收环境待确认，执行结果待记录。
