### 候选服务与数据权威

本轮设计采用五个业务服务作为可评审方案；尚无业务实现或供应商验收，不按评论、点赞、视频、向量等每项能力分别建服务。

| 候选服务 | 自己拥有的数据和职责 | API 协作与边界 | 产品条目 |
| --- | --- | --- | --- |
| `identity` 身份 | 账号、邮箱验证／找回、密码凭据、会话、账号状态、角色与讲师邀请 | 提供可信用户身份和状态；各域仍检查资源归属，不把角色等同全局数据权限 | FR-01 |
| `learning` 课程学习 | 课程、章节／课时、课程归属、内容与发布版本、媒体元数据和处理任务、学习记录 | 向交易提供课程可售状态；向社区提供可见性；向 Agent 提供显式授权的内容和版本；播放前询问权益 | FR-02、FR-03、FR-05 |
| `commerce` 交易权益 | 人民币售价、订单及购买快照、支付尝试、渠道事件、退款单、权益 | 独占支付和权益事实；不将价格在课程服务中再维护一份；课程目录可读取展示用价格投影，下单重新核验 | FR-04、FR-11 |
| `community` 社区 | 帖子、课程讨论、评论回复、赞踩、收藏、举报、处置记录、站内通知 | 课程讨论关联课程 ID，访问依据 learning／commerce；首版通知作为模块，后续关注私信也先留在本域 | FR-06、FR-07 |
| `assistant` 知识与 Agent | 知识库、资料来源与版本、切片和索引、Agent 配置及发布版本、会话、引用、调用和用量记录 | 通过授权 API 获取知识；依当前用户权限检索并调用搜索／模型；不拥有课程、订单或账号权威 | FR-08–FR-10、FR-12–FR-14 |

前端经既有 Traefik 路由访问服务，服务间沿用 HTTP＋JSON。基本依赖为：各域验证身份；learning 查询 commerce 权益；commerce 在售前查询 learning 可售状态；community 查询关联内容可见性；assistant 获取 learning 内容及 commerce 权益。避免同一请求互相回调：下单查询课程状态不再反向检查购买权益，播放鉴权不触发下单。

管理台是 `frontend/` 中受权限控制的入口，操作各域 API，不建立读写所有业务表的“后台服务”。通知只接收最小事件摘要，邮件验证属于 identity；站内通知失败不应回滚已成功的付款。

### 存储、后台任务与外部能力

- 延续 PostgreSQL 选型，每个业务服务独立逻辑数据库与账号；开发或小规模部署可共用实例，禁止跨库联表或直接读写其他域数据。
- 视频和资料存对象存储，数据库保存归属、状态和引用。课程媒体归 learning，独立上传的业务知识资料归 assistant；相同原始课程资料使用授权引用或派生副本，不形成第二个可编辑内容权威。
- 转码、知识解析／索引由所属域的 Worker 处理。首版候选为持久化任务表、租约、有限重试、失败重试入口；事件需可靠投递时用同事务待投递记录及接收去重。具体队列产品暂不选定。
- 检索索引为可重建的派生数据。优先验证现有数据库生态能否满足文本与向量检索，达到质量、规模或隔离瓶颈后再评估独立引擎；本阶段不固定向量库或 embedding 模型。
- 外部依赖包含媒体处理／分发、邮件、支付、模型和搜索。通过各自业务域适配所需提供商的官方 API，不建立泛化插件市场、万能工具运行器或通用编排平台。
- Redis、独立消息平台、搜索集群、服务网格和 Kubernetes 均不是首期默认依赖；只有实际测量或交付约束支持时再增加。

### 目录与依赖设计

已有 `frontend/`、`backend/services/ai2workspace/` 技术基线及独立 `workspace/` 保持职责。后续经实施指令进入对应任务时，按根 `PROJECT.md` 在 `backend/services/<服务名>/` 建立各自 Go module、`cmd/server/`、`internal/<业务包>/` 和本服务 `tests/`；既有健康检查基线如何归并由实施计划决定，不保留无职责的额外生产服务。

前端按页面和真实功能创建 `src/app/` 路由与 `src/features/` 模块，使用 `components/ui/` 的既有组件及 `services/generated/` 调用。前端测试归 `frontend/tests/`，跨服务契约与端到端验证归根 `tests/`，Go 测试归各服务 `tests/` 且留在本 module 内满足 internal 可见性。本文不预建目录。

## 3. 跨域主流程与授权

### 3.1 课程、视频与学习

课程草稿 → 新媒体版本上传与处理 → 显式发布 → 查询实时权益 → 获取受控播放凭证 → 保存本人进度。上传完成、媒体 ready、课程 published 是不同事实。[课程设计](./003-课程与媒体学习设计.md)定义全部状态与续传、版本、播放器边界。

### 3.2 下单、支付、退款与权益

下单先查 learning 的可售／可交付事实，再以 commerce 权威价格创建快照；服务端支付确认与授予权益在 commerce 本地事务中完成。退款成功仅撤销关联购买授予；通知和索引清理不参与支付事务。[交易设计](./004-交易退款与权益设计.md)定义退款窗口、状态与恢复机制。

### 3.3 社区与通知

独立讨论可在账号能力具备后交付；课程讨论增加课程可见性和实时权益依赖。通知只消费有去重键的最小业务事件，失败不会撤销付款或退款。具体目标类型、交互和管理语义见[社区设计](./005-社区互动与内容治理设计.md)。

### 3.4 知识入库与通用 Agent

知识来源授权 → 成本准入（若产生费用）→ 解析索引与发布 → Agent 绑定 → 用户权限交集 → 本次问答预算准入 → 实际搜索与 RAG → 生成并复核 → 引用输出。知识版本和索引由[知识设计](./006-知识库与检索设计.md)负责；回答状态由[Agent 设计](./007-通用Agent与联网问答设计.md)负责。视频转写、个人知识库和自主工具循环未自动纳入。

### 3.5 多模型提供商与强制联网

至少支持 DeepSeek、OpenRouter、火山、OpenAI，四家各自验证实际模型、参数与用量。搜索是应用流程的必要步骤，不依赖模型自动选工具；搜索失败不调用生成模型，模型不自动重试或切换提供商。模型适配、允许列表和价格依据见[模型与费用设计](./008-模型接入与AI费用治理设计.md)。

### 3.6 权限、隐私与撤回

实际知识范围为 **Agent 绑定范围 ∩ 当前用户有权范围 ∩ 已发布有效资料**。身份由 identity 验证，各域再验证资源归属和当前可用状态。不能信任浏览器提供的用户 Header，不能用讲师角色赋予全站资源访问权。

普通停售保留已购访问；退款撤销某笔授予、账号停用、内容必须撤回各有独立语义。受保护内容在检索前、命中后、生成前及返回／历史读取时复核当前权限；索引与缓存不是授权权威。引用、通知摘要和历史会话不能成为旁路。授权依赖不可用时拒绝新的受保护访问。

搜索只外发安全问题／关键词；不发送私有课文、身份信息、订单或会话全文，用户粘贴的付费原文同样需要检查。安全查询不能形成时停止问答。模型接收受保护证据时，使用已经核验数据政策的配置提供商，禁止静默外发给备用提供商。

外部网页和知识文本只作为数据，不能改变权限或授予新工具；网页获取限制公网目标和重定向，阻断本地／内网访问。已交付字节无法远程收回；播放凭证残留窗口由媒体选型实测，不能把新请求拒绝声称为已缓冲内容瞬间消失。

### 3.7 AI 配额与费用控制

费用准入在首个付费索引、搜索、embedding 或模型调用之前，不能作为问答完成后的附加统计。已消费与未结算预占共同占用预算；失败释放成功次数而不抹除真实费用，未知费用跨周期保留风险占用。课程购买不增加 AI 次数，AI 预算耗尽不影响学习、交易和社区。机制见[费用设计](./008-模型接入与AI费用治理设计.md)，数值只引用 PRD。

## 4. 共同接口与一致性要求

各领域设计列出计划 HTTP operationId、输入输出与错误。实际实现以本服务 Go DTO、标签和 Swaggo 注释为源，经官方工具生成 Swagger 和 Umi 客户端；设计表不是另一份手工 OpenAPI。公共路径前缀为 `/api/<service>/v1/`，内部契约使用 `/internal/<service>/v1/` 且不经公网路由开放；内部网络同样校验服务身份与调用用途。

- 共享错误至少区分未认证、无权、资源不存在、版本冲突、输入不合法、限流、依赖暂不可用；返回可展示错误码与 requestId，不暴露供应商凭据。领域特有原因保留在对应契约。
- 幂等键按可信主体与操作范围隔离；相同键及相同输入回放原结果，同键不同输入报冲突。任务、支付／退款尝试、外部调用各自保留关联标识，不能以一个 requestId 混淆多次计费。
- 请求中的用户 ID 只能由可信认证结果导出；服务间调用必须验证调用方及用途，身份断言、HTTP 凭证和 SSR 转发的具体方案见账号设计。公共接口与内部接口分别验证，无跨服务读表或源码导入。
- 条件更新与唯一约束控制并发；订单、支付事实与权益在 commerce 同域提交。跨域通知用本地持久化待投递记录和接收去重，失败可恢复；不新增通用分布式事务平台。
- 服务调用设置截止时间；写操作仅在业务幂等成立时恢复重试。选定支付渠道的查询能力、媒体处理回调、未知模型费用分别验收，不能把网络超时推断成业务失败。

| D-05 | 用索引／缓存状态授权，或查询当前业务权限 | 业务权威授权，索引仅派生；跨 Agent 和历史会话都校验 | FR-08、FR-11；增加查询依赖，需要超时和拒绝策略 |
| D-06 | 立即引入中间件，或先用域内持久化后台任务 | 优先简单且可恢复的任务机制，有吞吐证据后再引入消息／检索集群 | FR-03、FR-08、FR-12；需验证租约、去重和失败恢复 |
| D-07 | 按观看比例扣费，或整单退款 | 已采纳普通窗口内全额原路退，异常交付人工处理；不建设消费比例结算 | R-14、FR-04、AC-15；需接受已消费后退款成本 |
| D-08 | 广泛格式兼容，或有限媒体输入 | 单一输入规格、最多两档输出，复用存储续传与后台处理 | R-15、FR-03、AC-14；部分原片需讲师重新导出 |
| D-09 | 搜索故障仍生成，或失败停止 | 必联网前提下有限重试后停止作答；成功零结果另行处理 | R-16、FR-10、AC-16；AI 可用性依赖搜索服务 |
| D-10 | 仅统计成功次数，或同时约束实际成本 | 账号次数＋预算预占及用量核对，覆盖失败与入库 | R-17、FR-14、AC-17；简单域内记录，不做钱包平台 |
| D-11 | 一个巨型规格，或按需求领域拆分 | 按 S-09 拆七个领域设计和子计划，总览只维护共享边界与依赖；同一服务可承载多个领域模块 | R-18；保留所有既有短 ID 的文档归属 |

PRD 的准入上限不是吞吐或可用性承诺。后续测量上传处理、播放、支付权益生效、问答耗时和实际成本；没有测试证据时不填写通过。

## 6. 分阶段实施与恢复

顺序与可并行分支以[实施总计划](../plan/002-学习社区与通用Agent实施计划.md)为准：身份与可信契约 → 供课／交易／媒体学习；社区可并行，模型与费用先行，再接知识与 Agent；最后联合验收。外部依赖按领域设置门禁，不因某个渠道未选定而冻结所有其他工作。

现无业务数据迁移。本轮不创建工程和部署资源。后续服务上线需独立数据库账号、配置与备份恢复；索引可重建但不得恢复已撤回权限。退款／支付事实不能用代码回滚逆转；回滚与对账分开处理。旧健康检查基线保留到替代链路通过，生产最终不保留无职责的第六个服务。
