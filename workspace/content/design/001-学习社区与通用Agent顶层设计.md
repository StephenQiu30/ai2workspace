## 1. 背景、目标与约束

当前只有知识库网站和前后端健康检查基线，未实现业务认证、存储、课程、交易或 AI。顶层目标是建立清晰的数据权威和服务职责，使付费学习、社区与通用 Agent 能形成完整闭环。

用户已要求 Go 微服务，因此本方案保留独立服务边界；MVP 约束用于减少服务数量、基础设施和首版能力，不据此擅自改回单体。课程助手和平台客服只是通用 Agent 的配置实例。首期 Agent 是 RAG＋联网搜索＋回答，不提供退款、发布内容、修改课程等写入工具。

本轮只写文档，不创建下述服务、数据库、接口、任务或部署资源。PRD 的未决商业规则不会被技术方案隐式决定。

## 2. 方案概览与职责

### 候选服务与数据权威

建议五个业务服务；名称与数量属于待评审方案，不按评论、点赞、视频、向量等每项能力分别建服务。

| 候选服务 | 自己拥有的数据和职责 | API 协作与边界 | 产品条目 |
| --- | --- | --- | --- |
| `identity` 身份 | 账号、邮箱验证／找回、密码凭据、会话、账号状态、角色与讲师邀请 | 提供可信用户身份和状态；各域仍检查资源归属，不把角色等同全局数据权限 | FR-01 |
| `learning` 课程学习 | 课程、章节／课时、课程归属、内容与发布版本、媒体元数据和处理任务、学习记录 | 向交易提供课程可售状态；向社区提供可见性；向 Agent 提供显式授权的内容和版本；播放前询问权益 | FR-02、FR-03、FR-05 |
| `commerce` 交易权益 | 人民币售价、订单及购买快照、支付尝试、渠道事件、退款单、权益 | 独占支付和权益事实；不将价格在课程服务中再维护一份；课程目录可读取展示用价格投影，下单重新核验 | FR-04、FR-11 |
| `community` 社区 | 帖子、课程讨论、评论回复、赞踩、收藏、举报、处置记录、站内通知 | 课程讨论关联课程 ID，访问依据 learning／commerce；首版通知作为模块，后续关注私信也先留在本域 | FR-06、FR-07 |
| `assistant` 知识与 Agent | 知识库、资料来源与版本、切片和索引、Agent 配置及发布版本、会话、引用、调用和用量记录 | 通过授权 API 获取知识；依当前用户权限检索并调用搜索／模型；不拥有课程、订单或账号权威 | FR-08–FR-10、FR-12–FR-14 |

前端经既有 Traefik 路由访问服务，服务间沿用 HTTP＋JSON。基本依赖为：各域验证身份；learning 查询 commerce 权益；commerce 在售前查询 learning 可售状态；community 查询关联内容可见性；assistant 获取 learning 内容及 commerce 权益。避免同一请求互相回调：下单查询课程状态不再反向检查购买权益，播放鉴权不触发下单。

管理台是 `frontend/` 中受权限控制的入口，操作各域 API，不建立读写所有业务表的“后台服务”。通知只接收最小事件摘要，邮件验证属于 identity；站内通知失败不应回滚已成功的付款。

### 存储、后台任务与外部能力

- 延续 PostgreSQL 选型，每个业务服务独立逻辑数据库与账号；开发或小规模部署可共用实例，禁止跨库联表或直接读写其他域数据。
- 视频和资料存对象存储，数据库保存归属、状态和引用。课程媒体归 learning，独立上传的业务知识资料归 assistant；相同原始课程资料使用授权引用或派生副本，不形成第二个可编辑内容权威。
- 转码、知识解析／索引由所属域的 Worker 处理。首版候选为持久化任务表、租约、有限重试、失败重试入口；事件需可靠投递时用同事务待投递记录及接收去重。具体队列产品暂不选定。
- 检索索引为可重建的派生数据。优先验证现有数据库生态能否满足文本与向量检索，达到质量、规模或隔离瓶颈后再评估独立引擎；本阶段不固定向量库或 embedding 模型。
- 外部依赖包含媒体处理／分发、邮件、支付、模型和搜索。通过各自业务域适配所需提供商的官方 API，不建立泛化插件市场、万能工具运行器或通用编排平台。
- Redis、独立消息平台、搜索集群、服务网格和 Kubernetes 均不是首期默认依赖；只有实际测量或交付约束支持时再增加。

### 目录与依赖设计

已有 `frontend/`、`backend/services/ai2workspace/` 技术基线及独立 `workspace/` 保持职责。后续若确认五域方案，才按根 `PROJECT.md` 在 `backend/services/<服务名>/` 建立各自 Go module、`cmd/server/`、`internal/<业务包>/` 和本服务 `tests/`；既有健康检查基线如何归并由实施计划决定，不保留无职责的额外生产服务。

前端按页面和真实功能创建 `src/app/` 路由与 `src/features/` 模块，使用 `components/ui/` 的既有组件及 `services/generated/` 调用。前端测试归 `frontend/tests/`，跨服务契约与端到端验证归根 `tests/`，Go 测试归各服务 `tests/` 且留在本 module 内满足 internal 可见性。本文不预建目录。

## 3. 关键流程与状态

### 3.1 课程、视频与学习

课程建议区分草稿、待审核、已发布、已下架；媒体独立区分待上传、上传中、处理中、可用、失败、已撤回。媒体成功不等于课程已发布，课程发布前核对必要素材可用。替换素材建立新版本，旧处理任务不得覆盖新版本；业务发布显式切换可见版本。

上传由服务授权后直达媒体存储或提供商，限定账号、资源、类型和大小；服务端验证最终对象与归属后创建处理任务。视频字节不经 Go 应用进程中转。候选播放方案为转码后的点播流和 CDN，播放器获取受控播放凭证，不暴露长期公开原片地址。清单、片段、密钥和附件都要纳入访问方案，不能只保护课程页面。

上传／处理中展示进度和状态；失败保留可重试入口；不可用素材不能假装可播放。媒体平台官方接口也将处理状态与可播放状态分开，参见 [Cloudflare Stream API](https://developers.cloudflare.com/api/resources/stream/)；这里只引用模式，不选择该供应商。

learning 记录用户、课时、内容版本、最近位置及进度状态；是否计算完课另定。保存采用幂等更新并限制写入频率；多设备冲突、完成阈值及内容变更后的进度策略属于 PRD Q14，不能简单以最大的播放时间代替真实完成。

#### 上传会话与处理

采用 [PRD 的视频上传规格](../prd/001-学习社区与通用Agent产品需求.md#视频上传规格)，不在代码以外维护第二套上限。learning 拥有上传会话、源文件和处理版本；会话关联操作者、课程、课时、预期文件信息与过期时间。创建、续传、完成均重新检查资源归属，短期直传凭据不能扩大到整个存储空间。

复用选定存储的官方分片／续传 API：同一会话以分片标识恢复，完成请求具备幂等键，服务端以实际对象信息和解析结果为准。不要仅检查扩展名、浏览器 MIME 或用户声明的时长。零字节、超限、损坏或不支持的编码进入明确失败状态，不启动无限格式猜测。临时上传凭据可以短于会话有效期，续传通过服务端重新授权刷新。

后台校验、转码、可播放检查形成有版本任务；相同源版本的重复通知不能重复创建产物。先写临时输出，确认全部必要产物可用后再标记 ready；旧任务只能更新自身版本，发布切换在 learning 内完成。网络故障可恢复上传，源文件不合格需重新导出，处理失败由有权限的供给者显式重试，不能无限自动重转码。

取消／过期会话主动终止未完成分片，周期清理补偿遗漏；完成竞态先核对实际对象状态，不能清理已发布媒体。原片和有效播放产物不适用“过期分片”清理策略。对象存储未完成上传通常仍占空间，参考 [S3 multipart 生命周期](https://docs.aws.amazon.com/AmazonS3/latest/userguide/mpuoverview.html)；该例证不指定 AWS。HLS 编码和播放兼容性参考 [Apple HLS 规范](https://developer.apple.com/streaming/hls-authoring-specification-for-apple-devices.html)，本产品的大小、时长和格式门槛来自 PRD 推荐，不是该规范要求。

### 3.2 下单、支付、退款与权益

1. commerce 查询当前可售课程及价格，创建带课程标题、金额和币种快照的订单；同一请求的重复提交使用幂等键处理。
2. 创建支付尝试并返回渠道支付入口；浏览器跳回只触发状态查询，不授予权益。
3. 服务端验证支付通知的签名、商户、订单、金额、币种与状态，在本地事务中记录支付事实、去重事件并授予唯一权益。终态不得被旧通知倒退。
4. 处理超时或通知缺失时主动查询渠道并对账；“结果未知”保持处理中，不以超时直接重付。通知下游通过可重试投递，权益权威不依赖通知到达。
5. 退款申请、审批、渠道退款和退款完成是不同状态；使用独立退款单与幂等键。退款终态和权益变更在 commerce 内一致提交，已确认人工审核及成功后撤权，具体条件与特殊情况已有 PRD 第 7.5 节推荐，待商业政策确认。

订单、支付尝试、退款与权益分别建模，避免一个状态字段同时代表四件事。金额使用人民币最小货币单位的整数或精确金额类型，禁止浮点运算；不提供任意删除已付款订单的 CRUD。渠道重复通知和乱序是需处理的实际情况，参考 [Stripe Webhooks](https://docs.stripe.com/webhooks#handle-duplicate-events)；退款不是同步必成，参考 [Stripe Refunds](https://docs.stripe.com/refunds)。这些来源用于证明异常类型，不代表选择 Stripe 或给出退款政策。

#### 退款实现与依据

产品窗口、金额与运营目标以 [PRD 退款规则](../prd/001-学习社区与通用Agent产品需求.md#退款规则)为准。commerce 保存订单政策版本、学习权益首次实际可用时刻、申请时间、审核人与理由、实际支付金额和渠道退款记录。普通窗口从“已支付且课程可交付”的服务端事实开始，不依赖客户端首次播放上报，也不计算观看百分比。未交付时窗口未起算，仍可走未交付退款入口。

业务退款申请和渠道尝试分开：申请为待审核、已拒绝、已撤回或已批准；批准后渠道尝试为待提交、处理中、成功、异常／关闭。审核与撤回并发以条件状态更新保证只发生一种结果。待提交失败仍是已批准申请，不能要求用户重新申请或误标成功。列表可显示组合状态，保留全部处理记录。

同一申请仅允许一个未终结的渠道退款尝试；请求超时先查询原渠道退款单，使用相同业务退款编号恢复。只有确认尝试失败／关闭后才由管理员创建关联的新尝试；成功、处理中和未知结果不能再发新的退款；渠道“异常”不等于已关闭或终态失败，不能据此新起退款。回调和主动查询走同一幂等处理，校验商户、订单、币种、金额及单号，乱序通知不能回退终态，累计退款不能超过已支付金额。支付渠道支持的退款期限不是商户责任自动结束的依据；原路退款不可用时转人工异常处理，不标成已完成。

权益授予引用具体购买记录：渠道成功后，在 commerce 事务中更新该笔退款并撤销该笔授予，再按其余有效授予判断课程访问。不能简单清空用户与课程的总权益。这样重复扣款退多余款、或旧退款通知到达时用户已经回购，都不会误撤其他合法购买。

人工队列包含待审、批准未提交、渠道异常及超出运营目标的事项；状态变化提供站内通知，邮件只作补充，不以通知送达决定退款成功。普通停售继续保留已购访问；因内容必须撤回而独立限制访问时同时启动通知与退款处理，不把内容撤回状态伪造为退款终态。

参考 [消费者权益保护法](https://www.samr.gov.cn/zt/ndzt/2019n/bjspjsqjxcjwljxyjsckpxc/zcfg/art/2023/art_5004b2b0f4154c76acfca499fe9c737a.html)及[实施条例](https://www.samr.gov.cn/zw/zfxxgk/fdzdgknr/bgt/art/2024/art_0aea188276a44f0baf940ab95ee00e0a.html)：数字内容例外有具体适用条件，售后承诺与未按约交付责任不能由本设计自行免除。本次推荐七天政策是商业选择，发布前须确认能履约，不宣称在线课程统一适用或不适用某一法定退货规则。[微信支付退款指引](https://pay.wechatpay.cn/doc/v3/merchant/4013071031)用于核验受理、查询与终态差异，不代表已选定该渠道。

### 3.3 社区与通知

帖子、课程讨论及评论／回复共享清晰的内容归属；每条回复引用所属讨论，首版单层回复已确认，具体交互见 PRD。赞踩使用每用户每目标唯一态，取消是恢复未表态；计数是可校正的汇总，不成为独立权限依据。作者编辑／删除和管理员隐藏／处置分别记录，避免把管理行为归到作者名下。

收藏需选择允许的目标类型并验证目标可见性。站内通知保存接收者和事件去重键，阅读状态只影响该用户。被隐藏内容不从详情、搜索、通知摘要或后续知识导入继续暴露；关联对象下架时显示可解释状态，不产生悬空操作。

### 3.4 知识入库与通用 Agent

**入库流程**：资料登记和授权 → 解析／清洗 → 按来源位置切片 → 生成检索数据 → 质量检查 → 发布可检索版本。资料记录知识库、源资源、版本、状态及权限依据；视频需要转写文本才能按内容检索，不能把“支持上传视频”写成“已能理解视频”。字幕／转写的供应方、费用和准确性另行验证。

**配置模型**：Agent 定义角色说明、允许的知识库集合、提供商／模型和回答要求；每次回答联网是固定流程，不提供关闭后正常作答的配置；发布形成稳定配置版本。课程 ID 只是某些实例的业务关联，可没有课程，也可关联多个允许的知识库，不把 `course_id` 设计为通用 Agent 的唯一入口。

**回答流程**：认证与 Agent 可用性 → 计算当前用户可访问的知识范围 → 检索和核验来源状态 → 每次回答实际发起联网搜索 → 合并证据并生成回答 → 返回正文、知识引用／网页链接及实际来源类型。首版用有限、可解释的检索与搜索流程，不做自主循环规划、多 Agent 编排或可视化流程编辑器。

即使业务知识足够，仍须为本次回答发起搜索；不能用旧搜索缓存或模型自称“已联网”代替实际调用。知识库检索与安全搜索在输入已确定时可并行，不要求所有用户都绑定课程。缺少课程专属依据时明确说明，不把网页答案冒充课程结论；无证据时承认不足，来源冲突时指出差异及时间。本轮推荐搜索未成功时明确失败并提示重试，不提供仅 RAG 的正常回答；成功零结果和服务失败分别处理，详见下节。课程学习不依赖 Agent 正常运行。

#### 搜索执行与失败

采用 [PRD 联网搜索失败策略](../prd/001-学习社区与通用Agent产品需求.md#联网搜索失败策略)。一次问答使用稳定请求 ID，每次外部尝试单独标识；前端重复提交或查询返回原状态，明确“重新生成”才建立新问答并重新准入。首版用用户问题做确定性过滤／安全改写，不增加一次隐藏的 LLM 查询改写或自主多轮搜索。

预占后执行授权 RAG 检索和真实搜索；只有搜索成功且所需知识检索未失败，才启动配置的生成模型。证据检索阶段使用整体截止时间，RAG、搜索、网页读取、重试和等待均受该边界约束；仅 PRD 指定的瞬时错误重试，非幂等计费搜索的重复尝试也记成本。每个调用记录状态、提供商请求 ID、查询摘要与获取时间；不要将付费原文或敏感搜索词写入普通运行日志。

结果至少区分成功有结果、成功零结果、调用失败、响应无效和安全阻断。零结果经过有效响应校验，不允许将解析失败、空响应体或限流页当成成功。网页获取只处理允许的公网地址并受同一检索阶段截止时间约束；取不到全文时只使用已取得证据。搜索失败不调用生成模型；知识检索错误也显式失败，不能用网页内容伪装课程依据。

流式生成前已完成所需检索；生成断流保持部分内容“未完成”，不可在后台重复发送模型请求再拼成假装一次完成的答案。生成使用 PRD 定义的总时限与流空闲时限；超时终结本地运行状态并释放槽位，成本预占继续保留。取消向搜索、检索与生成传播，但本地结束不代表上游已停止或不计费，需独立核对。请求终态、可见结果和费用状态分开：用户看到失败并不意味着平台调用成本为零。

### 3.5 多模型提供商与强制联网

首期接入范围至少为 DeepSeek、OpenRouter、火山、OpenAI；提供商名单是用户要求，具体模型、接口、地域和凭据仍需实施前确认。火山的具体模型服务入口按官方方舟文档核验，不能将平台品牌直接当成端点。

assistant 维护最小的提供商适配边界：将业务请求转换成实际上游输入，将流式／完整响应、错误和可取得的用量转换成稳定的内部结果。每个 Agent 指定提供商和模型；配置记录模型能力，不能假定四家都支持相同参数、结构化输出、工具、流式事件或 embedding。Embedding 和生成模型单独选型，改变 embedding 模型需要重建对应索引，不能混用旧向量。

联网由应用流程执行和核验，搜索提供方独立于生成模型选型。即使上游支持内置联网，也须证明本轮实际搜索过；只在提示词中要求联网或设置工具开关不足以满足“每次回答都联网”。检索与搜索结果按当前权限处理后传给所配置模型；Agent 不获得任意网络、业务写入或本机执行权限。

提供商不可用时明确失败，不能静默切到另一家外发受保护材料或重复计费。本轮推荐不自动重试生成模型、不跨提供商切换；费用上限和配额的候选默认值见第 3.7 节，仍待确认；流中断保留明确失败状态，不把部分答案标成完成。统一内部用量摘要，同时保留上游请求 ID、实际模型和原始用量证据；缺失用量记为未知，不能记为零。密钥只由服务端配置管理，不进入浏览器、文档、Agent 提示词或运行日志。

以下资料在 2026-11-17 核验，具体兼容性仍以实施时选用模型实测为准；本轮未使用凭据或调用真实模型。

| 提供商 | 官方依据与接入关注点 |
| --- | --- |
| DeepSeek | [官方 Web Tools](https://api-docs.deepseek.com/guides/web_tools/)：原生搜索存在工具选择约束，不能假定模型必定执行；保留流式事件、引用及用量差异 |
| OpenRouter | [官方 API Reference](https://openrouter.ai/docs/api_reference/overview)：聚合入口不是单一底层提供商，参数和流式 usage 有差异；记录可取得的实际模型／路由和用量，不把协议兼容当作能力相同 |
| 火山 | [方舟 Chat API](https://docs.volcengine.com/docs/ark/chat-api?lang=zh)：按实际区域、端点和模型核验参数、流式用量及工具兼容；内置搜索不能代替应用层必联网保证 |
| OpenAI | [官方 Web Search](https://developers.openai.com/api/docs/guides/tools-web-search)：区分支持的 API 与模型能力，验证实际搜索调用及引用；不用自动工具选择保证每答联网 |

### 3.6 权限、隐私与撤回

实际知识范围取 **Agent 绑定范围 ∩ 当前用户有权访问范围 ∩ 已发布有效资料**。资料维护者权限不能透传给学员；课程权益失效后，同一 Agent、另一个 Agent、历史会话和引用链接都不能绕过保护。

普通课程下架表示停止新售，不撤销已购用户的播放及相应课程知识访问；知识资料撤回、退款撤权和特殊下架分别处理，不能用同一个“下架”标志阻断所有已购访问。索引写入可异步，但知识删除／撤回／权限撤销先改变权威可用状态；检索前过滤、命中后再核验，生成和返回前核对状态，后台清理旧切片及缓存。授权不可用时受保护内容拒绝访问；索引不是权限权威。授权过滤还必须依赖可信身份，参考 [Azure AI Search 安全筛选](https://learn.microsoft.com/en-us/azure/search/search-security-trimming-for-azure-search)。

搜索请求发送通用问题或经处理的关键词，不将私有课文、订单、身份信息和会话全文拼到外部查询。付费内容出现在用户问题中时也要识别外发风险；无法形成安全查询时停止本次问答并解释，不通过跳过搜索输出正常答案。模型处理资料的范围、保留期限及供应商数据政策属于 Q17／Q18，不能用“内部知识库”暗示资料从不交给外部模型。

网页、课程材料和模型输出均是数据，不授予新权限；不因材料中有“忽略之前指令”而改变检索范围或启用工具。网址获取需限制协议、重定向和目标地址，不能访问本地或内网资源；模型只可使用检索与搜索白名单能力。参考 [OWASP Prompt Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html#agent-specific-defenses)。

新播放授权应检查实时权益。已签发的短期凭证或已缓冲片段无法承诺瞬间失效，因此评审时需确定可接受撤销窗口及提供商能力；已交付给用户的字节不能远程收回。历史答案读取按当前访问权限重校验或隐藏受限内容；缓存按用户权限和知识版本隔离，首版优先不共享付费问答缓存。

### 3.7 AI 配额与费用控制

产品额度及所有数值以 [PRD AI 费用控制](../prd/001-学习社区与通用Agent产品需求.md#ai-费用控制)为准。首版仅在 assistant 域增加问答记录、调用明细、额度周期和成本预占，不新增计费微服务、分布式钱包或按供应商建设独立平台。管理员选择经验证模型；学员不能提交任意模型名、推理预算或跳过配额。四家支持范围继续保留，具体模型未满足限额时标为不可用，不伪称接入验收完成。

**准入与预占**：先认证、权限和安全查询检查，再在同一事务中检查账号发起频率、运行槽位、成功次数占位及账号／平台日月预算。多个请求竞争最后额度必须只有符合条件者获准。预占覆盖完整输入的保守 token 估算、上游可计费最大输出／推理、最多搜索尝试、查询 embedding 和配置缓冲；加缓冲后的最终预占必须同时满足单次、账号与平台上限，不能在单次上限外再加一层缓冲。首版禁用额外原生联网／工具调用，避免独立搜索之外产生未纳入上界的工具费用。未能确定计费上界、价格或适用汇率则不发起调用。

**分项结算**：所有外部调用归入请求或入库任务，保存实际模型、提供商请求 ID、价格版本、原始币种、原始 usage、归一化成本与结果。获得可靠最终用量后，将预占转为实际成本，释放确实多占部分；未发出的调用可释放，但已发出又失联、缺少 usage 或取消不能按零结算。成功次数仅在完整结果持久化时消耗一次；失败／取消释放该次数占位，费用预占独立保留。断线后读取同一已完成结果不重复扣次数；明确重试为新请求。

**未知与跨周期**：未知费用进入待核对队列，依据提供商查询或账单结算；达到 PRD 的人工处理阈值后告警，不能仅因租约超时而抹除预占。请求按准入时的 Asia/Shanghai 周期归属；历史未决费用在新周期作为风险占用扣减可用额度，核对后更新原周期并释放风险占用，避免月末失联后通过重置绕过预算，也避免重复记成本。实际费用超过预占照实入账并阻止继续超额调用，不能为使账面达标丢弃差额。

**价格与后台任务**：维护模型输入、缓存命中／未命中、计费推理、搜索单价及适用附加费；未知缓存命中按更保守价格估算。价格和汇率有版本与有效期，未验证或过期拒绝新调用。入库解析、embedding、重建索引以及后续获授权的转写，和问答共用平台预算；后台任务同时占其子额度，按内容哈希和来源版本去重，可暂停恢复。价格变更不能改写历史记录。

**运营边界**：达到阈值提醒管理员，预算不足只拒绝新的 AI 付费任务；已预占任务按边界收尾，不中断课程播放／购买。控制台区分估算、已确认、待核对和供应商账单，配额修改留操作记录。模型不自动重试、不跨提供商回退；用户主动重试重新计入准入与上界。禁止在缺少账单时宣称预算绝对限制了供应商最终账单。

用量解析需按提供商单独验证：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)说明流中断可能缺少最终 usage，输出上限涉及推理 tokens；[OpenRouter 用量记录](https://openrouter.ai/docs/cookbook/administration/usage-accounting)支持提供商成本及异步核对；[DeepSeek Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)的用量与流式结构需按实际接口处理。引用仅支持计量边界，本轮不抄写价格、不读密钥、不发起付费调用；火山同样需以实际端点的 usage 和账单完成验收。

## 4. 接口、数据与一致性

下表描述业务契约，不是手工 Swagger 或数据库建表文件。

| 能力 / 数据 | 必要输入输出 | 权限与错误 | 一致性要求 |
| --- | --- | --- | --- |
| 账号与会话 | 邮箱、密码、验证／找回凭据；会话与角色 | 限制重复尝试；验证与找回令牌有有效期及单次用途；密码不明文存储或写日志 | 邮箱唯一性按确定的规范化规则；停用和退出可撤销会话 |
| 课程发布 | 课程 ID、预期内容版本、素材引用；发布状态 | 作者／管理员及对象归属；版本冲突、素材未就绪 | 单域事务维护版本切换，发布后可售状态可查询 |
| 媒体授权 | 课程／课时、用户、用途；上传或播放凭证 | 身份、内容状态、试看范围和权益；过期／处理中／无权 | 凭证短期有效；业务资源与媒体归属保持对应 |
| 订单与支付 | 课程 ID、幂等键；权威金额、订单与支付状态 | 后端确认价格；验签及商户／金额核验；支付未知状态可查询 | 订单、支付事实与权益在 commerce 本地一致提交 |
| 权益检查 | 用户 ID、课程 ID、访问用途；允许／拒绝及状态依据 | 仅可信服务查询，用户不可指定他人身份绕过 | 不以未及时失效的正向缓存放行；调用失败拒绝受保护访问 |
| 讨论与反馈 | 目标 ID、正文／态、预期版本；内容和汇总 | 作者权限、目标可见性、重复写入、内容隐藏 | 赞踩唯一约束，必要操作幂等，关联资源校验失败时不盲写 |
| 知识资料 | 知识库、来源、版本、访问范围；处理及发布状态 | 维护权与源资源权；格式不支持／解析失败／撤回 | 当前状态优先于索引；解析、索引与发布可重试且不覆盖新版本 |
| Agent 问答 | Agent、会话、问题；回答、来源和降级信息 | 当前用户知识权限、会话归属、额度；模型／搜索错误 | 保存实际模型、配置、搜索调用和来源版本；取消后停止多余调用；不承诺自动重试无重复费用 |

各域未来手工维护 Go Handler、DTO、标签和 Swaggo 注释，由官方工具生成各服务 Swagger，再由 Umi OpenAPI 生成前端调用。实际接口路径、字段、错误码和数据库结构在规则确认后细化；本轮不手写第二份契约，不创建生成文件。

跨域使用明确的请求超时和有限重试；读请求按错误类型重试，写请求只有具备幂等语义时才重试。部分失败不能伪装成成功，付款成功但通知失败仍保留权益，索引失败不撤销课程发布。需要投递的任务与业务状态同事务写入，接收方去重；首版不引入通用分布式事务框架。

## 6. 后续实施、发布与恢复边界

建议先闭合身份、课程和交易权益，再接入媒体学习与社区，再完成知识和 Agent 闭环；各域可以在契约确定后并行。这里只描述依赖方向，不是执行计划，也不授权开始编码。

生产前需选定并验证支付渠道、媒体服务、邮件和模型／搜索；运行数据的备份恢复、业务与派生索引的重建、渠道对账和数据库变更恢复需纳入实施计划。退款和权益变更不能靠回滚代码恢复，必须通过业务状态与对账核实；旧版本索引可重建但不能恢复已撤回权限。

现阶段不存在业务数据迁移，本轮不发布。允许回退的配置和内容版本需保留；下架、账号停用和关闭 Agent 的应急入口应可独立使用，不依赖模型正常运行。
