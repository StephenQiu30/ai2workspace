## 1. 背景、范围与非目标

当前 Go 服务只提供健康检查；前端已有请求适配器，SSR 入口只校验服务端 API 地址，尚未建立账号、会话或权限系统。公开注册、邮箱密码、验证后购买和互动、找回密码、管理员与受邀讲师已由需求确认。

本领域实现账号生命周期、邮箱验证、密码登录与重置、退出、账号停用、讲师邀请和可信身份解析。它提供“当前是谁、账号是否有效、具备哪些角色”的事实；课程归属、购买权益、讨论可见性和知识授权仍由各领域判断。

不纳入首版：第三方登录、企业 SSO、多租户组织、自定义权限编辑器、权限服务集群。注销后的交易凭证与用户内容保留政策尚未确定，不以物理删除账号代替设计。

## 3. 会话、页面与生命周期

### 注册、验证与找回

注册写入账号和待发送邮件事项。发送失败展示可重发，不回滚已经创建的账号，也不显示已验证。邮件验证、找回与讲师邀请使用独立用途的单次令牌，保存摘要、到期和消费状态；不同用途不能互换，原始值不写入日志。

邮箱唯一性采用一致的规范化策略，具体大小写及国际化处理在实现门禁中确定；数据库唯一约束处理并发注册。密码通过经过维护的密码哈希库保存，算法、参数和长度边界在实施时核验，不明文存储或作为可逆业务字段。

错误密码给出统一失败结果；注册／找回响应避免通过不存在账号的差异泄漏邮箱清单。前端可以明确说明“如该邮箱符合条件，将收到邮件”，同时提供当前操作失败或重试的状态。

重置成功后撤销该账号既有会话，用户重新登录。验证令牌的消费和账号状态更新保持本域事务一致，重复点击返回已完成或失效的可解释结果，不重复变更。

### 会话方案

首版采用服务端不透明会话：浏览器保存随机会话凭据，identity 保存凭据摘要与账号、创建／过期、撤销状态及版本。各领域对受保护请求查询可信身份，避免长时间有效的自包含角色声明阻碍账号停用。

浏览器会话 Cookie 使用生产 HTTPS、HttpOnly、Secure 和适当 SameSite；更改状态的请求同时校验来源及 CSRF 凭据。Cookie 范围、闲置／绝对有效期、密码与限流参数属于实施前配置门禁，不以浏览器本地角色或 localStorage 作为权威。

登录成功签发新会话，退出撤销当前会话并清理 Cookie。账号停用、密码重置使既有会话不可继续使用；角色变更通过当前解析结果生效。其他域不得用过期的正向缓存延长访问。

SSR 只从当前 Next.js 请求上下文读取并转发所需会话 Cookie；不能将整个用户请求 Header 无筛选转发，也不能把某个用户的凭据放进单例拦截器。响应中的 Set-Cookie 只在实际登录／退出等会话操作链路正确传回浏览器。

### 状态与交互

| 对象 | 状态／转换 | 页面与恢复 |
| --- | --- | --- |
| 账号 | 未验证 → 已验证；有效 ↔ 停用 | 未验证说明购买／互动限制；停用不误称密码错误；恢复不恢复已撤销旧会话 |
| 会话 | 有效 → 过期／撤销 | 清除当前登录态并返回登录入口；保留可安全恢复的页面位置 |
| 验证／找回令牌 | 未使用 → 已使用，或到期／替换 | 过期可申请新令牌；不得以重复请求执行多次重置 |
| 讲师邀请 | 待接受 → 已接受／撤销／过期 | 接受者需证明对应邮箱归属；已有账号只增加被授权角色 |
| 邮件任务 | 待发送 → 已发送，或重试中／需处理 | 页面显示发送结果与重试限制；邮件失败不授予权限 |

页面覆盖加载、提交中、校验失败、等待邮件、链接过期、会话失效、服务不可用及重试。登录和管理员界面沿用现有组件基线，本轮没有视觉稿或已通过的交互证据。

## 4. HTTP 契约与数据一致性

以下路径和 operationId 为本轮设计方案，进入 Go DTO 后保持唯一稳定；公共路径前缀为 `/api/identity`。错误响应至少含 `code`、可显示的 `message`、`requestId`，限流附可用的重试信息；不回传密码、令牌或内部异常堆栈。

| operationId／方法与路径 | 输入 → 输出 | 权限、错误与幂等 |
| --- | --- | --- |
| `identityRegister` POST `/accounts` | email、password → accepted、nextStep | 统一受理结果避免枚举邮箱；校验错误 400；邮箱唯一；禁止传入 roles |
| `identityVerifyEmail` POST `/email-verifications` | token → 验证结果 | 单用途、未过期；消费与状态更新原子化 |
| `identityResendEmailVerification` POST `/email-verification-requests` | 当前会话 → accepted、nextStep | 仅为本人未验证邮箱受控重发；已验证返回一致结果，不允许任意收件地址；受发送限流 |
| `identityLogin` POST `/sessions` | email、password → 当前账号摘要＋会话 Cookie | 凭据失败 401；限制失败尝试；停用不签发会话 |
| `identityLogout` DELETE `/sessions/current` | 当前会话 → 204 | 退出重复执行不恢复会话；清理 Cookie |
| `identityGetCurrentUser` GET `/me` | 当前会话 → userId、emailVerified、roles、accountStatus | 未登录 401；不返回密码摘要或其他账号信息 |
| `identityRequestPasswordReset` POST `/password-reset-requests` | email → 统一受理结果 | 公开且限流；发送失败有追踪记录 |
| `identityResetPassword` POST `/password-resets` | token、newPassword → 完成结果 | 单次令牌；成功撤销原会话；并发仅一次完成 |
| `identityInviteInstructor` POST `/instructor-invitations` | email → inviteId、status | 管理员；重复有效邀请复用或明确冲突，不无限发送 |
| `identityAcceptInstructorInvitation` POST `/instructor-invitations/accept` | token → roles | 当前账号需验证邀请邮箱；不能更改为其他用户 |
| `identityCancelInstructorInvitation` DELETE `/instructor-invitations/{inviteId}` | expectedVersion → status、version | 管理员；只撤销待接受邀请，已接受邀请不能冒充角色撤销；并发版本冲突拒绝 |
| `identitySetAccountStatus` PATCH `/accounts/{userId}/status` | status、expectedVersion、reason → accountStatus、sessionVersion | 管理员；版本冲突 409；审计与会话失效一致提交 |
| `identityRevokeInstructor` DELETE `/accounts/{userId}/instructor-role` | expectedVersion、reason → roles、accountVersion | 管理员；当前身份解析立即反映撤销；不撤销该账号合法购买权益 |

邮件重发、邀请撤销及当前账号摘要读取使用上述独立操作，必须具备相应授权和限流约束，不能作为公开管理后门。

### 跨服务身份契约

`identityResolveSession`：`POST /internal/identity/sessions/resolve`，调用方使用独立服务凭据，输入本次会话凭据，返回 `userId`、`emailVerified`、`roles`、`accountStatus`、`sessionVersion`。原始会话只用于本次解析，不进入链路日志或业务数据库。

网关不向公网暴露内部路由，内部服务仍独立校验调用方凭据；仅处于同一网络不代表可信。服务凭据由运行配置提供、按调用方区分与轮换，不放在前端或文档。生产链路的加密与凭据管理验证纳入总计划。

公共 Handler 的用户身份只取解析结果，忽略或拒绝浏览器提供的 `X-User-Id`、角色和伪造管理员声明。公共请求中的目标用户 ID 不得覆盖操作者；内部接口携带业务主体 ID 时，同时校验服务调用权限和用途，禁止做不受约束的代理。

身份解析超时或不可用时返回服务不可用，受保护操作停止；不能当匿名请求继续读取受限数据，也不能当密码错误诱导反复登录。调用传播 requestId、截止时间和取消；不引入全局无限重试。

后台任务由所属域记录触发者、资源及用途；执行时重新检查需要持续有效的资格。系统恢复任务使用被授予该操作的服务身份，不能复用讲师 Cookie 或伪造管理员。

### 数据与并发约束

| 数据 | 唯一权威及最小字段 | 一致性要求 |
| --- | --- | --- |
| Account | identity：userId、规范化邮箱、密码摘要、验证／停用状态、版本 | 邮箱唯一；角色与账号状态不得由客户端任意赋值 |
| Session | identity：会话摘要、userId、到期、撤销、版本 | 撤销后所有新解析拒绝；原始值不持久化明文 |
| OneTimeToken | identity：用途、摘要、目标、到期、消费 | 消费条件更新；重复与并发不会重复执行业务 |
| Invitation | identity：目标邮箱、邀请人、状态、版本 | 只给匹配邮箱账号授予讲师；保留撤销与接受记录 |
| Audit／MailTask | identity：操作者、动作、结果；邮件任务引用和状态 | 最小审计；发送与账号事务解耦，任务可恢复 |

## 5. 设计决定与取舍

| 决定 ID | 选择与依据 | 影响及限制 |
| --- | --- | --- |
| D-01 | 服务端会话＋当前解析，优先保证停用、退出和权限变更可控 | FR-01、FR-11；身份服务故障会限制受保护能力，需要容量验证 |
| D-02 | 角色留在 identity，资源权限留在资源领域 | 不建设万能权限平台；跨域调用不得省略所有权检查 |
| D-03 | SSR 按请求显式转发，公共 Header 不携带可被信任的用户声明 | 防止串用户与身份冒用；生成调用必须覆盖 Cookie／错误处理 |
| D-04 | 邮件采用本域可恢复任务，事务内记录发送事项 | 无需默认消息队列；投递失败不能冒充验证成功 |

## 6. 实施、发布与恢复

执行顺序与前后端任务见[领域计划](../plan/003-账号与访问控制实施计划.md)：先账号／会话与请求适配，再讲师邀请和服务鉴权，最后跨域停用验收。服务骨架随首个真实任务创建，不预建无职责目录。

初始管理员的安全创建、邮件服务、域名和发送能力、会话时限、密码与限流配置先作为门禁落实。首位管理员不得通过公共注册参数获得；密钥和运行配置不进入知识库。

邮件故障允许受控重发；会话存储恢复后仍应保留已经撤销的事实。账号停用后恢复账号不恢复旧会话；重置密码和权限调整不能通过回滚镜像撤销审计事实。

仅确认产品与本设计不表示已批准上线或创建真实账号。本轮没有业务数据迁移、真实邮件发送或凭据读取。
