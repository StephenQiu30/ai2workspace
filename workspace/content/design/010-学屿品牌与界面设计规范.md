该视觉基线适用于原创 IP 作品、制作工作台、交易及既有课程和社区界面。Landing Page 的结构和英文文案约定见本页专节。知识库使用 Fumadocs Spacious。现行页面见[原创 IP 系统设计](./018-原创IP首版系统设计与验收总览.md#2-逻辑边界与页面)。[既有社区交互设计](./009-学屿首版页面与交互设计.md)、[社区首页 V1](https://www.figma.com/design/aSWSoC2ykhoSlhXe3X4TtC?node-id=2-235) 和[社区首页 V2](https://www.figma.com/design/aSWSoC2ykhoSlhXe3X4TtC?node-id=9-892)用于核对旧功能及通用组件。

## 全站布局

`BasicLayout` 在应用根布局组合 `Navbar`、`Content`、`Footer`。每页只提供正文。帖子与课程、学习与订单、管理列表、空状态和错误状态使用同一容器；长正文和账号表单可在容器内限制行长。Figma 的 `Content` 提供可替换的 PageBody 实例属性。[桌面 BasicLayout](https://www.figma.com/design/3RvT2iBZxUtBGrTqgxNEnd?node-id=104-2351)、[移动 BasicLayout](https://www.figma.com/design/3RvT2iBZxUtBGrTqgxNEnd?node-id=104-2438)

| 区域 | 桌面 | 移动 |
| --- | --- | --- |
| 共同内容边界 | 两侧各占视口宽度的 1/30，最多 80 px。1440 px 视口净宽 1344 px，1920 px 视口净宽 1792 px | 最小边距 16 px，390 px 视口净宽 358 px |
| Navbar | 68 px 高。NavigationMenu 紧随品牌靠左，账号操作靠右，导航内容与正文同宽 | 64 px 高，Sheet 内复用竖向 NavigationMenu |
| Content | 顶部 24 px、底部 64 px，短页面填满剩余高度 | 顶部 16 px、底部 48 px，版面可随内容增长 |
| Footer | 与正文两侧对齐，短页位于视口底部，长页随文档滚动 | 链接自然换行，保留触控空间 |

Navbar、Content、Footer 共同使用 `layout-container`。两侧共用 `--layout-gutter: clamp(1rem, 3.333333vw, 5rem)`，正文净宽随视口连续变化。页面切换、加载和权限提示均保留正文基线。键盘可通过“跳至正文”越过导航；滚动条预留空间，减少页面切换时的横向跳动。

## 页面结构

原创 IP 的公开首页以正式作品开场。IP 专页与作品详情承载设定、观看、制作拆解、讨论与二创入口。制作工作台优先显示正在制作的作品、待审镜头和任务状态。页面结构与验收见[作品发布设计](./015-作品发布与制作学习设计.md)与[制作工作台设计](./012-剧本分镜与成片制作设计.md)。

购买页面将商品、价格、权益和可执行动作放在同一视野。管理页先配置，再预览买家将看到的价格及交付。操作使用“播放试看”“提交审片”“查看交付”等明确动词。

## 视觉基础

Vercel Geist Minimal 使用近白画布、紧凑的西文标题、低对比度阴影与清晰的内容分组。页面以留白、网格和对齐建立层级。业务前端默认使用完整浅色方案。Landing Page 默认按浅色设计，暗色属于按需扩展。支持暗色的界面为所有语义令牌和交互状态提供主题值，并分别验收。下表记录的是本项目采用的令牌值。[Geist 字体](https://vercel.com/font)、[Geist 字体排版](https://vercel.com/geist/typography)、[Geist 颜色](https://vercel.com/geist/colors)

| 角色 | 设计令牌与数值 |
| --- | --- |
| 主要文字与底色 | `--text: #171717`。`--bg: #ffffff` 用于营销页及内容表面。`--gray-50: #fafafa` 用于业务画布与浅色分区。`--gray-100: #ebebeb` 用于中性填充和控件状态 |
| 辅助文字 | `#4d4d4d` 用于次级正文。辅助信息通过语义令牌区分，按实际背景测量对比度 |
| 工作流强调色 | `--develop: #0a72ef`（Develop Blue）、`--preview: #de1d8d`（Preview Pink）、`--ship: #ff5b4f`（Ship Red）。用于有对应语义的流程标识、徽标和局部视觉，以文字或图标同时标明状态。浅底徽标使用同色调浅背景与满足对比度的前景 |
| 圆角 | `--radius-btn: 6px` 用于按钮及同类控件，`--radius-card: 8px` 用于卡片和浮层，`--radius-pill: 9999px` 用于徽标。纯内容行保持直角。Figma 同步 `radius/control`、`radius/surface`、`radius/pill` |
| 重点动作 | 主操作黑底白字，次操作使用中性浅底或轮廓，弱操作使用文字。选择、焦点和禁用分别有可识别的状态 |

西文使用 Geist Sans，网页中文沿用系统字体回退，Figma 中文使用 Noto Sans SC。全局开启 `font-feature-settings: 'liga'`，常用字重为正文 400、控件 500、标题 600。英文的 48 px 展示标题使用 −2.4 至 −2.88 px 字距，窄屏采用流式字号并按比例收紧。中文和多行正文保持自然字距及可读行高。常规正文以 16/24 px 为基线，业务页保持 20/28 px 页标题、16/24 px 栏目标题和 14/24 px 摘要。展示标题使用单个 `h1`，下级标题按语义排列。

原创 IP 的常驻内容采用无边框版面。作品、讨论和制作记录通过留白、对齐和背景分组。阴影令牌用于需要抬升的浮层等交互表面。输入轮廓、焦点、强制颜色模式下的可辨识边界使用各自的语义令牌。以下为设计参考值：

```css
--shadow-border: rgba(0, 0, 0, 0.08);
--shadow-hairline: 0 0 0 1px var(--shadow-border);
--shadow-card: var(--shadow-hairline), inset 0 1px 0 rgba(255, 255, 255, 0.7),
  0 1px 2px rgba(0, 0, 0, 0.04), 0 6px 20px rgba(0, 0, 0, 0.04);
```

### 令牌落地与现有基线

设计令牌通过 `frontend/src/app/globals.css` 映射为 shadcn 语义变量和 Tailwind `@theme inline`。例如 `--text` 对应 `--foreground`，白色卡片对应 `--card`，`--gray-50` 对应业务 `--background`，白色营销画布通过营销布局的语义表面令牌应用。圆角和阴影由主题及公共组件变体消费。页面使用 `text-foreground`、`bg-card`、`bg-background` 等语义类，Figma 使用相同角色的变量和文本样式。[shadcn 主题](https://ui.shadcn.com/docs/theming)

现有工程已使用 Geist 和 Radix Nova。当前默认半径仍为 4 px，既有卡片圆角、阴影和 Figma 样式按后续界面任务逐步对齐本文目标。迁移时检查同类控件、所有状态与相邻页面的视觉一致性。

## 组件与验收

业务页面先复用 `frontend/src/components/ui/` 中的 shadcn/ui Radix Nova。导航使用 `NavigationMenu`、`Sheet` 和 `DropdownMenu`，内容使用 `Card` 或 `Item`，操作使用 `Button`，状态标识使用 `Badge`，筛选使用 `ToggleGroup`。优先使用现有变体及尺寸，新增的通用视觉状态写入共享组件变体。页面 `className` 用于布局，组件色彩、字体和控件状态由主题及变体管理。Radix 组合使用 `asChild`，弹层保留可访问标题，`Avatar` 配置 `AvatarFallback`。[shadcn 组件](https://ui.shadcn.com/docs/components)

共享 `Layout`、`Heading` 和 `Text` 负责排版及页面语义。链接与图片使用 Next.js 组件，富文本由 Tiptap 编辑。图标使用现有 Lucide SVG，Button 内标注 `data-icon`，装饰图标设为 `aria-hidden`，纯图标操作提供可访问名称。可点击的按钮、链接与控件采用 `cursor-pointer`，对支持悬停的设备提供平滑且有反馈的状态切换。优先过渡实际变化的颜色、阴影或 `transform`，静态内容及禁用状态保持各自语义。遵循 `prefers-reduced-motion`，保留键盘焦点环，避免粘性导航遮住焦点或锚点。[Vercel Web Interface Guidelines](https://vercel.com/design/guidelines)

| 界面 | 组件及检查 |
| --- | --- |
| 编辑与讨论 | `FieldGroup`、`Field`、`Input`、`Textarea` 和 Tiptap 富文本区承载适用输入；编辑失败保留输入 |
| 作品与列表 | 作品、讨论行和制作记录采用平面布局与组间留白。按需使用 `Badge`、`Button`、`Pagination` 呈现状态、操作与分页。空结果、无权和请求失败分别处理 |
| 视频、付款与反馈 | 播放保留原生媒体控件，结算用 `Dialog`，等待、错误与重试使用 `Spinner`、`Alert` 等组件 |
| 导航与焦点 | 桌面导航可由键盘操作，移动菜单放入 `Sheet`。聚焦可见、输入有标签、交互目标至少 44 px；允许缩放，窄屏避免横向滚动 |

按 390、768、1440 px 验证移动、平板、桌面，并在 320 px 窄屏或等效缩放下检查内容重排。核对无意外横向滚动、键盘可达及焦点可见、移动触控目标至少 44 × 44 CSS px、正文对比度至少 4.5∶1、大字和必要控件状态至少 3∶1。涉及动效、弹窗、表单或数据加载时，覆盖减弱动态效果、焦点恢复、错误重试和等待反馈。对照实际页面记录结果。Figma 原型可使用标注清楚的样例，正式售价、访问权和发布结果由对应服务返回。[需求及参考依据](../research/002-创作社区与知识付费平台调研.md)、[WCAG 2.2](https://www.w3.org/TR/WCAG22/)

## Landing Page 模板

使用前先填入 **Landing Page Theme** 和 **Sections to add**，并明确目标受众、可用内容和 CTA 目的地。标准营销页按下表组织，英文模板的所有用户可见文案使用英文，页面语言设为 `en`，图标替代文本、操作名称和元信息也与页面语言一致。社区、学习及管理页面沿用各自的本地化规则。

| 顺序 | 区块 | 内容与组件 |
| --- | --- | --- |
| 1 | Navbar | 品牌标识、可访问的主要导航和主 CTA。窄屏使用 `Sheet` 收纳导航，保留优先操作 |
| 2 | Hero | 一个展示级标题、一段副文案、主次两个 `Button`，配 CSS 实现的抽象或 3D 主视觉。纯装饰视觉退出无障碍树和点击命中，预留尺寸并支持静态呈现 |
| 3 | Features | 三张含 SVG 图标的 `Card`，分别说明用户能完成的任务或实际收益 |
| 4 | Testimonials | 三张引用卡片，使用获准展示的真实评价及署名。设计预览可用明确标注的样例。正式发布以可核验素材为准 |
| 5 | Pricing | 三档并列，第二档通过 `Badge` 与阴影层级突出。各档标明实际价格、币种、计费周期和权益，CTA 指向有效入口。待上线方案只用于标注状态的设计预览 |
| 6 | Final CTA | 聚焦主行动，保留一个明确动作，并连接实际目标页面或流程 |
| 7 | Footer | `Copyright © 2026 Learnis`、次级导航、已发布的隐私政策与服务条款、联系入口、可索引的相关页面链接和带可访问名称的社交图标。正式页使用有效地址 |

桌面三卡并列，平板根据可读宽度折行，移动端按内容顺序单列。主次 CTA 在窄屏可堆叠。Hero 和卡片通过网格、对齐与项目品牌建立辨识度；抽象视觉可使用 CSS 渐变、变换和伪元素，按需使用模糊效果。发布验收检查页内锚点、所有 CTA、社交与法律链接的真实去向，以及标题、描述、规范 URL、viewport 和 Open Graph 预览。

工程实现沿用 Next.js App Router、共享布局和现有 shadcn/ui 组件。自定义样式通过现有 `globals.css` 或路由附近的 CSS Module 维护，SEO 与 Open Graph 通过 Next.js Metadata API 提供，viewport 使用框架默认值或 `viewport` 导出并允许用户缩放。独立 HTML 原型可将浏览器端自定义样式放在 `<head>` 内的 `<style>` 中，并直接声明相应元信息。验收以实际工程版本为准。[Next.js Metadata 与 Open Graph](https://nextjs.org/docs/app/getting-started/metadata-and-og-images)

## Tiptap、正文与评论边界

Tiptap 提供 headless 编辑能力，工具栏、选择器、链接弹窗、图片状态和错误反馈采用 shadcn Radix 组件；编辑区与内容节点由 Tiptap 负责。官方 StarterKit 可配置或关闭不需要的扩展，不能因依赖自带能力就把全部功能加入首版。[Tiptap 概览](https://tiptap.dev/docs/editor/getting-started/overview)、[StarterKit](https://tiptap.dev/docs/editor/extensions/functionality/starterkit)

| 场景 | 首版设计 | 边界 |
| --- | --- | --- |
| 正文编辑 | 独立标题输入；正文段落、标题层级、无序/有序列表、引用、链接、行内/块代码、图片 | 不自动加入表格、任意 HTML、iframe、视频嵌入、协同编辑或付费扩展 |
| 正文工具栏 | 段落/标题 DropdownMenu、列表/引用 Toggle、链接 Dialog、代码动作、图片上传动作、撤销/重做 | 使用真实选区状态与可用命令，不能只做静态选中外观 |
| 评论编辑 | 精简段落输入；建议仅提供链接、行内代码与必要文本强调 | 不展示正文级标题、图片和复杂块工具；精简扩展白名单在页面评审中核定 |
| 阅读展示 | 统一正文渲染器呈现同一允许结构 | 编辑与阅读样式一致，结构通过后端白名单校验；不能直接信任任意 HTML |
| 图片 | 正文块图片、替代文本、宽高占位、上传中/失败/重试 | Tiptap Image 负责展示，不提供服务端上传；上传服务、大小/类型与资源授权由业务实现另行落实 |
| 链接 | 默认可读文字与下划线；编辑弹窗显示目标地址 | 协议与目标校验；禁止脚本地址；外链新窗口行为应有可访问说明 |
| 粘贴 | 保留允许结构，清除来源网站样式 | 不将粘贴的表格/嵌入扩展成新业务功能 |
| 提交与恢复 | 校验错误定位到字段；提交中阻止重复发送；失败保留正文 | 自动保存、跨设备草稿和具体保留期限未确认，不虚构“已自动保存” |

Tiptap Image 的图片显示与上传是不同职责，链接 UI 也需要宿主自行组合；这些属于使用官方扩展的必要适配，不等于手写替代 UI 控件。[Image](https://tiptap.dev/docs/editor/extensions/nodes/image)、[Link](https://tiptap.dev/docs/editor/extensions/marks/link)
