## 1. 背景、目标与交付边界

学屿是以社区为首页的课程学习与交流产品。界面让用户先找到讨论与课程，再完成阅读、学习和互动；问答作为当前任务的辅助能力存在。正式品牌写作“学屿 · Learnis”，中文短称“学屿”，英文写作“Learnis”，未来包名、服务标识等技术命名使用小写 `learnis`。

本轮完成品牌与完整首版 Figma 设计，包括浅色桌面稿、主要移动稿、关键交互与状态。本文定义视觉及组件规则；P01–P21 页面模板和 G01 全局问答面板由[首版页面与交互设计](./009-学屿首版页面与交互设计.md)维护。设计完成、Figma 可点击和知识库构建通过均不代表业务功能已实现。

UI-S-11 确认沿用首页黑白灰、无边框基准同步全部 Figma 页面与实现规范，本轮不修改 `frontend/`。无边框规则覆盖设计组件、页面及未来实现映射；本页仍是唯一正文，不创建 `design-system/MASTER` 或另一份主题规范。Geist 与现有官方 shadcn/ui Radix 基线保留。

截至本轮核验，前端是服务连接基线页，使用 Next.js、TypeScript、Tailwind v4、shadcn/ui Radix Nova、Geist 和 Lucide；实际已有 `Alert`、`Badge`、`Button`、`Card` 四种组件。本规范中其余组件属于后续选用清单，未安装、未接入。Tiptap 尚未安装。

技术标识统一更名已确认，但本轮不执行目录、包名、Go module、服务名、环境配置、接口、域名或部署迁移。既有文档的稳定 ID 保留追溯，不能把设计中的 `learnis` 写成当前工程已更名。源码实施、依赖安装、数据库、真实付费调用、发布均不属于本轮。

## 2. 视觉原则与品牌资产

### 2.1 视觉原则

1. 默认页面为白色，白色与浅灰表面、深灰文字建立层级，黑色主 CTA 说明当前最主要动作。
2. 展示颜色统一为黑、白与中性灰；链接使用深色文字及下划线，选中状态使用灰色表面与明确文字，键盘焦点使用黑色外环。错误、警告和成功通过图标、标题及可执行动作区分。
3. 页面以内容、留白和底色组织；卡片、表格、导航、footer 默认无描边，不添加装饰 `Separator`。卡片只承载需要分组的内容，不将所有文字包入嵌套卡片。
4. 使用组件既有 variant 与语义 Token；同一种动作、状态和密度在页面之间保持一致。
5. 中文可读性优先：英文源中的紧字距、大小写和句号习惯不强加给中文。
6. 原来源的彩色网格渐变保留为来源记录，不作为首版业务界面装饰；首版 Logo、社区、学习页与管理页采用统一黑白灰体系。

这些是学屿采用的设计原则。无边框是用户的项目决定；Vercel 官方色彩系统本身定义了边框色阶和分隔使用规则，不能将本项目选择写成 Vercel 强制要求。[Geist Colors](https://vercel.com/geist/colors)

### 3.2 语义与组件行为

`Badge/info`、`warning`、`error` 继续表达各自状态，均采用灰底深色文字；通过“待审核”“处理失败”等完整标签说明结果，不用灰度深浅代替文字。Alert 保留信息、警告或错误图标。删除、退款、发布等重要动作继续使用 AlertDialog 的标题、后果说明和明确动作标签。

`default` 为黑底白字，`secondary` 为灰底深色字，`ghost` 为透明底深色字，`link` 为带下划线的深色文字；官方 `outline` 仅保留兼容语义，业务次操作选用 `secondary`。无边框只移除静态装饰，不移除焦点外环。

### 3.3 已计算色对与边界

| 色对 | 对比度，约 | 用途与限制 |
| --- | --- | --- |
| 白 / `#171717` | 17.93:1 | 主操作、深色表面 |
| `#171717` / `#f5f5f5` | 16.45:1 | 状态、次按钮、输入文字 |
| `#4d4d4d` / 白 | 8.45:1 | 正文 |
| `#6b6b6b` / 白、`#fafafa`、`#f5f5f5` | 5.33 / 5.11 / 4.89:1 | 次级说明、placeholder |
| `#f5f5f5` / 白 | 1.09:1 | 表面层次；不能单独视作必需控件边界达到 3:1 |
| `#ebebeb` / 白 | 1.19:1 | 装饰或兼容边界；不作为唯一识别线 |

普通文字至少 4.5:1，大字至少 3:1，必要非文字信息至少 3:1。以上仅为不透明静态 sRGB 色对计算；真实控件识别、透明叠加、键盘、状态播报和完整 WCAG 仍需业务实现后验证。[文字标准](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文字标准](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)

## 4. 字体、中文排版与内容密度

Geist 与 Geist Mono 由官方以 OFL 提供，来源文件“私有字体、必须替换”的说法不成立。当前前端已通过 `next/font/google` 引入 Geist / Geist Mono，保留此基线；中文不能依赖 Latin 子集覆盖。[Geist Font](https://vercel.com/font)

| 字体角色 | 字体栈 / 使用 |
| --- | --- |
| UI 与正文 | `Geist, "PingFang SC", "Microsoft YaHei", system-ui, sans-serif`；未安装中文字体时使用系统回退 |
| 代码与技术值 | `"Geist Mono", ui-monospace, SFMono-Regular, Menlo, Monaco, monospace`；中文仍由系统回退 |
| 字重 | 正文 400，按钮与强调 500，中文标题和中英字标采用 Medium 500；不通过堆叠粗体替代信息层级 |
| 中文字距 | 默认 0；不套用英文标题的负字距和大写规则 |
| 英文显示标题 | 可沿用来源负字距，但只在英语标题中验证；不作为混合中英标题默认值 |

本轮 Figma 可用字体与网页实现字体分别记录：英文、数字采用可用的 Geist Regular / Medium / SemiBold；中文设计稿采用 Noto Sans SC Regular / Medium。当前 Figma 可用字体中没有对应中文 SemiBold，中文标题使用 Medium，不以伪粗体假装拥有该字重。Noto Sans SC 是设计稿的中文替代字体，不表示 Geist 支持中文；后续网页实现仍沿用上表 Geist 加中文系统 fallback 的方案。中文标题字重和换行在 Figma 与实际浏览器间需要复核，不能承诺两者字形、字宽完全相同。

| 触达面积 | 移动主要操作至少 44×44 CSS px，图标视觉可小于触达区；这是一项项目目标，不等于整页通过 WCAG AAA |
| 圆角 | 输入、普通按钮、菜单项 6px；卡片与 Dialog / Sheet 内部主要表面 12px；较大媒体卡片可 16px |
| 营销 CTA | 100px 胶囊仅用于营销型区域；可与同屏导航 6px 按钮共存，不在同一组件角色内随意切换 |
| 圆形 | 头像、Logo 问答入口使用 full；内容卡片不套 full |
| 默认描边与分隔 | 卡片、表格、导航和 footer 不绘制静态描边，不添加装饰 Separator；通过留白、对齐和底色组织 |
| 默认深度 | 内容卡片不绘制描边且无重投影；Dialog、Sheet、菜单与助手等弹层无描边，仅使用轻阴影表达层级 |
| 弹层阴影 | 来源候选 `0 1px 1px #00000005, 0 8px 16px -4px #0000000a, 0 24px 32px -8px #0000000f`；需结合实际表面复核 |
| 动效 | hover / focus 120ms，菜单与浮层 160–200ms；减少动态效果偏好下取消位移和非必要动画；数值为项目决定 |

图标采用项目现有 Lucide。组件中的图标尺寸由组件 API 与默认样式控制，不在每个页面单独重写。单独展示的图标采用 16 / 20 / 24px 网格；图标按钮必须有可访问名称。

### 5.2.1 已确认首页与页面密度

[确认基准首页](https://www.figma.com/design/3RvT2iBZxUtBGrTqgxNEnd?node-id=58-86)为黑白灰课程社区：顶部简短介绍与发布入口，主区先展示课程标题、分类、讲师、章节／课时、价格和查看入口，再展示按时间排列的讨论标题、独立摘要、作者与分类。右侧为登录态继续学习和话题；游客替换为登录入口，不伪造个人进度。首页承担公开发现与 SEO／GEO，但不使用大面积宣传 Hero 挤占课程和讨论。

课程列表沿用首页卡片语言；学习页突出媒体和目录；社区详情与 Tiptap 保持可读列；订单、通知与管理表格使用同一灰阶状态和留白。课程、账号及示例数字仅用于设计，不代表已发布真实数据。移动首页同样在讨论前提供紧凑课程入口。

### 5.3 导航与账户入口

主导航只包含“社区”“课程”“我的学习”。品牌链接回到社区首页；当前页面通过文字颜色、轻背景或下划线表达，同时提供当前页语义，不只依赖灰度变化。游客点击“我的学习”进入登录路径，登录后返回原目标。

登录用户右侧展示通知按钮与头像。头像菜单包含本人账号、我的订单、本人获授权的管理入口与退出，具体菜单条目以页面设计为准。普通用户不显示管理入口，受邀讲师仅进入获授权的课程与知识管理，管理员可进入其余管理能力；直接访问管理地址时仍由后端核权。游客以登录 / 注册入口代替个人账户状态，不展示虚构通知数量或默认已登录身份。

footer 保留品牌、必要帮助与已存在的政策入口；不能为填充布局编造客服电话、备案号、政策承诺或未创建链接。社区和课程内容页均有 footer；沉浸学习页与全屏浮层可使用紧凑页脚，但不把它覆盖在视频控制栏或编辑器操作上。

### 5.4 学屿助手浮层

右下角入口使用品牌 Logo，视觉按钮为 52×52px；桌面距视口右侧和底部各 24px，移动为 16px 并加安全区。入口显示时页面内容底部留 104px，避免遮挡发布、支付、视频控制或表单提交；必要时随页面操作区上移，不能只提高层级覆盖内容。

桌面问答浮层参考宽 440px、高 680px，消息区独立滚动，高度不超过可用视口减 112px；移动使用全屏 Sheet。标题为“学屿助手”，有明确关闭动作；当前课程场景可显示已授权课程上下文。上下文由访问权决定，不因用户正停留在公开课程介绍页而授予受保护资料。

浮层由标题、会话内容、来源、状态与输入区组成。关闭只收起浮层并恢复焦点到入口，不等于取消正在运行的问答；取消由明确动作触发，重开后呈现可取得的真实运行状态。来源详情通过面板内 Sheet 等组件查看，关闭来源后回到原答案。首版不建立独立用户 Agent 页面。管理员配置页属于管理区域，入口在管理员头像菜单之后的管理导航。系统可支持不同 Agent 配置，但普通用户页面不暴露供应商密钥、预算、管理配置或内部提示词。

现有领域 PRD 未承诺逐字流式展示；设计以检索 / 搜索 / 生成状态和完整答案为基线。采用聊天组件不自动升级为已实现流式传输、历史持久化或分支会话能力。

## 6. shadcn Radix 组件与复用边界

本项目保持 `radix-nova` 与 Radix 基础，不在本轮切换 Base UI。组件由官方 CLI 查询、查看并在后续实施时按需引入，不手工复制另一套控件库。语义变量与组件自身的 CVA／样式统一表达无边框规则，不在页面逐处拼接 `border-0` 或覆盖颜色、字号和圆角；也不使用全局选择器将全部 `border`、`outline`、`ring` 清零。

业务次级操作选择灰色填充的 `secondary`，轻操作按用途选择 `ghost`／`link`；不使用描边 `outline` 作为业务默认次级按钮。官方 `outline` 兼容 API 保留原含义，不把同名 variant 偷换为填充样式；Figma 中对应的原 outline 设计变体改名为 secondary，与未来组件调用保持一致。

| 页面能力 | 采用组件 / 组合 | 必须保留的行为 |
| --- | --- | --- |
| 全站导航 | `NavigationMenu`、`NavigationMenuLink asChild` + Next `Link` | 链接语义、当前页、键盘操作 |
| 移动导航 | `Sheet`、`SheetTitle`、`SheetClose` | 可访问标题、焦点管理、关闭恢复 |
| 头像与账户菜单 | `Avatar` + `AvatarFallback`；`DropdownMenu` | fallback、真实 Button 触发器、菜单分组 |
| 普通表单 | `FieldGroup`、`Field`、`FieldLabel`、`FieldDescription`、`FieldError` + 控件 | 标签关联、错误、禁用、提交状态 |
| 搜索与问答输入 | `InputGroupInput` / `InputGroupTextarea`、`InputGroupAddon`、`InputGroupButton` | 键盘输入、附属按钮、输入保留 |
| 工具栏选择 | `ToggleGroup`、`Toggle`、`DropdownMenu`、`Tooltip` | pressed / selected 语义，不用手写 Button 模拟整组切换 |
| 内容承载 | `Card` 完整组合、`Item`、`Badge` | 标题层级与内容结构；默认无描边，不添加装饰 Separator，避免过度卡片化 |
| 列表与管理数据 | `Table` / 官方 Data Table 组合、`Pagination`、`Tabs` | 排序和分页状态、空态、可访问表头 |
| 反馈 | `Alert`、`Empty`、`Skeleton`、`Spinner`、Radix 项目的 `Sonner` | 稳定占位、明确原因与可执行恢复 |
| 确认与详情 | `Dialog`、`AlertDialog`、`Sheet` | 标题、描述、取消、焦点返回 |
| 问答会话 | `MessageScroller`、`Message`、`Bubble`、`Attachment`、`Marker`、`Trace` | 视口与滚动、消息与工具步骤的职责分开 |
| 课程目录 | `Accordion` / `Collapsible` 与必要 `ScrollArea` | 展开状态、当前课时、锁定原因 |
| 代码与引用 | 适用 `CodeBlock`、`HoverCard`、链接组件 | 复制反馈、来源可打开、长内容局部滚动 |

官方 `MessageScroller` 负责视口、定位和跟随行为，不拥有消息数据、传输、持久化或模型状态。`Message` 是行布局，`Bubble` 是消息表面；`Trace` 用于实际可展示的工具步骤与来源，不要求模型公开内部推理全文。[Message Scroller](https://ui.shadcn.com/docs/components/radix/message-scroller)、[Message](https://ui.shadcn.com/docs/components/radix/message)、[Trace](https://ui.shadcn.com/docs/components/radix/trace)

本次 CLI 的 `docs` 对 `message-scroller`、`message`、`bubble`、`attachment`、`marker` 未返回文档链接，但官方注册表搜索与 Radix 官网已有这些组件。该现象是已观察到的链接索引缺口，不能视为组件不存在；后续安装前仍需重查可用性和版本。

### 6.1 不手写 UI 的适用范围

业务页面不手写已有按钮、输入、菜单、弹层、反馈、分隔线、头像和聊天气泡的替代实现。页面组合既有组件表达产品行为，共享布局只为真实复用建立。

允许的底层范围包括：Next.js 根布局必需的 `html` / `body`；具有语义的 `header`、`main`、`footer` 与布局容器；官方 shadcn 组件内部原生元素；Tiptap 的编辑区域及正文节点；受控图片、音视频播放器底层。它们不得被当作另造控件的豁免。Next.js 本地官方文档明确要求根布局定义 `html` / `body`，所以本规则不是“所有源码零 HTML 标签”。

全站 footer 由语义页壳与官方链接组合，以留白和对齐分组，不添加装饰 Separator，不使用 `CardFooter` 冒充全站语义 footer。网站知识库继续采用现有 Fumadocs 布局；本文业务主题不覆盖知识库的官方 Spacious 基线。

### 6.2 设计与未来实现的统一映射

下表是 R-30 的统一约定，不是当前前端代码完成记录。Figma 使用语义变量和组件实例；未来实现继续使用现有主题文件与 `components/ui/` 中的官方组件源码，在组件层集中调整，复用 [shadcn 语义主题](https://ui.shadcn.com/docs/theming)，不另建平行设计系统或主题正文。

| 设计对象 | Figma／视觉规则 | 未来 shadcn／Tailwind 映射 | 必须保留的状态 |
| --- | --- | --- | --- |
| 页面与页壳 | 默认白色；导航、footer 无描边与装饰分隔 | `background` → `canvas`；页壳共享样式维护间距和表面，不在页面重复覆盖 | 当前页、链接语义、移动收纳与焦点 |

| 输入与搜索 | 无描边；默认 `control-surface`，hover `control-hover`；16 / 24px；单行 Input 桌面高 40px、移动高 44px，多行输入按内容场景设置高度 | `Input`、`InputGroup`、`Textarea` 统一组件样式；组合输入由同一外层承载表面与焦点，避免叠加多圈 | label、placeholder、输入值、错误、输入保留及焦点 |
| Tiptap 编辑 | 无描边灰色表面；工具栏与输入表面一致 | 编辑器宿主复用上述语义变量；工具栏仍采用官方 shadcn Radix，不自行重造控件 | 选区／pressed、只读、上传状态、校验和键盘操作 |
| 弹层与助手 | 白色表面，无描边，仅轻阴影 | `Dialog`、`AlertDialog`、`Sheet`、`DropdownMenu`、`Popover` 与 G01 的共享表面样式 | 标题、遮罩、焦点管理、关闭及回到触发点 |

| 错误与禁用 | 错误文字／图标＋浅灰底；禁用具有明确不可操作语义 | `FieldError`、`error-deep`／`error-soft`、`aria-invalid`／关联描述与 `disabled` | 不以颜色或透明度单独传达；错误状态仍保留可见焦点 |

## 7. Tiptap、正文与评论边界

Tiptap 提供 headless 编辑能力，工具栏、选择器、链接弹窗、图片状态和错误反馈采用 shadcn Radix 组件；编辑区与内容节点由 Tiptap 负责。官方 StarterKit 可配置或关闭不需要的扩展，不能因依赖自带能力就把全部功能加入首版。[Tiptap 概览](https://tiptap.dev/docs/editor/getting-started/overview)、[StarterKit](https://tiptap.dev/docs/editor/extensions/functionality/starterkit)

| 场景 | 首版设计 | 边界 |
| --- | --- | --- |
| 正文编辑 | 独立标题输入；正文段落、标题层级、无序/有序列表、引用、链接、行内/块代码、图片 | 不自动加入表格、任意 HTML、iframe、视频嵌入、协同编辑或付费扩展 |
| 正文工具栏 | 段落/标题 DropdownMenu、列表/引用 Toggle、链接 Dialog、代码动作、图片上传动作、撤销/重做 | 使用真实选区状态与可用命令，不能只做静态选中外观 |
| 评论编辑 | 精简段落输入；建议仅提供链接、行内代码与必要文本强调 | 不展示正文级标题、图片和复杂块工具；精简扩展白名单在页面评审中核定 |
| 阅读展示 | 统一正文渲染器呈现同一允许结构 | 编辑与阅读样式一致，结构通过后端白名单校验；不能直接信任任意 HTML |
| 图片 | 正文块图片、替代文本、宽高占位、上传中/失败/重试 | Tiptap Image 负责展示，不提供服务端上传；上传服务、大小/类型与资源授权由业务实现另行落实 |
| 链接 | 默认可读文字与下划线；编辑弹窗显示目标地址 | 协议与目标校验；禁止脚本地址；外链新窗口行为应有可访问说明 |
| 粘贴 | 保留允许结构，清除来源网站样式 | 不将粘贴的表格/嵌入扩展成新业务功能 |
| 提交与恢复 | 校验错误定位到字段；提交中阻止重复发送；失败保留正文 | 自动保存、跨设备草稿和具体保留期限未确认，不虚构“已自动保存” |

Tiptap Image 的图片显示与上传是不同职责，链接 UI 也需要宿主自行组合；这些属于使用官方扩展的必要适配，不等于手写替代 UI 控件。[Image](https://tiptap.dev/docs/editor/extensions/nodes/image)、[Link](https://tiptap.dev/docs/editor/extensions/marks/link)

### 7.1 公开摘要与受保护内容

社区列表和游客详情只读取独立公开字段：标题、作者、分类、时间和公开摘要。公开摘要由作者/管理流程单独维护，不由前端取正文前几行生成，也不通过折叠、模糊、透明遮罩隐藏已经下发的正文。图片、评论正文、代码片段和富文本原始数据均不能随游客摘要响应一起下发。

登录墙明确显示“登录后阅读正文和评论”，提供登录/注册并保留原页面回跳；不用虚构被遮挡的正文制造内容预览。受课程权限约束的讨论还须检查课程访问权，登录不自动解锁所有课程讨论。

课程介绍、价格和目录可以公开；学习内容、播放地址与资料仍按账号和课程权益校验。详情页“开始学习”“购买课程”“继续学习”等动作由真实权限与状态决定，不以按钮显示代替服务端鉴权。通知和搜索结果沿用同一公开边界，不携带可绕过登录的受保护摘要。

## 8. 交互、状态与可访问性

### 8.1 统一组件状态

| 状态 | 设计要求 | 典型组件 |
| --- | --- | --- |
| 默认 | 标签说明对象与动作，主次操作清晰 | Button、Field、NavigationMenu |
| hover / active | 使用统一浅背景或现有 variant，不改变布局尺寸 | Button、DropdownMenuItem、列表项 |
| focus-visible | 保留不透明 `#171717` 的 2px 环与 2px offset；所有可交互元素有可见焦点，浮层内焦点顺序与视觉一致 | 所有控件 |
| 选中 | 文字/图标或下划线与背景共同表达，保留 selected / pressed 语义 | Tabs、ToggleGroup、导航 |
| disabled | 真正不可操作时才使用；有需要时给出原因，不只降低透明度 | Button、Input、菜单动作 |
| loading | 原动作文字可变为“发布中…”等；Spinner 与 disabled/忙碌语义结合，保留宽度 | Button、提交动作 |
| invalid | 错误文字／图标配浅灰表面，字段错误就近展示；不依赖彩色描边，保留 Field `data-invalid`、控件 `aria-invalid` 与描述关联 | Field、FieldError |
| 成功 | 明确“已保存/已发布”等真实结果；重要结果可持续查见 | Sonner、Alert、页面状态 |
| 空 | 说明为什么为空及可用下一步，不使用虚构数据填充 | Empty |
| 加载 | Skeleton 与最终布局相近，防止大幅跳动；不泄露权限未知内容 | Skeleton |
| 失败 | 可读原因、保留已有内容与可恢复动作；避免只显示错误码 | Alert、重试 Button |

### 8.2 业务状态覆盖

| 场景 | 必须设计的状态 |
| --- | --- |
| 社区与详情 | 列表加载/空/失败、游客摘要、登录墙、已登录正文、正文已隐藏/不可访问、评论空/加载/失败、单层回复、互斥赞踩、收藏与取消 |

| 课程 | 公开详情、免费/付费、已购/未购、试看、学习中、播放加载/失败、课程不可访问、权益撤回后的恢复指引 |

来源内容和错误原因显示到用户能采取行动的程度，不向普通用户暴露内部供应商配置、密钥、调试栈或未授权知识。问答失败不阻止课程播放、阅读和社区操作。重复支付、退款、发布等业务安全仍由领域规则约束，本页不另设状态机。

### 8.3 可访问性规则

- 使用原生语义与 Radix 组件行为；Dialog / Sheet 保留可访问标题，关闭后焦点回到触发点；Esc 关闭与遮罩行为按组件惯例和产品场景验证。
- 图标按钮提供动作名称；Avatar 有 fallback；有意义的图片有替代文本。通知数量与状态要能被读屏理解，不能只靠红点。
- 普通文本至少 4.5:1，大字至少 3:1；关键图形和焦点指示至少 3:1。本文颜色计算不是完整 WCAG 通过报告。
- 键盘可完成导航、菜单、发布、评论、问答打开关闭和表单提交；不产生键盘陷阱。输入法组合输入时不把确认选字误作发送。
- 长文在 200% 文本放大后仍可读，320px 宽不出现页面级横向滚动；工具栏溢出可滚动且有可发现入口。
- 触屏主要操作按 44×44 项目目标设计，不能用仅 28px 的导航视觉高度声称满足触达要求。WCAG 2.2 AA 目标尺寸基线为 24×24 且有例外，44×44 属更严格目标。[目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- 状态播报适度：提交结果与关键失败可通过 live region 告知，不逐 token 或逐条骨架重复播报。
- 尊重减少动态效果；浮层与粘性导航不遮挡焦点、错误提示、浏览器放大后的关键内容。移动输入文字使用 16px 并保留浏览器缩放，不通过禁止 zoom 处理聚焦放大。
