# 课程与媒体学习 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 让供给者发布可交付课程，让有权访问的学员播放并恢复进度。

**Architecture:** `learning` 拥有课程、章节课时、媒体版本与进度；价格／购买权益来自 `commerce`。上传直达选定媒体存储，服务校验并处理版本；播放时同时验证内容状态与权益，不能用课程页面鉴权替代媒体保护。

**Tech Stack:** 既有 Go／Gin／PostgreSQL、Next.js／TypeScript／shadcn Radix、Swaggo → Umi OpenAPI；媒体官方上传与播放能力待选型验证。

## Global Constraints

- 课程 → 章节 → 课时；录播视频与图文资料。草稿、审核发布、普通下架与必须撤回分别处理，普通下架保留已购访问。
- 上传基线见 [PRD 视频上传规格](../prd/003-课程与媒体学习产品需求.md#视频上传规格)：MP4／H.264／8-bit SDR，可无音轨，否则 AAC；`0 < bytes ≤ 2,147,483,648`、`0 < duration ≤ 120 分钟`、旋转后长边 ≤1920／短边 ≤1080、≤30 fps。
- 每讲师最多 2 个并行上传会话、有效期 24 小时；受保护 HLS 最多 720p／1080p，不升采样或提高帧率。首版不提供学员原片下载。
- schema、Go DTO、自动生成客户端按[工程规范](../standards/001-项目文档与设计规范.md#工程规范与目录设计)归属；不新增转写、直播、作业或完课判定需求。

**Files:**

| Test | `backend/services/learning/tests/integration/media_test.go`、`frontend/tests/upload_state.test.ts`。 |

**Interfaces:**

- Produces: `learningCreateUpload({courseId, lessonId, declaredBytes, fileName}) → {uploadId, sourceVersion, expiresAt, uploadInstructions}`；`learningCompleteUpload({uploadId, idempotencyKey, parts}) → {sourceVersion, state}`。sourceVersion 表示待校验源，处理后独立 mediaVersion 表示转码产物，不混成一个状态。指令限制到单个对象与会话，不能授权整个存储空间。
- Consumes: 选定媒体供应商官方分片／续传、元数据探测和处理通知；完成通知经验证后只更新自己 mediaVersion；课程发布操作显式选中 ready 版本。

- [x] 写 `TestUploadLimitsAndExpiry`，以元数据与受控素材断言 `2,147,483,648` 字节／120 分钟／1920×1080／30 fps 可接受、任一加一或零时长被拒；第三会话拒绝，创建后 24 小时到期不能再续传。
- [x] 写 `TestUploadValidatesActualMedia`、`TestMediaVersionPublication`；伪 MP4／HEVC／损坏文件拒绝，`completeCount == 1`，新版本失败及旧回调到达均不改动当前有效发布版本；ready／发布／停止交付保存真实生效时间，重复通知不能重写 delivery evidence。
- [x] 执行 `make check SERVICE=learning` 确认新增用例失败后，在 `upload.go`、`processing.go` 实现授权直传、重新鉴权续传、真实校验、持久任务和幂等状态处理，媒体可用与撤回更新交付历史的有效时间；不会由 Go 中转视频字节。
- [x] 在 `video_uploader.tsx` 实现 `VideoUploader`；展示上限、进度、处理中、重新导出、续传与过期重传，ready 后通过课程编辑器显式发布，不自动替换旧视频。
