**Goal**　让制作成员能确认设定版本、登记和引用素材，并由 IP 负责人按用途审批、开放和撤回。

**Architecture**　`identity` 提供会话身份，`creation` 核验工作区成员关系，并在 PostgreSQL 保存设定版本和用版权威。COS 保存文件，Go 按当前权限签发访问地址。

**Tech Stack**　Go / Gin / pgx、PostgreSQL、COS、Next.js / shadcn/ui。

## Global Constraints

- 设定包含角色、世界观和时间线。浏览、下载、站内二创、公开发布和商用交付分别核验。素材格式、大小和授权负责人在试点前确认。
- 后端以统一结构初始化空库。工作区与 IP 按当前成员状态鉴权，租户及媒体凭证留在环境配置。
- 工作区会话撤权后同时复核短链和长会话，协同资格由编辑权限单独判定。
- 文中新增的业务代码、测试与页面路径是规划目标。`backend/internal/identity/application/sessions/` 的会话机制与 `backend/internal/learning/application/media/` 的媒体行为作为业务回归依据。后端 REST 契约从 Go DTO 和 Swaggo 生成，再更新 Umi 客户端。
- 测试命令在目标工程建立后使用。真实付费、外部生产实例、提交和发布分别按实际授权执行。

## Review Focus

- TestWorkspaceAccess：缓存或旧会话下的工作区成员资格以当前状态为准。
- TestCanonApproval：并发审批不丢失正式指针或已用版本。
- TestUploadRegistration：超限或替换 COS 对象无法登记。
- TestAssetIsolation：旧访问链接与新链接走同一权限判断。
- TestAssetWithdrawal：撤回一个用途不会误伤其他合法用途。
