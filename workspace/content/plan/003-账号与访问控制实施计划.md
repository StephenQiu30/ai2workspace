# 账号与访问控制 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可公开注册、验证、找回和退出的邮箱账号，以及各业务域能够验证的当前身份。

**Architecture:** `identity` 独占账号、凭据、会话和角色。各业务服务通过受保护的身份解析契约取得当前主体，再自行验证资源归属；浏览器传入的用户 Header 不构成身份。前端复用生成调用与现有请求适配器。

**Tech Stack:** 既有 Go／Gin／Swaggo、PostgreSQL／pgx、Next.js／TypeScript／shadcn Radix、Axios／Umi OpenAPI；不新增统一认证框架或自研网关。

## Global Constraints

- 公众邮箱密码注册；邮箱验证后才允许购买和互动；讲师来自管理员邀请。一个账号可有多个角色，讲师资格不授予其他讲师资源的管理权。
- SSR 凭据必须随当前请求传递，不写入共享 Axios defaults；身份服务不可用时受保护操作失败，不把用户默认为匿名或管理员。
- 采用[工程规范](../standards/001-项目文档与设计规范.md#工程规范与目录设计)。本页工程路径均为计划创建，明确标为 Modify 的例外；当前只有 `ai2workspace` 健康检查基线。
- Swagger／前端调用由 Go DTO 与注释生成，不手改。服务接入、多服务生成配置和共享文件变更服从总计划 P0 的集成顺序。

## Review Focus

1. 重复邮箱与错误密码不能产生重复账号或泄漏凭据：T-01 `TestRegisterDuplicateEmail`、`TestLoginRejectsWrongPassword`。
2. 验证／找回令牌重放和失效必须被拒：T-01 `TestAccountTokenSingleUse`。
3. 两位用户同时 SSR 读取不能串用 Cookie：T-01 `ssr_session_isolation`。
4. 伪造身份 Header、普通用户邀请讲师不能越权：T-02 `TestServiceIdentityRejectsForgedActor`。
5. 退出、停用及撤销讲师资格后的旧会话不能继续操作：T-02 `TestRevokedSessionAndRole`。

**Interfaces:**

- Produces: `identityRegister({email, password}) → {accepted, nextStep}`；`identityVerifyEmail({token}) → {emailVerified}`；`identityLogin({email, password}) → {userId, emailVerified, roles, accountStatus}` 并设置会话 Cookie；`identityLogout() → 204`；`identityResendEmailVerification({}) → {accepted, nextStep}` 基于当前未验证会话，限流且不额外授予权限。
- Produces: `identityRequestPasswordReset({email}) → {accepted}`；`identityResetPassword({token, newPassword}) → {updated}`；`identityGetCurrentUser() → {userId, emailVerified, roles, accountStatus}`。上述返回不含密码、原始令牌和内部凭据。
- Consumes: 邮件提供方受控发送能力与测试收件箱；会话过期、令牌期限、密码策略在执行前按身份设计评审确定，不由前端自行设定。

- [ ] 在 `account_test.go` 写 `TestRegisterDuplicateEmail`、`TestLoginRejectsWrongPassword`、`TestAccountTokenSingleUse`；断言 `accountCount == 1`、注册响应不枚举已有邮箱、错误密码不签发会话、重复或失效 token 返回拒绝且原账号状态不被倒退；重复验证可返回已完成的幂等结果，不重新执行状态变更；重发请求限流且没有邮件送达也不能被标为已验证。
- [ ] 在 `backend/` 执行 `make check SERVICE=identity`，先确认新增业务用例因接口未实现失败；若只是缺数据库／邮件夹具则先补夹具，不能当作业务红灯。
- [ ] 在 `accounts/account.go` 和 `sessions/session.go` 实现上述账号操作对应的事务、单次令牌消费、重发限流与会话失效，Handler 的 DTO／Swaggo 注释覆盖成功和错误响应；同次交付接入本服务数据库、邮件适配与就绪检查。
- [ ] 在 `server.ts` 实现仅当前 SSR 请求的凭据转发；在 `account_form.tsx` 实现 `AccountForm`，通过生成的账号操作提交并显示验证、等待邮件、失效链接和失败状态。
- [ ] 在 `account.spec.ts` 写 `verified_account_roundtrip`、`ssr_session_isolation`：两位账号并行打开页面，断言各自 userId 始终一致，未验证者购买／互动被后端拒绝，重置密码后旧会话不可继续使用；写 `state_change_requires_csrf` 断言伪造跨站请求即使携带 Cookie 也不能执行状态变更。
- [ ] 运行本页“验证命令”中的服务、前端与 `account.spec.ts`／`identity.spec.ts` 检查；期望全部通过，保留邮件模拟与真实送达的区别。

## Task T-02：受邀讲师、停用与跨服务可信身份

**依据与状态：** FR-01／FR-11、AC-01／AC-11；依赖 T-01，未开始。

**Files:**

| 操作 | 精确路径与职责 |
| --- | --- |
| Create | `backend/services/identity/internal/access/authorization.go`、`backend/services/identity/internal/access/handler.go`、`backend/services/identity/internal/access/request.go`、`backend/services/identity/internal/access/response.go`；`frontend/src/app/manage/accounts/page.tsx`、`frontend/src/features/account/account_management.tsx`。 |
| Modify after T-01 | `backend/services/identity/internal/server/server.go`、`backend/services/identity/schema.sql`。 |
| Test | `backend/services/identity/tests/integration/access_test.go`、`tests/contracts/service_identity.spec.ts`、`tests/e2e/account_roles.spec.ts`。 |

**Interfaces:**

- Produces: `identityResolveSession({opaqueSession}, serviceCredential) → {userId, emailVerified, roles, accountStatus, sessionVersion}`，仅内部可信调用；账号不存在／停用／会话失效时拒绝。
- Produces: `identityInviteInstructor({email}) → {inviteId, status}`、`identityAcceptInstructorInvitation({token}) → {roles}`、`identitySetAccountStatus({userId, status, expectedVersion, reason}) → {accountStatus, sessionVersion}`；`identityRevokeInstructor({userId, expectedVersion, reason}) → {roles, accountVersion}`；`identityCancelInstructorInvitation`：输入 `{inviteId, expectedVersion}`，输出 `{status, version}` 仅管理员可撤销待接受邀请。准确字段及路由以账号设计中的 Go DTO 为生成来源。
- Consumes: T-01 会话事实；各域消费解析结果后继续进行自己资源的权限检查，不能将 `roles` 直接等价为任意 courseId 访问权。

- [ ] 在 `access_test.go` 写 `TestServiceIdentityRejectsForgedActor` 与 `TestRevokedSessionAndRole`；断言浏览器伪造 userId／roles Header 的调用被拒，普通用户邀请讲师被拒，退出／停用后的解析结果不可授权；撤销讲师立即禁止供课，但不影响其合法已购学习权益；邀请撤销后旧 token 不可接受，接受和撤销并发只能有一个终态。
- [ ] 执行 `make check SERVICE=identity`，确认失败落在上述未实现的权限行为。
- [ ] 在 `authorization.go` 落实内部身份解析、邀请单次接受／撤销和账号停用事务；停用／撤销角色使旧授权失效。仅服务凭据不能代替终端用户身份，也不能接受客户端指定的未核验 actor。
- [ ] 在 `account_management.tsx` 实现 `AccountManagement`，只通过生成接口展示邀请与停用动作，提交失败保留输入并说明状态；禁止前端直写角色或数据库。
- [ ] 在 `service_identity.spec.ts` 验证可信服务调用、无凭据和错误凭据；在 `account_roles.spec.ts` 验证普通用户／讲师／管理员三种入口和停用后的已有页面，服务端拒绝与前端状态一致。
- [ ] 执行下列检查并向课程、交易、社区、assistant 的消费任务交付真实契约产物；不只交付手写类型或 Mock Header。
