# 交易退款与权益 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可追溯的人民币单课购买和人工退款闭环，支付与退款成功只影响对应购买权益。

**Architecture:** `commerce` 独占价格、订单、支付尝试、退款和权益授予。在本服务事务内处理渠道事实与权益；下单只读取 learning 的可售快照，播放从不触发下单。渠道未知结果通过原单查询恢复。

**Tech Stack:** Go／Gin／PostgreSQL／pgx、Next.js／TypeScript／shadcn Radix、Swaggo／Umi OpenAPI；支付渠道使用实际选定商户的官方能力。

**Spec:** [本域需求](../requirement/004-交易退款与权益需求记录.md) R-04、R-14 → [领域设计](../design/004-交易退款与权益设计.md) → [领域 PRD](../prd/004-交易退款与权益产品需求.md) FR-04、AC-04、AC-15；[跨领域 PRD](../prd/001-学习社区与通用Agent产品需求.md#跨领域规则与验收) FR-11／FR-12、AC-11／AC-12；[总计划](./002-学习社区与通用Agent实施计划.md)。

## Global Constraints

- 中国大陆／人民币，单课一次性购买、平台收款；免费课程和试看保留；没有钱包、订阅、套餐或自动分账。
- [PRD 退款规则](../prd/004-交易退款与权益产品需求.md#退款规则)为唯一政策来源：权益首次实际可用起 7×24 小时内全额原路退，截止时刻受理，不扣观看或 AI 费用；2 个工作日审核、批准后 1 个工作日提交渠道。
- 支付、退款、权益分别建模；金额使用精确最小货币单位。通知／浏览器跳回／请求已受理均不能代替渠道成功事实。
- 处理中、失败、未知不提前撤权；成功仅撤对应 purchaseGrant。普通停售保留已购，必须停止交付与退款终态分别记录。
- [工程规范](../standards/001-项目文档与设计规范.md#工程规范与目录设计)及总计划 P0 统一契约、生成链路和共享配置适用；全部业务文件为计划创建。

## Review Focus

1. 金额、币种、商户或签名不匹配的通知：T-01 `TestPaymentRejectsInvalidFacts`。
2. 并发下单、重复／乱序回调与未知支付：T-01 `TestPaymentIdempotencyAndUnknown`。
3. 延迟交付、退款截止时刻与超窗质量问题：T-02 `TestRefundWindowAndExceptions`。
4. 退款未知／异常状态不等于可重发：T-02 `TestRefundUnknownDoesNotResubmit`。
5. 多扣款退款、旧退款迟到和已回购权益：T-02 `TestRefundRevokesOnlyPurchaseGrant`。

**Interfaces:**

- Consumes: `identityResolveSession`；`learningGetSaleSnapshot(courseId) → {courseId, publishedVersion, title, saleState, deliverable}`，不会反向读取本订单权益。
- Produces: `commerceCreateOrder({courseId, idempotencyKey}) → {orderId, amountMinor, currency, state, policyVersion}`；`commerceCreatePaymentAttempt({orderId, channel, idempotencyKey}) → {attemptId, paymentAction, state}`；`commerceGetOrder(orderId) → {orderId, state, paymentState, entitlementState}`。

## Task T-02：人工退款、原单恢复与权益撤销

**依据与状态：** FR-04／FR-12、AC-12／AC-15；依赖 T-01 和学习 T-01／T-02 的交付证据（不依赖播放器首次使用），未开始。

**Files:**

| 操作 | 精确路径与职责 |
| --- | --- |
| Create | `backend/services/commerce/internal/refunds/refund.go`、`backend/services/commerce/internal/refunds/handler.go`、`backend/services/commerce/internal/refunds/request.go`、`backend/services/commerce/internal/refunds/response.go`、`backend/services/commerce/internal/refunds/reconciliation.go`。 |
| Create | `frontend/src/app/manage/refunds/page.tsx`、`frontend/src/features/commerce/refund_form.tsx`、`frontend/src/features/commerce/refund_review.tsx`。 |
| Modify after T-01 | `backend/services/commerce/schema.sql`、`backend/services/commerce/internal/server/server.go`、`frontend/src/features/commerce/order_detail.tsx`。 |
| Test | `backend/services/commerce/tests/integration/refund_test.go`、`frontend/tests/refund_state.test.ts`、`tests/e2e/refund.spec.ts`、`tests/contracts/refund_access.spec.ts`。 |

**Interfaces:**

- Produces: `commerceCreateRefund({orderId, reason, idempotencyKey}) → {applicationId, applicationState, channelState}`；`commerceReviewRefund({applicationId, decision, reason, expectedVersion}) → {applicationState, channelState, version}`；`commerceGetRefund(applicationId) → {applicationState, channelState, amountMinor, deadline, progress}`。
- Consumes: T-01 购买快照、支付事实与 grantId；`learningGetDeliveryEvidence({courseId, notBefore:grantActivatedAt}) → {firstDeliverableAt?, evidenceVersion, contentVersion}`。服务端持久化 `firstAvailableAt`，按 grantActivatedAt 与交付有效区间求首次实际可用，不能用用户点击播放时间或渠道 paidAt 起算；通知迟到／恢复查询不重置，缺证据保持未知。
- Produces: `commerceCancelRefund({applicationId, expectedVersion}) → {applicationState}`；`commerceRetryRefund({applicationId, failedAttemptId, expectedVersion}) → {attemptId, channelState}`，权限和状态条件以交易设计为准。
- 原单查询／渠道成功驱动本地事务；只有确认失败／关闭才可人工新建关联渠道尝试，ABNORMAL／unknown 不能当终态失败；撤销针对原 grantId，保留其余有效授予。

- [ ] 写 `TestRefundWindowAndExceptions`，断言延迟交付不减少 `7×24h` 窗口、截止瞬间可申请、窗口内已观看／使用 AI 不扣费；超窗质量／未交付／重复扣款仍有人工入口；交付通知迟到按有效时间起算，依赖故障不能冒充未交付。
- [ ] 写 `TestRefundUnknownDoesNotResubmit` 与 `TestRefundRevokesOnlyPurchaseGrant`：未知状态 `newChannelAttemptCount == 0`，受理未成功保持权益；多扣款退多余一笔仍 allowed；旧退款成功回调不得撤回新购买 grant。
- [ ] 执行 `make check SERVICE=commerce` 确认失败后，在 `refund.go`、`reconciliation.go` 实现申请／批准／渠道状态分离、待审撤回竞争控制、原单查询与成功撤权同事务，待审取消和已确认失败后的人工重试沿上述独立操作；累计退款不得超过实付。
- [ ] 实现审核队列的到期提醒，覆盖 2 工作日待审、批准后 1 工作日未提交、异常 1 工作日人工跟进；工作日历来源在执行前确定，不能以 48／24 自然小时冒充工作日目标。
- [ ] 在 `refund_form.tsx` 实现 `RefundForm`、在 `refund_review.tsx` 实现 `RefundReview`；展示截止时刻、已消费不扣费、原路金额、实际渠道进度与人工入口；批准后不承诺可取消或固定到账日。
- [ ] 在 `refund.spec.ts` 与 `tests/contracts/refund_access.spec.ts` 验证审核／撤回竞争、永久停供通知全额退款和退款后播放／讨论／知识访问改变；通知投递失败不改变退款事实。
- [ ] 执行本页命令，将沙箱／Mock 与真实支付退款验收分开记录；真实商户小额付款与退款必须在后续获授权环境执行，当前不调用渠道。
