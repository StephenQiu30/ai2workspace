# 社区互动与内容治理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付可管理自己内容的学习讨论，以及不会泄漏受限内容的互动、通知和举报闭环。

**Architecture:** `community` 持有帖子、评论、互动、举报及站内通知；课程讨论通过 learning 验证当前访问权。单个服务内完成状态与审计事务，跨域通知采用持久投递和接收去重，不增加消息微服务。

**Tech Stack:** 既有 Go／Gin／PostgreSQL、Next.js／TypeScript／shadcn Radix、Swaggo／Umi OpenAPI。

**Spec:** [本域需求](../requirement/005-社区互动与内容治理需求记录.md) R-05、R-06、R-07 → [领域设计](../design/005-社区互动与内容治理设计.md) → [领域 PRD](../prd/005-社区互动与内容治理产品需求.md) FR-06、FR-07、AC-06、AC-07；[跨领域 PRD](../prd/001-学习社区与通用Agent产品需求.md#跨领域规则与验收) FR-11／FR-12、AC-11／AC-12；[总计划](./002-学习社区与通用Agent实施计划.md)。

## Global Constraints

- 邮箱验证后互动；课程讨论参与须有当前课程访问权。首版单层回复、赞踩互斥可取消、收藏、站内通知、举报处置。
- [需求 009](../requirement/009-学屿品牌与界面需求记录.md) UI-S-05–07 已确认游客独立公开摘要／登录后正文评论、Tiptap 正文与精简评论、帖子和回复互斥赞踩／仅帖子收藏、时间排序分页。关注、私信、群聊、推荐算法、星级评价与任意附件上传不自动纳入；正文长度、图片限制、评论精简集合、分页大小及保留期限仍按局部门禁落实。
- 作者身份由可信会话决定，作者删除与管理隐藏分别留痕；不可用目标不从详情、搜索或通知正文重新泄漏。
- [工程规范](../standards/001-项目文档与设计规范.md#工程规范与目录设计)适用，任务按纵向行为交付，所有业务路径均为计划创建；共享配置由总计划集成负责人修改。

## Review Focus

1. 双击、重复提交及并发切换赞踩：T-01 `TestReactionIsSingleState`。
2. 他人编辑、跨帖回复和深层回复：T-01 `TestPostOwnershipAndReplyDepth`。
3. 退款或课程撤回后的课程讨论读写：T-01 `course_discussion_access`。
4. 内容隐藏后旧详情／通知仍显示正文：T-02 `TestHiddenContentDoesNotLeak`。
5. 通知重复投递、服务故障与他人收件箱：T-02 `TestNotificationDeliveryAndIsolation`。

**Interfaces:**

- Consumes: `identityResolveSession`；`learningCheckCourseAccess({userId, courseId, purpose:"discussion"}) → {allowed, reason, accessVersion, contentVersion}`。
- Produces: `createPost({scope, courseId?, title, publicSummary, body, requestId}) → {postId, version, state}`；`updatePost({postId, expectedVersion, title, publicSummary, body}) → {version, state}`；`deletePost({postId, expectedVersion}) → {version, state}`；公开摘要独立维护，`listPosts / getPost` 按身份与课程权限返回视图，游客响应不含正文／评论及富文本原始数据。

- [x] 在 `backend/` 执行 `make check SERVICE=community`，确认用例因行为未实现失败；测试数据库／身份夹具先准备，不能把环境错误当测试预期。

- [x] 在 `community_access.spec.ts` 和 `community.spec.ts` 写 `course_discussion_access`：未购、退款后和课程撤回的新读写拒绝，普通停售已购仍可讨论；游客仅收到标题、作者昵称、分类、时间和独立摘要，登录后回原位置再读正文／评论；公开搜索及爬虫不能取得额外全文，时间分页按已确认规则验证。运行本页检查命令。

**Interfaces:**

- Produces: `reportContent({targetType, targetId, reason, requestId}) → {reportId, state}`；`moderateContent({reportId, expectedVersion, action, reason}) → {state, version}`；`listNotifications(cursor) → {items, nextCursor}`；`markNotificationRead({id, read}) → {read}`。
- Produces: `appendNotification({eventId, recipientId, type, target}, serviceCredential) → {notificationId, accepted}`，内部接口按 `(eventId, recipientId)` 去重，类型和最小摘要白名单。
- Consumes: 交易与内容生产者的持久待投递事件；投递成功后生产者标记已投递，community 故障不撤销付款或退款。

- [x] 写 `TestHiddenContentDoesNotLeak`，断言隐藏后列表、直接 ID 详情、旧通知目标均不返回正文；重放旧事件不能恢复作者删除或管理员隐藏的内容。
- [x] 写 `TestNotificationDeliveryAndIsolation`，断言同事件重复发送 `notificationCount == 1`，他人读取／改已读拒绝；模拟通知服务故障后 `paymentState == paid`，恢复投递只生成一个事项。
- [x] 执行 `make check SERVICE=community` 确认失败后，在 `report.go` 和 `notification.go` 实现举报去重、管理员处置审计同事务、收件人隔离与事件接收去重；权限校验失败不退化为空列表后继续写入。
- [x] 在 `notification_list.tsx` 实现 `NotificationList`、在 `report_review.tsx` 实现 `ReportReview`；通知只保留最小状态摘要，点击重新鉴权，不能复制付费文稿或完整回复作为永久预览。
- [x] 在 `moderation.spec.ts`／`notification_delivery.spec.ts` 验证举报提交、审核拒绝／隐藏、本人收件箱及投递恢复；执行以下检查并记录消费端的真实事件契约。
