# 模型接入与 AI 费用治理 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 接入四类指定提供商，并在任何付费知识、搜索或问答调用前控制可用次数、并发和人民币成本，保留异常费用核对能力。

**Architecture:** `assistant` 的 provider 适配上游差异，usage 管理同一服务内的准入预占与实际费用账。模型选择固定于 Agent 发布版本；未知用量仍占预算。没有钱包、积分、充值或静默供应商故障切换。

**Tech Stack:** Go／Gin／PostgreSQL／pgx、Next.js／TypeScript／shadcn Radix、Swaggo／Umi OpenAPI；官方模型与搜索接口，价格／汇率版本化配置。

**Spec:** [本域需求](../requirement/008-模型接入与AI费用治理需求记录.md) R-13、R-17 → [领域设计](../design/008-模型接入与AI费用治理设计.md) → [领域 PRD](../prd/008-模型接入与AI费用治理产品需求.md) FR-13、FR-14、AC-13、AC-17；[跨领域 PRD](../prd/001-学习社区与通用Agent产品需求.md#跨领域规则与验收) FR-11／FR-12、AC-11／AC-12；[总计划](./002-学习社区与通用Agent实施计划.md)。

## Global Constraints

- 至少 DeepSeek、OpenRouter、火山、OpenAI 各验证一个允许模型；具体端点、模型与价目未选定，兼容协议不等于已接入。缺价、价目过期或不能可靠限制计费输出则禁止调用。
- [PRD AI 费用控制](../prd/008-模型接入与AI费用治理产品需求.md#ai-费用控制)：账号每日 20 次成功问答；每分钟 3 个新请求、账号同时 1 个、平台同时 10 个；跨课程／Agent／模型共享，买课不叠加。
- 总输入最多 8,000 tokens；可计费输出最多 2,000 tokens，包含推理；单次最终预占（已含 20% 缓冲）≤¥0.50，账号 ¥2／日、平台 ¥100／日和 ¥2,000／月，任一不足拒绝。
- 后台入库 ¥20／日是平台日预算内子上限；Asia/Shanghai 自然日／月，80% 提醒，100% 或余额不足以预占时拒绝新付费调用，已有预占可收尾。
- 未知费用 24 小时转人工核对，跨周期仍扣减可用预算，核对后归原调用周期并消除重复占用；实际超预占完整入账，不能截断。
- [工程规范](../standards/001-项目文档与设计规范.md#工程规范与目录设计)适用。本页创建唯一 assistant module；知识、Agent 后续扩展该服务，不能各建新服务。

## Review Focus

1. 四家用量字段、推理计费及缺失 usage 不一致：T-01 `TestProviderUsageNormalization`。
2. 最后额度被并发争抢或换 Agent 绕过：T-02 `TestBudgetAtomicAdmission`。
3. 搜索第二次尝试、后台索引与总预算分离失控：T-02 `TestBudgetIncludesAllPaidSteps`。
4. 超时／取消、跨日月和未知费用被清零：T-03 `TestUnknownCostAcrossPeriods`。
5. 缺价、过期汇率、账单超预占或手动提高预算掩盖超支：T-01 `TestModelEligibility`、T-03 `TestSettlementRecordsOverrun`。

**Interfaces:**

- Produces: `provider.Generate(ctx, GenerationInput) (GenerationResult, error)`；生成输入为 `{providerId, modelId, messages, maxBillableOutputTokens, deadline, requestId, attemptId}`，结果为 `{text, finishReason, usage:{state, inputTokens?, outputTokens?, reasoningTokens?}, providerRequestId, actualModel, route?, state}`；usage.state 区分 known／unknown，保留输入、输出及可取得的推理计费字段；actualModel／route 保留上游实际模型与可取得的路由，不用请求模型冒充已核验的聚合路由，requestId 关联业务运行，attemptId 区分每次外部尝试；精确类型按模型费用设计。
- Produces: `listModels() → {items}`，每项包含 `providerId / modelId / enabled / capabilities / priceVersion`，不含密钥。后台配置引用服务端 secretRef，前端不管理明文 Key。
- Consumes: 四家实际官方协议、允许模型能力和价格版本；embedding 与生成能力独立登记，不假设同一模型能二者兼任。

- [x] 写 `TestProviderUsageNormalization`，用四家独立响应夹具断言完整／流式／断流／缺失 usage 的结果与上游事实一致；缺失用量必须 `usage.state == "unknown"`，不能填 0。
- [x] 写 `TestModelEligibility`，断言未知价格、过期价目／汇率、无法约束 2,000 计费输出或总输入超过 8,000 的模型／请求拒绝；模型参数或供应商错误不触发另一个提供商。
- [x] 在 `backend/` 执行 `make check SERVICE=assistant`，确认缺失行为后，在 `provider.go` 定义最小消费契约，在四家文件适配输入／流式／错误／用量；同次交付创建 assistant 服务、schema、健康及官方生成接入。
- [x] 在 `model_catalog.tsx` 实现 `ModelCatalog`，仅展示可用状态、模型限制和价格配置是否完整，具体模型选择仍在 Agent 配置页；界面不得将协议测试通过标为真实接入通过。
- [x] 运行本页服务与前端检查；登记四家的待真实验证项：配置／权限、正常回答、流式或完整返回、错误展示、用量及 RAG＋实际搜索，不执行付费调用。

## Task T-02：新请求的次数、并发与成本原子预占

**依据与状态：** FR-14、AC-17；依赖 T-01，未开始。

**Files:**

| 操作 | 精确路径与职责 |

| Modify after T-01 | `backend/services/assistant/schema.sql`、`backend/services/assistant/internal/server/server.go`、`frontend/src/app/manage/ai-usage/page.tsx`。 |
| Test | `backend/services/assistant/tests/budget_test.go`、`frontend/tests/usage_summary.test.ts`、`tests/contracts/ai_admission.spec.ts`。 |

**Interfaces:**

- Produces: `usage.Reserve(ctx, ReservationInput) (Reservation, error)`；输入标明 requestId、可信 userId 或后台任务身份、kind、provider/model、价目版本、最大调用清单及估算；输出 reservationId、保留金额／成功槽／并发槽、预算版本与状态。价格取服务端可信配置，不接收客户端自报成本。
- Consumes: T-01 的允许模型与价目；一次完整问答估算覆盖查询 embedding、最多 2 次搜索、一次最大生成并加 20% 缓冲。后台任务走同一全局准入但不占学员成功次数。
- Produces: `getUsageSummary() → {successfulAnswers, activeRuns, knownCost, reservedCost, limits, period}`，学员只看本人；管理员查看平台汇总；金额用精确单位保存。

- [x] 写 `TestBudgetAtomicAdmission`，断言并发竞争最后额度仅一个成功；第 21 次成功占位、第 4 个每分钟新请求、第 2 个账号同时运行、第 11 个平台同时运行均拒绝，跨 Agent／模型仍共享。
- [x] 写 `TestBudgetIncludesAllPaidSteps`，断言最终估算 `base × 1.20` 含在 ¥0.50 内，首次尚未取得证据时按 8,000 输入 tokens 上界预占，搜索第二尝试已预占；账号 ¥2／日、平台 ¥100／日／¥2,000／月、后台 ¥20／日任一不足均 `providerCalls == 0`，后台没有独立于 ¥100 的额外额度。
- [x] 执行 `make check SERVICE=assistant` 确认失败后，在 `budget.go` 实现同库原子准入、幂等 requestId、速率与并发槽，超额立即返回具体原因而非无限排队；未付费也不绕过滥用速率限制。
- [x] 在 `usage_summary.tsx` 实现 `UsageSummary`，区分成功次数与费用不足，说明 20 次不是保证次数；已消耗、预占和未知单列，不把未结算当余额。
- [x] 在 `ai_admission.spec.ts` 用多个 Agent 和并发账号验证同一预算权威；通过生成调用读取用量，不能由前端扣数；运行本页检查并交付 knowledge／agent 消费契约。

## Task T-03：结算、未决费用与运营控制

**依据与状态：** FR-14／FR-12、AC-17；依赖 T-02，未开始。

**Files:**

**Interfaces:**

- Produces: `usage.Reconcile(ctx, SettlementInput) (Settlement, error)`，输入 reservationId、attemptId、providerRequestId、实际用量／费用、状态与证据版本；输出 knownCost、unresolvedReservedCost、releasedAmount、成功次数结算与状态，重复结算幂等。
- Produces: `updateBudget({expectedVersion, limits, effectiveAt, reason}) → {version, limits}`，管理员专用并记录变更；暂停新 AI 任务不能取消已发生账务。公开用户接口不具备更改本人额度或价格的权力。
- Produces: `listReconciliations({period, state}) → {items, nextCursor}`，仅授权管理员读取证据摘要，不暴露原始密钥或会话全文。
- Consumes: 每个实际外部尝试的结果；本地失败／取消不自动证明上游未计费，缺失 usage 继续预占并进入核对队列。

- [x] 写 `TestUnknownCostAcrossPeriods`，断言失败释放成功次数和本地运行槽，但断流／未知费用不释放；跨上海日／月边界仍占可用预算，24 小时未决进入人工队列；核对后费用归原周期并只消除一次风险预占。
- [x] 写 `TestSettlementRecordsOverrun`，断言实际费用超过预占仍完整入账并阻止继续超额调用，不能把实际数值截成 ¥0.50；确认未产生费用才释放，重复账单或结果不重复扣费。
- [x] 执行 `make check SERVICE=assistant` 确认失败后，在 `settlement.go` 实现已知结算／未知保留／成功次数幂等结算，在 `reconciliation.go` 实现 24 小时人工事项、跨期风险占用和价目版本追踪；取消通知不直接归零成本。
- [x] 在 `budget_management.tsx` 实现 `BudgetManagement`，展示已知／预占／未决、80% 提醒和暂停新任务；预算修改有明确新版本与原因，不能清空既有消费或掩盖超支。
- [x] 在 `ai_budget.spec.ts` 验证耗尽只阻断新 AI，课程、交易、社区仍可使用；已有合法预占可收尾；四家适配的用量都进入同一结算而不是各自独立用户额度。
- [x] 运行下列检查；后续真实账单核对逐家标明可信字段与无法取得的部分，未决不伪装成已结清，真实验收由总计划单独记录。
