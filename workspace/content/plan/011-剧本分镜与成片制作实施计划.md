**Goal**　让制作团队在平台从分场剧本和逐镜素材获得一集经审片的可播 MP4。

**Architecture**　`creation` 持有剧本、分镜、审片清单和产物版本。协同编辑态与 PostgreSQL 固化快照分开。制作模块执行渲染，预览和 MP4 共用 Remotion 合成参数。需要持久恢复时由制作模块登记 Temporal 工作流。

**Tech Stack**　Go / PostgreSQL、Tiptap / Yjs / WebSocket、Temporal、Remotion、COS、Redis / SSE。

## Global Constraints

- 试点建议为一集 30–60 秒动态漫，帧率、分辨率、音量、字幕与素材格式在样片评审后确定。上游修改只标记相关镜头，审片快照一经确认便按版本只读。
- 制作验收先走手工链路，模型、校验和生成素材可独立联调。协同恢复验证使用多人和跨工作区样本。
- Remotion 真实样片的编码、队列时长和 CPU／内存实测另存。渲染运行与发布状态只通过产物契约交接。
- 文中新增的业务代码、测试与页面路径是规划目标。现有 learning 服务的媒体处理流程可作参考。剧本、分镜、审片和 MP4 合成由目标制作域交付。后端 REST 契约从 Go DTO 和 Swaggo 生成，再更新 Umi 客户端。
- 测试命令在目标工程建立后使用。真实付费、外部生产实例、提交和发布分别按实际授权执行。

## Review Focus

- TestScriptRecovery：撤权、断网及旧稿提交后重新同步仍能恢复已保存内容。
- TestShotRevision：单场对白改动不会弄脏不相关镜头。
- TestCandidateAdoption：输入过期或产物失权不会更新镜头。
- TestRenderNonBlocking：进度重连不阻塞草稿编辑。
- TestRenderRecovery / TestLateRender：重复通知、失败续跑和旧产物到达按审片版本归档。
